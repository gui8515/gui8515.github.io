Padrão de documentação

Este manual documenta o JSON++ Object para Clickteam Fusion 2.5. Usa quatro áreas complementares: Primeiros passos, Guias práticos, Conceitos e Referência da API. As páginas da API são a referência normativa para o usuário; os tutoriais apontam para elas em vez de repetir contratos.

Evidências e estado​

Use evidências nesta ordem: comportamento reproduzível em runtime; implementação do runtime; descritores de ACEs/propriedades e metadados do SDK; documentação existente; inferência. Identifique inferências e nunca as apresente como comportamento verificado. Uma implementação no código-fonte não é validação em runtime.

Use status para completude editorial (inventory, draft, reviewed, documented) e verification para evidência funcional (verified, implemented-not-runtime-tested, not-tested, unsupported, unknown). Inclua caminhos source e caminhos evidence quando conhecidos. Não invente versões nem datas de teste. A compatibilidade é registrada separadamente para Windows, Android, iOS, macOS e HTML5.

Metadados das páginas da API​

id: A13
title: Insert String
type: action
category: insertion
status: draft
verification: implemented-not-runtime-tested
source: Actions.cpp

Os IDs e nomes exibidos vêm do descritor atual. Mantenha IDs estáveis mesmo quando uma entrada estiver oculta nos menus ou houver lacunas. Os parâmetros seguem a ordem e os tipos do descritor. Diferencie o nome do menu dos símbolos de implementação quando divergirem.

Seções obrigatórias da API​

Cada página de ação, condição, expressão e propriedade de valor inclui: Descrição; Quando usar; Sintaxe; Anatomia; Parâmetros; Comportamento; Exemplos; Resultado esperado; Erros e casos especiais; Limitações; Compatibilidade de plataformas; Recursos relacionados; Metadados de verificação. Use Not applicable (não aplicável) somente com uma justificativa. Fatos desconhecidos são identificados explicitamente, nunca adivinhados.

Os exemplos usam a notação do editor de eventos do Clickteam Fusion em blocos text e devem usar literais JSON válidos. Declare as suposições antes do evento e mostre o JSON ou valor resultante depois. Use aspas escapadas conforme exigido pelo Fusion. Evite afirmar que um evento é disparado sem confirmação da implementação.

Níveis de exemplos​

  • Básico: o menor fluxo significativo; obrigatório sempre que o uso puder ser demonstrado.
  • Prático: um cenário realista de dados de jogador, inventário, configuração ou coleção quando o contexto ensinar mais que o exemplo básico.
  • Avançado: uma combinação de ACEs, navegação ou loops somente quando agregar valor didático.

Não gere três exemplos mecanicamente. Para uma ação de manipulação, prefira JSON inicial → Ação → JSON resultante. Para propriedades exclusivas do editor, mostre um cenário de configuração e declare explicitamente a ausência de efeito em runtime em vez de inventá-lo.

Vocabulário de compatibilidade de plataformas​

EstadoEvidência necessária
SuportadoImplementação e comportamento esperado confirmados por um teste reproduzível em runtime.
ParcialEvidência executável estabelece o comportamento com as restrições declaradas.
Não suportadoA evidência confirma a falta de suporte à operação documentada.
Não testadoA implementação ou disponibilidade é conhecida, mas o comportamento no runtime de destino não está suficientemente validado.
DesconhecidoA evidência é insuficiente para determinar a disponibilidade ou o suporte.

Use um estado por célula de plataforma e explique as evidências separadamente. Um harness Node verifica código JavaScript, mas não valida por si só uma exportação do Fusion, integração com navegador ou outro destino. Preserve a procedência conhecida de versão/teste; não invente uma versão de lançamento.

Regras por categoria​

As condições identificam explicitamente gatilho versus avaliação de estado, pré-requisitos e comportamento de repetição/consumo. As expressões registram o tipo de retorno e a semântica de erro/fallback; a referência implícita ao objeto Fusion faz parte da sintaxe, não é um parâmetro extra do descritor. As propriedades registram localização no editor, controle, padrão/opções/faixa declarados, leituras de inicialização, uso em runtime, ações relacionadas e evidências executadas como três afirmações distintas. Os metadados Folder/Group/FolderEnd são documentados como estrutura do editor, não funcionalidade de runtime. Se legenda, dicas, vinculação e implementação divergirem, mostre a discrepância e não escolha silenciosamente uma delas como contrato portátil.

Auditoria sistemática​

Execute python docs/tools/audit_documentation.py a partir do diretório deste manual. Ele verifica cobertura do descritor, identificadores duplicados, contagens/tipos de parâmetros, conteúdo obrigatório, exemplos JSON, links relativos, âncoras e acessibilidade pelos índices de categorias. Grava as evidências atuais em docs/reference/coverage.json. Páginas ausentes são informadas mesmo quando as verificações estruturais passam. --require-complete falha se qualquer entrada visível da API ou a ação oculta implementada A72 permanecer sem documentação.

Regras editoriais e de navegação​

Escreva em português brasileiro claro, preserve nomes oficiais do Fusion e termos técnicos, use links relativos e explique cada conceito uma única vez em Conceitos. Os índices da API listam cada ID exatamente uma vez. Não duplique identificadores para fazer um menu parecer completo. Marque explicitamente entradas ocultas, legadas, vazias ou não suportadas. Mantenha os antigos pontos de entrada Markdown de nível superior como índices de navegação.

Lista de verificação de conclusão​

  • ID do descritor, nome exibido, contagem/ordem/tipos de parâmetros e tipo de retorno correspondem.
  • A implementação e os chamadores relevantes foram inspecionados.
  • Padrões/faixas vêm de declarações explícitas, não de exemplos.
  • O resultado esperado decorre da implementação ou de um teste reproduzível.
  • O estado em runtime tem base em evidências e é específico por plataforma.
  • O exemplo, os links internos e as páginas relacionadas resolvem corretamente.
  • O estado editorial e o estado de verificação não são confundidos.
