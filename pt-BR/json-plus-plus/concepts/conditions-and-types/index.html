Condições, valores ausentes e tipos numéricos

As condições de estado inspecionam o documento atual quando o Fusion avalia o evento. Elas não são eventos consumidos: um estado verdadeiro pode permitir o mesmo evento novamente em avaliações posteriores. Condições de gatilho como On Error e On JSON Loaded pertencem a eventos gerados; a implementação HTML5 também tem flags alternativas para avaliação direta de callbacks. Testes dessas flags alternativas não estabelecem todo o comportamento de despacho de eventos do Fusion.

Ausente, null e vazio são estados diferentes​

Um membro ausente não existe. Um membro que contém JSON null está presente com valor nulo explícito. Um array ou objeto vazio é um contêiner presente sem elementos. Uma string vazia continua sendo uma string primitiva.

As implementações atualmente inspecionadas diferem:

Os predicados nativos de tipo para arrays vazios retornam true porque todos os elementos inspecionados satisfazem a regra quando não há elementos. HTML5 rejeita explicitamente o array vazio. Se um fluxo precisa ler o item zero, verificar apenas a uniformidade do tipo dos elementos é insuficiente nas plataformas nativas.

As funções de consulta HTML5 normalmente começam com uma verificação de valor lógico na raiz do documento. Raízes como 0, false e null podem, portanto, falhar na consulta antes da resolução do ponteiro. Uma raiz do tipo objeto que contém esses valores evita essa verificação específica da raiz; isso não elimina as demais diferenças da tabela.

Representação armazenada de inteiro e ponto flutuante​

Is Integer nativo testa a categoria de inteiro armazenada pela biblioteca JSON. Is Float e Is Double nativos testam a categoria de ponto flutuante; não distinguem duas larguras de precisão diferentes. Um token JSON 1.0 analisado é de ponto flutuante na biblioteca nativa, mesmo que seu valor matemático seja inteiro.

HTML5 armazena números JSON como Numbers de JavaScript. Is Integer testa se o valor é matematicamente inteiro, enquanto Is Float e Is Double testam se há parte fracionária. Consequentemente, 1.0 pode satisfazer Is Integer em HTML5 e falhar em seus callbacks Is Float/Double. Esses predicados não validam inteiros seguros, precisão nem faixas de valores da aplicação.

A igualdade depende da operação​

  • Compare to Structure nativo atualmente aceita um destino numérico e texto numérico finito analisado por completo. Seu nome no menu e a indicação no descritor não descrevem uma implementação nativa de igualdade profunda.
  • Compare to Structure em HTML5 analisa a entrada de comparação e compara strings de serialização JSON. A representação do objeto e a ordem das chaves podem afetar essa verificação.
  • Compare to Value nativo compara um número exatamente com um argumento Float do Fusion; não usa epsilon.
  • Compare to String nativo exige uma string e compara o texto exatamente. HTML5 converte ambos os lados com String, podendo corresponder a valores que não são strings.

Evidências e referências relacionadas​

Essas distinções vêm das implementações nativa e HTML5 atuais. Os resultados de verificação dos exemplos reproduzem casos selecionados de callbacks HTML5 no Node. Os métodos nativos de caminhos e consultas foram compilados no harness isolado existente, com verificações específicas listadas na auditoria; isso não é uma validação completa de exportação do Fusion.
