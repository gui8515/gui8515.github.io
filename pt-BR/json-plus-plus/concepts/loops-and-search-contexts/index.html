Buffers de loop e resultados de pesquisa

As expressões de loop leem um contexto de callback nomeado, não caminhos arbitrários do documento. As expressões de resultados de pesquisa leem uma lista de resultados armazenada, não uma pesquisa recém-executada. Trate seus ciclos de vida separadamente do documento em si.

Fases e ciclo de vida do loop​

Start Loop registra uma iteração sobre um objeto ou array existente. A ramificação nativa normal distribui o trabalho entre quadros: Handle chama o agendador, que processa itens dentro de um orçamento de tempo. handleRunObject em HTML5 chama stepLoops, que avança as coleções ativas. Não presuma que todos os itens ou a conclusão aconteçam antes do retorno de Start Loop.

On Start Loop pode ser executado antes de o buffer do primeiro item nativo ser preenchido. On Loop é o local adequado para ler os valores atuais. On End Loop é executado em torno da conclusão, após a qual o estado é removido. Um nome de loop explícito fora de um callback de item pode expor estado desatualizado ou da próxima etapa; expressões com nome vazio usam o nome atual da pilha de execução nativa ou currentLoopName em HTML5. Parâmetros de gatilho com nome vazio não têm a mesma semântica de alias.

O loop nativo padrão captura iteradores do contêiner JSON ativo. Alterações estruturais podem invalidá-los; o comportamento seguro de alteração e reinício não foi estabelecido para todos os cenários de callback. HTML5 também mantém uma referência ao destino e uma lista de chaves. Colete as alterações separadamente quando o fluxo precisar de iteração previsível sobre entrada estável.

O que os getters de loop realmente contêm​

  • Get Loop String retorna o conteúdo bruto de uma string para valores desse tipo e texto serializado para os demais.
  • Get Loop Number e Boolean usam zero quando o item atual não tem o tipo correspondente.
  • Get Loop Object/Array testam a flag do contêiner pai percorrido. Eles não validam se o item atual tem o tipo sugerido pelo nome.
  • Get Loop Index é o índice do loop ativo. Get Loop Number of Items é o total original do contêiner, não a quantidade restante nem o tamanho de um filho.
  • Caminhos de itens de objetos nativos acrescentam chaves brutas; HTML5 aplica escape aos tokens do ponteiro. Chaves contendo / ou ~ exigem cuidado especial ao reutilizar o caminho de um loop nativo.

Para uma coleção estável como {"items":["Potion","Key"]}, inicie um loop nomeado Inventory em /items e leia GetLoopString em On Loop Inventory. Os callbacks dos itens fornecem Potion e Key. O momento exato entre quadros e o comportamento de entrega de eventos exportados exigem validação no runtime.

Identidade e atualização dos resultados de pesquisa​

As ações de pesquisa preenchem uma lista de caminhos de resultados. Os getters nativos tipados de resultados releem o documento atual nesse caminho. HTML5 também armazena os valores e referências coletados. Substituir ou excluir membros do documento após uma pesquisa pode, portanto, produzir caminhos desatualizados, novos valores nativos ou valores mais antigos coletados em HTML5. Uma contagem de resultados não comprova que todos os caminhos ainda podem ser resolvidos.

O índice na lista de resultados e o índice no array são distintos. Get Result Index nativo tenta analisar o último token do caminho e, caso contrário, retorna a posição do resultado; HTML5 retorna a posição. Get Result Key nativo decodifica o token JSON Pointer, enquanto HTML5 retorna o token final da string armazenada. Os getters numéricos também usam sentinelas de falha diferentes: zero nativo contra menos um em HTML5.

Leia os resultados imediatamente após uma pesquisa bem-sucedida quando possível e verifique as condições pertinentes de tipo e erro. Uma pesquisa que falha pode deixar o estado anterior, dependendo do ponto de falha. Os callbacks nativos On Results Found/Not Results Found existem, mas não foi encontrado um emissor nas ações nativas de pesquisa inspecionadas; os exemplos básicos de getters leem diretamente após a pesquisa em vez de depender dessas notificações.

Metadados de gatilho e comportamento dos callbacks​

O descritor marca C33–C69 como Triggered=true. Algumas são manipuladores reais de eventos gerados; outras são callbacks que leem estado ou stubs nativos constantes. O SDK converte Triggered em flags de evento. Um callback que retorna true não substitui um ponto de chamada que emite o evento. Flags de estado como Read Only ou Auto Save não comprovam que a operação prometida é imposta ou agendada.
