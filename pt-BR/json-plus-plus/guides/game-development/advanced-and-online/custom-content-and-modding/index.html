Conteúdo personalizado e modding

A. Visão geral​

Emberfall aceita conteúdo escrito pelos próprios jogadores. O jogador coloca um arquivo JSON na pasta do mod, declara um item, um inimigo ou um nível, e o jogo o lê, o verifica e usa as partes que entende.

DificuldadeAvançado
ComplexidadeAlta — um documento de conteúdo, uma passagem de validação, uma cópia para o banco de dados do jogo e um relatório
Conhecimentos de FusionEventos de frame, objetos Active, objetos String e Counter, variáveis globais, loops
Conhecimentos de JSON++Carregar um arquivo externo, percorrer um array com loop, ler membros com um caminho calculado, escrever em outro documento

Cenário de jogo​

O jogador escreve um arquivo chamado mods/flame_sword.json com uma espada de sua própria criação. O jogo o lê quando a pasta de mods é aberta, encontra um item com o identificador custom_fire_sword, verifica que o dano é um número que o jogo aceita e adiciona o item ao banco de dados do jogo. A espada passa a ser encontrada, comprada e equipada como qualquer outra. Um segundo arquivo que declara um dano de menos cinquenta é recusado, e o relatório diz por quê.

Objetivos de aprendizado​

Ao final deste guia você será capaz de:

  • ler um documento escrito por um jogador e verificá-lo antes que o jogo confie nele;
  • validar a versão do conteúdo e a versão do jogo que ele exige;
  • copiar para dentro dos próprios documentos do jogo as definições que ele entende;
  • recusar os valores que o jogo não pode usar e explicar a recusa;
  • descrever com honestidade os limites das plataformas, sem prometer um sistema de arquivos que o jogador não tem.

O que você vai construir​

Um arquivo de conteúdo escrito por um jogador, os eventos que o carregam, uma passagem de validação sobre seus itens e seus inimigos, a cópia das definições aceitas para o banco de dados do jogo, um relatório que lista o que foi aceito e o que foi recusado, e o evento que remove de novo o conteúdo personalizado.

B. Pré-requisitos​

Conhecimentos de Fusion necessários

  • Eventos de frame e a condição Start of Frame.
  • O loop do jogo, com as condições que relatam os itens e o fim do loop.
  • O objeto Active e a condição is clicked.
  • O objeto String e a Action Set alterable string.
  • Variáveis globais no objeto Special.

Conceitos de JSON++ necessários

  • Entender loops JSON e Ler valores do loop.
  • Caminhos JSON, porque o caminho do item atual é o que endereça uma definição.
  • Valores ausentes, null e vazios: uma definição que perdeu um membro é recusada.
  • Estado da instância JSON: o conteúdo do jogador e o banco de dados do jogo vivem em dois objetos diferentes.

Limitações de runtime a considerar

  • O jogo alcança o arquivo por uma referência que o alvo suporta. No Windows e nos alvos móveis, ela é um caminho dentro da pasta da aplicação ou do sandbox da aplicação. No runtime de navegador, o jogador escolhe o arquivo com um seletor, ou o arquivo é lido do armazenamento da origem. Nenhum alvo dá a um jogo o sistema de arquivos inteiro do dispositivo.
  • Um arquivo de conteúdo declara números e nomes. Ele nunca executa código, e o jogo nunca trata um membro do arquivo como uma instrução.
  • O runtime de navegador recusa duas operações de arquivo ao mesmo tempo, de modo que uma pasta de mods é lida um arquivo por vez.
  • A extensão não verifica o conteúdo para o jogador. Toda verificação deste guia é um evento do jogo.

Objetos padrão usados aqui

String, Counter, Special, Timer, Active e JSON++ Object.

Tutoriais de pré-requisito relacionados

  • Trabalhar com arquivos por plataforma
  • Banco de dados de inimigos orientado por dados
  • Versionamento e recuperação de salvamentos

C. Cenário de jogo​

Um arquivo de conteúdo tem três seções: items, enemies e levels. Cada seção é um array de objetos, e cada objeto se nomeia com um identificador que o jogo nunca viu.

O jogo não confia no arquivo. Ele lê a versão da estrutura, compara com a versão que a build entende, e compara a versão do jogo que o conteúdo exige com a versão da build. Um arquivo que exige um jogo mais novo é recusado antes que algo seja lido dele.

Depois o jogo percorre os itens. Para cada um, verifica se o identificador, o nome e o tipo estão presentes, se o tipo é um que o jogo conhece e se os números estão dentro da faixa que o jogo aceita. Uma definição que passa é copiada para o banco de dados do jogo. Uma definição que falha é escrita no relatório, com o motivo.

A cópia é feita membro por membro, porque o conteúdo vive em outro documento. O jogo lê o nome do item personalizado e o escreve no banco de dados, depois o dano, depois o valor. A extensão fornece a leitura e a escrita; o jogo decide o que copiar.

D. Resultado final​

O sistema completo se comporta assim:

  • Um arquivo escrito pelo jogador é lido quando a pasta de mods é aberta.
  • As definições que o jogo entende ficam disponíveis no jogo, ao lado das que vêm com ele.
  • Uma definição com um membro ausente, um tipo desconhecido ou um valor fora da faixa aceita é recusada, e o relatório diz por quê.
  • Um arquivo que exige uma versão mais nova do jogo não muda nada.
  • Remover os mods remove o conteúdo personalizado do jogo, e os itens que vêm com ele permanecem.

E. Estrutura de dados JSON​

Um arquivo de conteúdo escrito por um jogador​

{
  "schema_version": 1,
  "content_version": "1.0.0",
  "requires_game_version": "1.2.0",
  "author": "player_one",
  "items": [
    {
      "id": "custom_fire_sword",
      "name": "Flame Sword",
      "type": "weapon",
      "stack": 1,
      "damage": 24,
      "value": 120,
      "icon": "custom_fire_sword.png"
    },
    {
      "id": "custom_ember_potion",
      "name": "Ember Potion",
      "type": "potion",
      "stack": 10,
      "heal": 35,
      "value": 60,
      "icon": "custom_ember_potion.png"
    }
  ],
  "enemies": [
    {
      "id": "custom_bone_golem",
      "name": "Bone Golem",
      "category": "undead",
      "hp": 120,
      "damage": 18,
      "speed": 45,
      "xp_reward": 90,
      "attack_range": 30,
      "loot_table": "bandit"
    }
  ],
  "levels": []
}

O objeto raiz guarda sete membros:

MembroTipoSignificado
schema_versionnumberA versão da estrutura do arquivo. A build aceita as versões para as quais foi escrita.
content_versionstringA versão do conteúdo em si, escolhida pelo autor.
requires_game_versionstringA versão mais antiga do jogo que entende este conteúdo.
authorstringO nome do autor, mostrado na lista de mods.
itemsarray of objectsOs itens personalizados.
enemiesarray of objectsOs inimigos personalizados.
levelsarray of objectsOs níveis personalizados, na estrutura do Carregar níveis a partir de JSON.

Cada item personalizado guarda:

MembroTipoSignificado
idstringO identificador do item. O jogo o usa como a chave do item no banco de dados.
namestringO nome mostrado no jogo.
typestringO tipo do item, com os valores que o catálogo do jogo usa: weapon, armor, potion, food, material e key.
stacknumberO número de unidades que ocupam um mesmo espaço. Uma arma tem uma pilha de 1.
damagenumberO dano de uma arma. O jogo recusa um valor abaixo de 0 ou acima de 999.
healnumberA vida restaurada por uma poção.
valuenumberO preço do item na loja.
iconstringO nome da imagem do item. O jogo procura essa imagem na pasta do mod.

Os membros name, type, stack e value são os membros do catálogo do jogo, de modo que um item copiado com esses quatro membros é lido exatamente como um item que vem com o jogo. Os membros damage e heal carregam o efeito do item, e viajam com o arquivo do mod porque um mod é um único documento.

Cada inimigo personalizado guarda o id, o name, o category, o hp, o damage, o speed, o xp_reward, o attack_range e o loot_table. Os nomes dos membros são os do banco de dados de inimigos do jogo, de modo que um inimigo personalizado é lido com o mesmo caminho que um inimigo que vem com o jogo, e as faixas são as mesmas. O category nomeia uma das famílias de /categories, e o loot_table nomeia uma das tabelas do documento de loot.

Uma seção vazia é válida. O arquivo de um mod que apenas adiciona um item pode deixar enemies e levels vazios.

G. Implementação passo a passo​

Passo 1 — Crie os objetos​

  1. Adicione os objetos listados acima ao frame dos mods.
  2. Crie as variáveis globais Item Id, Item Type e Mod File no objeto Special.

Passo 2 — Carregue o conteúdo de um mod​

Adicione um evento com a condição Mod List is clicked:

  • Action: Special : Set Mod File to ModFile("Mod List").
  • Action: Custom Content : Load JSON from file at Apppath$ + "mods/" + Mod File.

O nome do arquivo vem da linha que foi clicada. O caminho é montado em tempo de execução, de modo que um único evento lê todos os arquivos da pasta.

Passo 3 — Verifique a versão da estrutura​

Adicione um evento com a condição Custom Content: On JSON Loaded:

  • Condição do grupo: Custom Content: Is "/schema_version" equal to 1?.
  • Action: Special : Set Content Valid to 1.

Um arquivo com uma estrutura que a build não conhece não é lido adiante. O resto dos eventos deste guia roda dentro de um grupo que verifica essa flag.

Passo 4 — Verifique a versão do jogo​

Adicione um segundo grupo sob o mesmo evento:

  • Condição do grupo: Custom Content: Is "/requires_game_version" equal to Game Version?.
  • Action: Special : Set Content Valid to 1.

Os dois grupos escrevem a mesma flag, e a flag começa em zero. Um arquivo que passa em uma verificação e falha na outra deixa a flag em zero, e o conteúdo é recusado.

Passo 5 — Percorra os itens personalizados​

Adicione um evento com a condição Custom Content: On JSON Loaded:

  • Condição do grupo: Content Valid = 1.
  • Action: Custom Content : Start loop "Items" at "/items".

E um evento com a condição Custom Content: On Loop "Items":

  • Action: Special : Set Item Id to GetString( "Custom Content", GetLoopPath( "Custom Content", "Items" ) + "/id" ).
  • Action: Special : Set Item Type to GetString( "Custom Content", GetLoopPath( "Custom Content", "Items" ) + "/type" ).

O identificador do item é lido do próprio item, porque a posição de um item no array não é um nome.

Passo 6 — Recuse um item que o jogo não entende​

Adicione um grupo sob o evento de loop:

  • Condição do grupo: Custom Content: Is GetLoopPath( "Custom Content", "Items" ) + "/type" equal to "weapon"?.
  • Action: Report Text : Set alterable string to "Accepted: " + Item Id.

Adicione um segundo grupo para os outros tipos aceitos, e um terceiro que recusa todo o resto. Os tipos aceitos são os do catálogo do jogo: weapon, armor, potion, food, material e key:

  • Condição do grupo: Custom Content: Is GetLoopPath( "Custom Content", "Items" ) + "/type" equal to "armor"?.
  • Action: Report Text : Set alterable string to "Accepted: " + Item Id.

Passo 7 — Verifique se o membro está lá, e verifique os números​

Adicione um grupo sob o evento de loop:

  • Condição do grupo: Custom Content: GetLoopPath( "Custom Content", "Items" ) + "/damage" exists.
  • Action: Report Text : Set alterable string to "Refused: " + Item Id + " has no damage member".

Um membro ausente não é um zero. GetNumber relata o erro e devolve -1 quando o caminho não existe, de modo que uma cópia sem esta verificação escreveria um valor negativo no catálogo. A condição exists faz a pergunta antes de o valor ser lido.

Depois adicione a verificação do valor em si:

  • Condição do grupo: Custom Content: Is GetLoopPath( "Custom Content", "Items" ) + "/damage" equal to 0?.
  • Action: Report Text : Set alterable string to "Refused: " + Item Id + " has no damage".

Uma arma com dano zero é recusada, e uma arma com dano de menos cinquenta também: o segundo caso exige uma comparação do valor com o mínimo, que o jogo faz com os valores de dois counters.

Passo 8 — Copie o item aceito para o banco de dados​

Adicione um grupo sob o evento de loop:

  • Condição do grupo: Custom Content: Is GetLoopPath( "Custom Content", "Items" ) + "/type" equal to "weapon"?.
  • Action: Item Database : Set string GetString( "Custom Content", GetLoopPath( "Custom Content", "Items" ) + "/name" ) at "/items/" + Item Id with key "name".
  • Action: Item Database : Set string GetString( "Custom Content", GetLoopPath( "Custom Content", "Items" ) + "/type" ) at "/items/" + Item Id with key "type".
  • Action: Item Database : Set number GetNumber( "Custom Content", GetLoopPath( "Custom Content", "Items" ) + "/stack" ) at "/items/" + Item Id with key "stack".
  • Action: Item Database : Set number GetNumber( "Custom Content", GetLoopPath( "Custom Content", "Items" ) + "/value" ) at "/items/" + Item Id with key "value".
  • Action: Item Database : Set number GetNumber( "Custom Content", GetLoopPath( "Custom Content", "Items" ) + "/damage" ) at "/items/" + Item Id with key "damage".

O identificador do item é a chave do membro no catálogo, e o item personalizado entra no mesmo membro que os itens que vêm com o jogo, de modo que a loja, o inventário e o equipamento leem um item personalizado exatamente como um item nativo. Uma poção carrega o membro heal no lugar de damage, e ela é copiada com o mesmo padrão.

Passo 9 — Verifique o recurso​

O item nomeia uma imagem. A verificação dessa imagem pertence ao jogo: o objeto File do Fusion relata se o arquivo existe, e o jogo escreve a resposta no relatório.

  • Action: Report Text : Set alterable string to "Accepted: " + Item Id + " (image missing)".

A extensão não lê imagens e não sabe se um arquivo existe. Ela lê e escreve o documento que nomeia a imagem.

Passo 10 — Aplique os inimigos personalizados​

Adicione um segundo evento com a condição Custom Content: On Loop "Enemies", e leia o identificador do inimigo para uma global antes da cópia:

  • Action: Special : Set Enemy Id to GetString( "Custom Content", GetLoopPath( "Custom Content", "Enemies" ) + "/id" ).
  • Action: Enemy Database : Set string GetString( "Custom Content", GetLoopPath( "Custom Content", "Enemies" ) + "/name" ) at "/enemies/" + Enemy Id with key "name".
  • Action: Enemy Database : Set string GetString( "Custom Content", GetLoopPath( "Custom Content", "Enemies" ) + "/category" ) at "/enemies/" + Enemy Id with key "category".
  • Action: Enemy Database : Set number GetNumber( "Custom Content", GetLoopPath( "Custom Content", "Enemies" ) + "/hp" ) at "/enemies/" + Enemy Id with key "hp".
  • Action: Enemy Database : Set number GetNumber( "Custom Content", GetLoopPath( "Custom Content", "Enemies" ) + "/damage" ) at "/enemies/" + Enemy Id with key "damage".
  • Action: Enemy Database : Set string GetString( "Custom Content", GetLoopPath( "Custom Content", "Enemies" ) + "/loot_table" ) at "/enemies/" + Enemy Id with key "loot_table".

O inimigo personalizado entra no mesmo membro que os inimigos que vêm com o jogo, de modo que o banco de dados o lê com o mesmo caminho. O inimigo que o jogo cria lê /enemies/ + o identificador do seu tipo, e não importa se esse identificador pertence ao jogo ou a um jogador.

Passo 11 — Recuse um inimigo sem vida​

Os inimigos precisam da mesma verificação de existência que os itens:

  • Condição do grupo: Custom Content: GetLoopPath( "Custom Content", "Enemies" ) + "/hp" exists.
  • Action: Report Text : Set alterable string to "Refused: " + Enemy Id + " has no hp member".

Sem este grupo, um mod que esquecesse a vida colocaria -1 no banco de dados de inimigos, e um inimigo com vida negativa nunca morre.

Passo 12 — Remova o conteúdo personalizado​

Adicione um evento com a condição Remove Mods is clicked:

  • Action: Item Database : Delete item at "/items/custom_fire_sword".
  • Action: Enemy Database : Delete item at "/enemies/custom_bone_golem".
  • Action: Status Text : Set alterable string to "Custom content removed".

Os identificadores são os do arquivo do mod, de modo que o jogo remove exatamente o conteúdo que o jogador instalou. Os itens que vêm com o jogo têm outros identificadores, e não são tocados. Um mod com vários itens precisa de uma Action por identificador.

I. Comportamento esperado​

O conteúdo do jogador​

{
  "schema_version": 1,
  "content_version": "1.0.0",
  "requires_game_version": "1.2.0",
  "author": "player_one",
  "items": [
    {"id": "custom_fire_sword", "name": "Flame Sword", "type": "weapon", "stack": 1, "damage": 24, "value": 120, "icon": "custom_fire_sword.png"}
  ],
  "enemies": []
}

O catálogo do jogo depois da cópia​

{
  "items": {
    "potion_health": {"name": "Health Potion", "type": "potion", "stack": 10, "value": 25},
    "custom_fire_sword": {"name": "Flame Sword", "type": "weapon", "stack": 1, "damage": 24, "value": 120}
  }
}

O item personalizado fica ao lado dos itens nativos, no mesmo membro, e a loja e o inventário leem os dois com o mesmo tipo de caminho.

O banco de dados de inimigos depois da cópia​

{
  "enemies": {
    "slime": {"id": "slime", "name": "Marsh Slime", "category": "beast", "hp": 30, "damage": 6, "speed": 40, "xp_reward": 12, "attack_range": 24, "loot_table": "slime"},
    "custom_bone_golem": {"id": "custom_bone_golem", "name": "Bone Golem", "category": "undead", "hp": 120, "damage": 18, "speed": 45, "xp_reward": 90, "attack_range": 30, "loot_table": "bandit"}
  }
}

O inimigo personalizado é uma definição como as outras. O inimigo que o jogo cria lê /enemies/ + o identificador do seu tipo, de modo que um tipo escrito por um jogador é lido com o mesmo caminho que um tipo que vem com o jogo.

Depois de o jogador remover os mods​

{
  "items": {
    "potion_health": {"name": "Health Potion", "type": "potion", "stack": 10, "value": 25}
  }
}

O conteúdo personalizado desapareceu e os itens nativos não foram tocados.

J. Casos extremos e tratamento de erros​

SituaçãoO que aconteceTratamento
O arquivo não existeA carga falha e On Error é executadoRelate o arquivo ausente e continue com o conteúdo que já está carregado.
O arquivo não é JSONO documento não é substituídoRelate a falha e mantenha o conteúdo nativo.
O arquivo tem o schema_version erradoA flag de validade continua em zeroRecuse o conteúdo e diga qual versão a build entende.
O arquivo exige um jogo mais novoA flag de validade continua em zeroRecuse o conteúdo e diga a versão da build.
Um item não tem identificadorO caminho não seleciona nada e o identificador fica vazioRecuse o item e relate-o.
Um membro do arquivo está ausenteO número lê -1, a reserva da extensão, e o estado de erro do objeto é ativadoVerifique o membro com a condição exists antes da cópia, como fazem os Passos 7 e 11.
Um membro do arquivo tem o tipo erradoO número lê -1 e o texto lê vazioVerifique o tipo do membro antes da cópia, e recuse o conteúdo que não corresponde ao schema do jogo.
Dois itens compartilham um identificadorO segundo substitui o primeiroRecuse o duplicado e relate os dois identificadores.
Um item tem um tipo desconhecidoO tipo não é um que o jogo aceitaRecuse o item e relate o tipo.
Um número está fora da faixa aceitaO valor quebraria o equilíbrio do jogoRecuse o item e relate o valor.
A imagem do item está ausenteO jogo não encontra nenhuma figura para o itemA verificação pertence ao jogo, com o objeto File. Relate o item como incompleto.
O arquivo declara um nível que o jogo não entendeO nível é ignoradoO nível usa a estrutura do Carregar níveis a partir de JSON.
O conteúdo é carregado duas vezesOs membros são escritos de novo com os mesmos valoresA cópia é idempotente, porque a chave do membro é o identificador.
O arquivo é editado enquanto o jogo o lêO documento do runtime é o que foi interpretadoO jogo lê o arquivo de novo para o próximo mod.
O jogo roda no runtime de navegadorO jogo não alcança o sistema de arquivos do dispositivoO jogador escolhe o arquivo com uma referência de seletor, ou o arquivo vem do armazenamento da origem.
O jogo roda em um alvo móvelO arquivo precisa estar dentro do sandbox da aplicaçãoOfereça uma forma de importar o arquivo para o sandbox, ou leia-o do armazenamento da origem.

K. Compatibilidade entre runtimes​

O sistema lê um arquivo que o jogador escreveu e escreve os valores nos documentos do jogo.

AlvoTrabalho de arquivoAlteração de valoresObservações
WindowsImplementado e testadoImplementado e testadoO arquivo é lido da pasta da aplicação.
AndroidImplementado, sem verificação automáticaImplementado, sem verificação automáticaO arquivo precisa estar dentro do sandbox da aplicação.
HTML5Implementado e testadoImplementado e testadoO jogador escolhe o arquivo com um seletor, ou o arquivo vem do armazenamento da origem. Uma operação de arquivo concorrente é recusada.
macOSDesconhecidoDesconhecidoNenhuma build separada foi verificada.
iOSImplementado, sem verificação automáticaImplementado, sem verificação automáticaO arquivo precisa estar dentro do sandbox da aplicação.

Nenhum alvo dá a um jogo acesso irrestrito ao sistema de arquivos do dispositivo. A matriz completa está na Compatibilidade entre runtimes.

M. Próximos passos​

  • Valide o arquivo contra um schema. A extensão consegue validar um documento contra um JSON schema, que recusa um arquivo com um membro ausente antes de o jogo lê-lo. Veja Enable JSON Schema Validation.
  • Copie uma definição inteira de uma vez. Os construtores montam um texto JSON a partir dos valores que foram lidos, e o jogo insere esse texto no banco de dados com uma única Action.
  • Deixe o jogador escrever o arquivo dentro do jogo. Uma tela com campos para o nome, o tipo e os valores grava o arquivo de conteúdo com as Actions de arquivo do jogo.
  • Mostre os mods em uma lista. A lista lê os autores e as versões dos arquivos e mostra o relatório de cada um deles.
  • Guarde o conteúdo personalizado no arquivo de salvamento. O Sistema de inventário com pilhas guarda os itens que o jogador possui, e um item personalizado é guardado exatamente como um item nativo.
