Controles customizáveis

A. Visão geral​

O menu de opções de Emberfall deixa o jogador escolher as teclas de todas as ações do jogo. O mapeamento sobrevive a um reinício, os padrões podem ser restaurados e uma tecla que duplica outra é recusada com uma mensagem em vez de quebrar o jogo silenciosamente.

DificuldadeIntermediário
ComplexidadeMédia — um documento de mapeamento, uma lista de ações e uma verificação de conflito
Conhecimentos de FusionEventos de frame, objetos Active, objetos String, variáveis globais, o objeto de teclado
Conhecimentos de JSON++Ler membros com caminho calculado, substituir um item de um array, pesquisar valores, gravar o mapeamento

Cenário de jogo​

O jogador abre as opções de Emberfall e chega aos controles. Nove ações são listadas, de Mover para a esquerda até Pausar. O jogador pressiona a tecla W enquanto Mover para cima está selecionada, e a lista passa a mostrar W. O jogador tenta a mesma tecla em Mover para a esquerda, e o jogo recusa, porque W já move o herói para cima e duas ações não podem responder à mesma tecla.

Objetivos de aprendizado​

Ao final deste guia você será capaz de:

  • descrever os controles de um jogo como um documento de identificadores e teclas;
  • ler a associação de uma ação com um caminho montado em tempo de execução;
  • substituir uma tecla dentro de um array de teclas e manter o array com um formato conhecido;
  • descobrir se uma tecla já está em uso, com uma pesquisa e com um laço;
  • guardar o mapeamento, restaurar os padrões e carregar o mapeamento quando o jogo começa.

O que você vai construir​

Um documento de mapeamento que lista todas as ações do jogo com a tecla padrão e as teclas atuais, uma lista de controles no menu de opções, um evento de captura que registra a tecla pressionada, uma verificação de conflito que recusa uma duplicata, e os eventos que guardam o mapeamento e restauram os padrões.

B. Pré-requisitos​

Conhecimentos de Fusion necessários

  • Eventos de frame e a condição Start of Frame.
  • O objeto de teclado e a condição que relata uma tecla pressionada.
  • O objeto Active e a condição is clicked.
  • O objeto String e a Action Set alterable string.
  • Variáveis globais no objeto Special, inclusive uma que guarda texto.
  • O laço do jogo: um evento Loop que é executado uma vez por item de uma lista.

Conceitos de JSON++ necessários

  • Caminhos JSON, e a leitura de um item de um array com um caminho como /actions/move_left/keys/0.
  • Entender loops JSON, porque a verificação de conflito percorre as ações.
  • Resultados de busca e sua duração, porque a verificação de conflito também usa uma pesquisa.
  • Estado da instância JSON: o mapeamento vive em um JSON++ Object só seu.

Limitações de runtime a considerar

  • O JSON++ Object não lê o teclado. Ele guarda o mapeamento e o devolve. A detecção de uma tecla pressionada e o movimento do herói pertencem ao Fusion, ou ao sistema de entrada que o jogo usa.
  • O nome de uma tecla é texto. O jogo e o documento precisam concordar com a grafia, porque a comparação é uma comparação de texto.
  • Uma tecla que o jogo não consegue ler é uma associação morta. Teste as associações no alvo em que o jogo é publicado.

Objetos padrão usados aqui

String, Counter, Special, Timer, Active, JSON++ Object.

Tutoriais de pré-requisito relacionados

C. Cenário de jogo​

Toda ação de Emberfall tem um identificador: move_left, move_right, move_up, move_down, jump, attack, interact, use_potion e pause. O identificador nunca muda. A tecla que responde a ele é o que o jogador escolhe.

O documento guarda as duas coisas. Para cada ação, ele guarda o nome mostrado no menu, a tecla padrão e a lista das teclas associadas no momento. A lista é um array porque uma ação pode responder a mais de uma tecla, e porque uma associação pode manter uma segunda tecla como alternativa.

O menu de opções lê o documento e desenha uma linha por ação. Quando o jogador seleciona uma linha e pressiona uma tecla, o jogo grava essa tecla no documento. Antes da gravação, o jogo verifica se a tecla já está em uso por outra ação, e recusa quando está.

Os eventos de jogabilidade leem o mesmo documento. O evento que faz o herói pular compara a tecla pressionada com a tecla guardada em /actions/jump/keys/0. O documento é o único lugar onde a associação vive, e isso é o que faz da restauração dos padrões um único evento.

D. Resultado final​

O sistema completo se comporta assim:

  • A lista de controles mostra a associação atual de cada ação.
  • Selecionar uma ação e pressionar uma tecla a reassocia na hora, e a lista mostra a nova tecla.
  • Uma tecla que outra ação já usa é recusada, e a lista mantém a associação antiga.
  • Restaurar padrões devolve a todas as ações a tecla com que o jogo foi publicado.
  • O mapeamento é guardado e aplicado na próxima inicialização.
  • O código de jogabilidade não muda quando uma association muda.

E. Estrutura de dados JSON​

  "schema_version": 1,
  "actions": {
    "move_left": {
      "name": "Move left",
      "default": "left",
      "keys": ["left"]
    },
    "move_right": {
      "name": "Move right",
      "default": "right",
      "keys": ["right"]
    },
    "move_up": {
      "name": "Move up",
      "default": "up",
      "keys": ["up"]
    },
    "move_down": {
      "name": "Move down",
      "default": "down",
      "keys": ["down"]
    },
    "jump": {
      "name": "Jump",
      "default": "space",
      "keys": ["space"]
    },
    "attack": {
      "name": "Attack",
      "default": "z",
      "keys": ["z"]
    },
    "interact": {
      "name": "Interact",
      "default": "e",
      "keys": ["e"]
    },
    "use_potion": {
      "name": "Use potion",
      "default": "q",
      "keys": ["q"]
    },
    "pause": {
      "name": "Pause",
      "default": "escape",
      "keys": ["escape"]
    }
  }
}

O objeto raiz guarda a versão e as ações.

actions é um objeto cujos membros são as ações, cada uma nomeada pelo seu identificador. Um objeto é usado em vez de um array porque o identificador da ação é a chave da busca, e um caminho como /actions/jump/keys/0 alcança a associação de uma única ação sem nenhum índice.

Cada ação guarda três membros:

MembroTipoSignificado
namestringO nome da ação mostrado no menu de opções.
defaultstringA tecla com que o jogo é publicado. A restauração dos padrões a copia de volta para keys.
keysarray de cadeiasAs teclas atualmente associadas à ação. A primeira é a tecla que o jogo usa, e as outras são alternativas.

O nome de uma tecla é um texto escolhido pelo jogo: left, right, up, down, space, z, e, q, escape. O documento não define esse vocabulário; o jogo define.

G. Implementação passo a passo​

Passo 1 — Crie os objetos​

  1. Adicione aos frames que os usam os objetos listados acima.
  2. Crie as variáveis globais Action Id, New Key, Default Key e Other Key no objeto Special.
  3. Dê às linhas do Controls Row uma alterable string chamada ActionId com o identificador da ação: move_left, jump, attack e assim por diante.

Passo 2 — Carregue o mapeamento​

Adicione um evento Start of Frame:

  • Condição: Start of Frame.
  • Action: Controls Data : Load JSON from file at Apppath$ + "controls.json".

Passo 3 — Desenhe a lista​

Adicione um evento com a condição Controls Data: On JSON Loaded:

  • Action: Timer : Fire event "ControlsReady" after 00"-01.

O Timer agenda ControlsReady com atraso de 10 ms. O evento nomeado confirma que a carga já terminou antes de atualizar a lista.

Passo 4 — Mostre a associação de uma linha​

Adicione um evento com a condição Controls Row is clicked:

  • Action: Special : Set Action Id to ActionId("Controls Row").
  • Action: Special : Set Default Key to GetString( "Controls Data", "/actions/" + Action Id + "/default" ).
  • Action: Key Label : Set alterable string to GetString( "Controls Data", "/actions/" + Action Id + "/keys/0" ).

A primeira Action guarda o identificador da linha em uma global, de modo que os eventos seguintes funcionam com qualquer linha. A última Action mostra a tecla em uso.

Passo 5 — Capture a tecla que o jogador pressionou​

Adicione um evento com a condição Keyboard: On key pressed:

  • Action: Special : Set New Key to <a tecla que foi pressionada>.
  • Action: Controls Data : Set array New Key at "/actions/" + Action Id + "/keys" with key "unused" and index 0.

A primeira Action registra a tecla em uma global. A segunda substitui o primeiro item do array de teclas da ação que está sendo editada. O array mantém seu formato: a associação sempre tem uma primeira tecla, e a restauração dos padrões tem um valor para gravar.

Passo 6 — Recuse uma tecla que outra ação já usa​

Adicione um evento com a condição Controls Data: On Loop "Actions" e, dentro dele, a comparação abaixo. O laço percorre as ações do documento, e a comparação lê a primeira tecla de cada uma:

  • Condição do grupo: Controls Data: Is "/actions/" + GetLoopKey( "Controls Data", "Actions" ) + "/keys/0" equal to New Key?.

Dentro desse grupo, o evento que relata o conflito:

  • Action: Status Text : Set alterable string to "Already used by another action".

O grupo é executado para a ação que já é dona da tecla. O evento que grava a nova associação pertence ao grupo que não encontra conflito, de modo que a gravação nunca acontece quando há um conflito.

Passo 7 — Grave a associação quando nada está em conflito​

O laço grava a tecla da ação corrente em uma global e compara essa tecla com a nova:

  • Action: Special : Set Other Key to GetString( "Controls Data", "/actions/" + GetLoopKey( "Controls Data", "Actions" ) + "/keys/0" ).

  • Condição do grupo: Controls Data: Is "/actions/" + Action Id + "/keys/0" equal to New Key? lê a associação da ação que está sendo editada, e o grupo que grava a nova tecla é executado quando essa associação é diferente da tecla nova.

As duas comparações juntas dão a regra de que o guia precisa: o jogo grava a nova tecla somente quando a ação que está sendo editada não é a ação que já é dona dela.

Passo 8 — Restaure os padrões​

Adicione um evento com a condição Restore Defaults is clicked:

  • Action: Controls Data : Set array Default Key at "/actions/" + Action Id + "/keys" with key "unused" and index 0.
  • Action: Status Text : Set alterable string to "Default restored".

O evento restaura a ação selecionada. Para restaurar todas as ações de uma vez, percorra as ações com um laço e grave o membro default de cada uma no primeiro item do seu próprio array de teclas.

Passo 9 — Guarde o mapeamento​

Adicione um evento com a condição Save Controls is clicked:

  • Action: Controls Data : Save JSON to file at Apppath$ + "controls.json".

E um evento com a condição Controls Data: On JSON Saved to File:

  • Action: Status Text : Set alterable string to "Controls saved".

Passo 10 — Leia a associação na jogabilidade​

Os eventos de jogabilidade leem o mapeamento. O evento que faz o herói pular compara a tecla que foi pressionada com a tecla guardada no documento:

  • Condição: Keyboard: On key pressed.
  • Condição: Controls Data: Is "/actions/jump/keys/0" equal to <a tecla que foi pressionada>?.
  • Action: Player : Set Y Velocity to -300.

O documento não lê o teclado e não move o herói. Ele guarda o nome da tecla, e os eventos do jogo decidem o que essa tecla significa.

I. Comportamento esperado​

O mapeamento de uma instalação nova​

{
  "schema_version": 1,
  "actions": {
    "move_left": {"name": "Move left", "default": "left", "keys": ["left"]},
    "move_up": {"name": "Move up", "default": "up", "keys": ["up"]},
    "jump": {"name": "Jump", "default": "space", "keys": ["space"]},
    "attack": {"name": "Attack", "default": "z", "keys": ["z"]}
  }
}

A lista mostra left, up, space e z.

Depois de o jogador associar W a Mover para cima​

{
  "schema_version": 1,
  "actions": {
    "move_left": {"name": "Move left", "default": "left", "keys": ["left"]},
    "move_up": {"name": "Move up", "default": "up", "keys": ["w"]},
    "jump": {"name": "Jump", "default": "space", "keys": ["space"]},
    "attack": {"name": "Attack", "default": "z", "keys": ["z"]}
  }
}

O array de move_up ainda tem um item, e o padrão não foi tocado, de modo que a restauração dos padrões tem um valor com que trabalhar.

Depois de o jogador tentar associar W a Mover para a esquerda​

O documento não muda:

{
  "schema_version": 1,
  "actions": {
    "move_left": {"name": "Move left", "default": "left", "keys": ["left"]},
    "move_up": {"name": "Move up", "default": "up", "keys": ["w"]}
  }
}

A linha de status lê Already used by another action, e a associação de Mover para a esquerda continua sendo left.

J. Casos extremos e tratamento de erros​

SituaçãoO que aconteceTratamento
O arquivo de mapeamento está ausenteA carga falha e On Error é executadoPublique o arquivo com o jogo e grave os padrões quando ele faltar.
Uma ação não tem o membro keysO caminho não seleciona nada e a expressão devolve um texto vazioVerifique a existência de /actions/ + Action Id + /keys/0 antes de lê-lo.
Uma ação tem um array keys vazioO caminho não seleciona nadaGrave o padrão no array quando o array estiver vazio.
O jogador associa uma tecla que o jogo não consegue lerA associação é guardada e a ação nunca aconteceTeste todas as teclas que o jogador pode escolher nos alvos em que o jogo é publicado.
Duas ações compartilham uma teclaAmbas respondem à mesma teclaA verificação de conflito recusa a segunda associação.
A ação que está sendo editada é a dona da teclaA verificação acusaria um conflito consigo mesmaCompare a associação da ação que está sendo editada com a tecla nova antes de relatar o conflito.
O jogador associa uma tecla a uma ação que tem alternativasA primeira tecla é substituída e as alternativas permanecemGrave no índice 0 do array e mantenha os outros itens.
O documento é editado à mão e tem uma ação desconhecidaO jogo a ignoraPercorra as ações com um laço em vez de nomeá-las uma a uma.
O jogo roda em HTML5Apppath$ não tem significadoUse uma referência de navegador como storage://controls e consulte o Trabalhar com arquivos por plataforma.
O mapeamento é gravado enquanto o jogo o lêO documento do runtime pode ser substituídoGrave o arquivo em um único evento e deixe o jogo ler o documento de novo depois de gravá-lo.

K. Compatibilidade entre runtimes​

O sistema lê e grava um arquivo e lê valores com caminhos calculados.

AlvoTrabalho de arquivoAlteração de valoresObservações
WindowsImplementado e testadoImplementado e testadoApppath$ resolve para a pasta da aplicação exportada.
AndroidImplementado, sem verificação automáticaImplementado, sem verificação automáticaGrava dentro do sandbox da aplicação. Teste a exportação.
HTML5Implementado e testadoImplementado e testadoUse uma referência de navegador para o mapeamento.
macOSDesconhecidoDesconhecidoNenhuma build separada foi verificada.
iOSImplementado, sem verificação automáticaImplementado, sem verificação automáticaGrava dentro do sandbox da aplicação. Teste a exportação.

O teclado pertence ao runtime do jogo e não à extensão. O que a extensão contribui é o documento, as leituras e as gravações. A matriz completa está na Compatibilidade entre runtimes.

M. Próximos passos​

  • Mantenha as alternativas em uso. Grave a segunda tecla do array na segunda condição da ação, para que o jogador possa associar duas teclas à mesma ação.
  • Mostre a tecla que está em conflito. A pesquisa pelo valor devolve o caminho do resultado, e o caminho nomeia a ação que é dona da tecla.
  • Restaure todas as ações de uma vez. Um laço sobre as ações grava o membro default de cada uma no primeiro item do seu próprio array.
  • Guarde o mapeamento com as outras preferências. Um único arquivo de preferências com o idioma, a dificuldade e os controles mantém um único ponto de salvamento das opções.
  • Valide o mapeamento. Um JSON schema rejeita um mapeamento que perdeu uma ação antes de o jogo lê-lo. Veja Enable JSON Schema Validation.
