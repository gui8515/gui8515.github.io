NPC Relationships and Reputation

A. Overview​

The people of Emberfall remember what the hero does. Warden Dorn remembers a bribe taken and a bandit reported. Elder Rook remembers a hero who refused the bounty of the slimes. What they remember becomes a score, the score becomes a relationship, and the relationship decides how they speak, what they offer and which doors they open.

DifficultyAdvanced
ComplexityHigh — two documents, a walk over the thresholds of an NPC, a score that changes the interface
Fusion skillsFrame events, Active objects, String objects, global variables, group conditions, an event that runs every frame
JSON++ skillsAbsolute paths, reading nested members, adding and subtracting numbers, sorting a map by value, iterating an object, saving a file

Gameplay scenario​

The bandit camp of Emberfall offers the hero a bribe to look the other way. Warden Dorn of the watch wants the opposite. Whatever the hero decides, one of the two men remembers it, and the next time they meet they greet the hero differently. The relationship of an NPC is not a feeling but a number, and the number is stored in the save file of the run.

Learning objectives​

By the end of this guide you will be able to:

  • give every NPC an identifier and store a score for that NPC;
  • describe the relationship of an NPC as a set of thresholds, so that the score alone decides the state;
  • change the score when the player makes a decision, and let the data decide how much the decision is worth;
  • change the greeting, the options and the doors of an NPC when the state changes;
  • unlock an interaction when the score reaches its requirement;
  • keep the decisions of the player across a restart.

What you will build​

A reputation panel that shows the score and the state of the NPC the hero is talking to, a greeting that changes with the state, an interaction that appears when the score is high enough, an NPC definition file (npcs.json), a reputation file (reputation.json) and the events that apply a decision, recompute the state and refresh the interface.

B. Prerequisites​

Fusion knowledge you need

  • Frame events such as Start of Frame, and events with the condition Always, which are evaluated again in every frame.
  • Group conditions under an event, and the order in which the actions of an event run before its groups are evaluated.
  • Active objects, the is clicked condition and the Set visible and Set invisible actions.
  • The String object and the Set alterable string action.
  • Global variables on the Special object, written as Special : Set <name> to <value>, and comparisons of two values, such as a number read from a document and a number read from another document.

JSON++ concepts you need

  • JSON Paths, because every read of a score is addressed by an absolute path.
  • Understanding JSON Loops and Reading Loop Values, because the thresholds of an NPC are walked to find the state that the score has reached.
  • JSON Objects and Arrays, because the thresholds are an object whose keys are the names of the states.
  • Missing, Null and Empty, because a score that reads as zero does not prove that the member is present.
  • Conditions and Triggers, in particular the difference between a state condition and a trigger such as On JSON Loaded.

Runtime limitations to keep in mind

  • JSON++ Object stores the score, the decisions and the state. It never greets anybody, never opens a door and never raises a number by itself. The Fusion events of this guide copy the numbers into the interface.
  • JSON++ Object has no action that deletes a file. A reputation that must be erased is overwritten with a fresh document.
  • File paths follow the host. Apppath$ + "reputation.json" works on Windows. HTML5 needs a browser reference such as storage://reputation. See platform-specific file operations.
  • A save emits On JSON Saved to File when the file work completes. On some targets the completion is asynchronous, so the message that confirms a save belongs in that event.

Standard objects used here

JSON++ Object, Active, String and Special.

C. Gameplay Scenario​

Emberfall opens in the village square of level_village. Warden Dorn stands by the gate and watches the road. Beside him, a soldier waits with a purse of coin that the bandits sent.

The hero can report the bandits or take the purse. Nothing else in the world changes when the choice is made, and no message announces what it is worth. The value of the decision is written in the definitions of the NPCs, and the events of the game only read it.

When the hero walks up to Dorn afterwards, the man greets the hero according to the score that is stored for him. A score that fell below the threshold of wary gets a short answer and a closed shop. A score that reached the threshold of friendly opens the cavern gate.

Elder Rook reacts the same way, with his own thresholds and his own decisions. The two NPCs never share a number, because each of them has its own entry in the reputation document.

D. Final Result​

The completed system behaves like this:

  • Taking the bribe of the bandits lowers the score of Warden Dorn and is remembered as a decision.
  • Reporting the bandits raises the score of Warden Dorn and is remembered as a decision.
  • The relationship state of an NPC follows its score: the state is the highest threshold that the score has reached.
  • The greeting of an NPC, the shop button and the interaction button all follow the state that is stored.
  • An interaction becomes available when the score of the NPC reaches its requirement, and using it writes the flag that records it.
  • The dialogue that an NPC opens follows the relationship, so a hostile NPC greets the hero with a different conversation.
  • Everything is written to the file, so the hero is greeted the same way after a restart.

E. JSON Data Structure​

The definitions of the NPCs​

{
  "schema_version": 1,
  "npcs": {
    "npc_elder_rook": {
      "display_name": "Elder Rook",
      "thresholds": {
        "hostile": -20,
        "wary": -5,
        "neutral": 5,
        "friendly": 20,
        "trusted": 40
      },
      "states": {
        "hostile": {"greeting": "Leave. Now.", "can_trade": 0},
        "wary": {"greeting": "I have nothing for you.", "can_trade": 0},
        "neutral": {"greeting": "Well met.", "can_trade": 1},
        "friendly": {"greeting": "Good to see you.", "can_trade": 1},
        "trusted": {"greeting": "The village is in your debt.", "can_trade": 1}
      },
      "decisions": {
        "took_slime_bounty": {"label": "Took the bounty of the slimes", "reputation": 5},
        "refused_bounty": {"label": "Refused the bounty of the slimes", "reputation": -10}
      },
      "interactions": {
        "open_crypt": {"label": "Open the sealed crypt", "min_reputation": 40}
      }
    },
    "npc_warden_dorn": {
      "display_name": "Warden Dorn",
      "thresholds": {
        "hostile": -30,
        "wary": -10,
        "neutral": 0,
        "friendly": 15,
        "trusted": 35
      },
      "states": {
        "hostile": {"greeting": "Turn back.", "can_trade": 0},
        "wary": {"greeting": "You are not welcome here.", "can_trade": 0},
        "neutral": {"greeting": "State your business.", "can_trade": 1},
        "friendly": {"greeting": "The watch is glad to see you.", "can_trade": 1},
        "trusted": {"greeting": "The cavern is open to you.", "can_trade": 1}
      },
      "decisions": {
        "reported_bandits": {"label": "Reported the bandits to the watch", "reputation": 15},
        "took_bribe": {"label": "Took the bribe of the bandits", "reputation": -20}
      },
      "interactions": {
        "open_cavern_gate": {"label": "Open the cavern gate", "min_reputation": 15}
      }
    }
  }
}

The root holds the version of the document and one member, npcs, whose keys are the identifiers of the NPCs.

Each NPC holds four members:

MemberTypeMeaning
display_namestringThe name shown by the panel.
thresholdsobjectThe score that each state starts at, keyed by the name of the state.
statesobjectWhat the NPC does in each state.
decisionsobjectThe choices the player can make, and what each of them is worth.
interactionsobjectThe doors and the services that open when the score is high enough.

The keys of thresholds are the names of the states, and the values are the scores that open them. The keys of states are the same names, and each entry holds the greeting of the NPC in that state and a flag that says whether the NPC trades.

Each decision holds a label for the log of the game and a reputation number. The number may be negative. A negative value is how the score falls.

Each interaction holds a label for the button and a min_reputation number. The interaction opens when the score of the NPC reaches that number.

The reputation of the player​

{
  "schema_version": 1,
  "npcs": {
    "npc_elder_rook": {
      "reputation": 25,
      "state": "friendly",
      "decisions": {"took_slime_bounty": 1, "refused_bounty": 0},
      "interactions": {"open_crypt": 0}
    },
    "npc_warden_dorn": {
      "reputation": -8,
      "state": "wary",
      "decisions": {"reported_bandits": 0, "took_bribe": 1},
      "interactions": {"open_cavern_gate": 0}
    }
  }
}

This document is written to disk. Each NPC holds four members:

MemberTypeMeaning
reputationnumberThe score. It may be negative.
statestringThe name of the state that the score has reached.
decisionsobjectOne flag per decision. A flag of 1 means the decision was made.
interactionsobjectOne flag per interaction. A flag of 1 means the interaction was used.

The score is the only number that the player changes. The state is written by the game and follows the score. The decisions and the interactions are latches: they stop a decision from being applied twice and they record that a door was already opened.

Two documents, two jobs​

The definitions belong to the game and never change while it runs. The reputation belongs to the run and changes with every decision. A new game only has to reset the small document, and a designer can add an NPC without touching a single saved file.

G. Step-by-Step Implementation​

Step 1 — Create the objects and the globals​

  1. Add the objects listed in the previous section to the frame that holds the village square.
  2. On the Special object, create the global variables Current NPC, Threshold Name, Threshold Value, Decision Id and Refresh Ready. Leave them empty or at zero.
  3. Set the Interaction Button and the Trade Button to invisible.

Step 2 — Load the two documents​

Add a Start of Frame event with two actions:

  • Action: NPC Data : Load JSON from file at Apppath$ + "npcs.json".
  • Action: Reputation : Load JSON from file at Apppath$ + "reputation.json".

Step 3 — A decision changes the score​

Add an event with the condition Take Bribe is clicked.

  • Action: Special : Set Current NPC to "npc_warden_dorn".

Under that event, add a group:

  • Condition of the group: Reputation: Is "/npcs/npc_warden_dorn/decisions/took_bribe" equal to 0.
  • Action: Reputation : Set number 1 at "/npcs/npc_warden_dorn/decisions" with key "took_bribe".
  • Action: Reputation : Add number GetNumber( "NPC Data", "/npcs/npc_warden_dorn/decisions/took_bribe/reputation" ) at "/npcs/npc_warden_dorn" with key "reputation".
  • Action: Special : Set Refresh Ready to 1.

The group condition is the latch that keeps a decision from being applied twice. The value that is added is read from the definitions of the NPC, so the price of the decision is data and not a number typed into an event.

Add the same event for Report Bandits, with the decision reported_bandits, the value 15 read from the same place, and the NPC npc_warden_dorn.

The action Add number <value> at "<path>" with key "reputation" adds a number that may be negative, and the member reputation keeps its sign. A score of minus twenty is a real score, not a missing member.

Step 4 — Recompute the state of the NPC​

Add an event with the condition Always, below the events that raise the flags.

  • Condition of the group: Special : Refresh Ready = 1.
  • Action: Special : Set Refresh Ready to 0.
  • Action: Reputation : Set string "hostile" at "/npcs/" + Current NPC + with key "state".
  • Action: NPC Data : Sort by value in ascending order at "/npcs/" + Current NPC + "/thresholds".
  • Action: NPC Data : Start loop "Thresholds" at "/npcs/" + Current NPC + "/thresholds".

The first action gives the NPC the lowest state before the walk begins, so that a score below every threshold still has a state. The sort puts the thresholds in the order of their values, so that the walk visits the lowest threshold first. The sort changes the order of the members of the map in the definitions document, and nothing else.

Step 5 — Walk the thresholds and find the state​

Add an event with the condition NPC Data: On Loop "Thresholds".

  • Action: Special : Set Threshold Name to GetLoopKey( "NPC Data", "Thresholds" ).
  • Action: Special : Set Threshold Value to GetLoopValue( "NPC Data", "Thresholds" ).

Under that event, add a group:

  • Condition of the group: GetNumber( "Reputation", "/npcs/" + Current NPC + "/reputation" ) >= Threshold Value.
  • Action: Reputation : Set string Threshold Name at "/npcs/" + Current NPC + with key "state".

Because the thresholds are walked in ascending order, the last threshold that the score has reached is the highest one, and the state that is written at the end is the right one.

The comparison is a comparison of two values read from the documents. The extension supplies the numbers; the comparison itself is native Fusion work.

Step 6 — Show the score and write the file​

Add an event with the condition NPC Data: On End Loop "Thresholds".

  • Action: Reputation Label : Set alterable string to GetString( "NPC Data", "/npcs/" + Current NPC + "/display_name" ) + ": " + Str$(GetNumber( "Reputation", "/npcs/" + Current NPC + "/reputation" )) + " (" + GetString( "Reputation", "/npcs/" + Current NPC + "/state" ) + ")".
  • Action: Reputation : Save JSON to file at Apppath$ + "reputation.json".

The file is written at the end of the walk, when the state is final. A decision that is interrupted before the end of the walk leaves the previous state on disk.

Step 7 — Show the decisions that the NPC remembers​

In the event of Step 4, add one action after the start of the walk of the thresholds:

  • Action: Reputation : Start loop "Decisions" at "/npcs/" + Current NPC + "/decisions".

Add an event with the condition Reputation: On Loop "Decisions".

  • Action: Special : Set Decision Id to GetLoopKey( "Reputation", "Decisions" ).

Under that event, add a group:

  • Condition of the group: Reputation: Is "/npcs/" + Current NPC + "/decisions/" + Decision Id + equal to 1.
  • Action: Decision Label : Set alterable string to GetString( "NPC Data", "/npcs/" + Current NPC + "/decisions/" + Decision Id + "/label" ).

The decisions are an object keyed by the identifier of the decision, so the loop key names the decision and the loop value is the flag that says whether it was made. Only the decisions that were taken are shown, and the wording of each one comes from the definitions of the NPC.

Step 8 — Greet the hero​

Add an event with the condition Elder Rook is clicked.

  • Action: Special : Set Current NPC to "npc_elder_rook".
  • Action: Greeting Label : Set alterable string to GetString( "NPC Data", "/npcs/npc_elder_rook/states/" + GetString( "Reputation", "/npcs/npc_elder_rook/state" ) + "/greeting" ).

Under that event, add a group for the shop:

  • Condition of the group: NPC Data: Is "/npcs/npc_elder_rook/states/" + GetString( "Reputation", "/npcs/npc_elder_rook/state" ) + "/can_trade" equal to 1.
  • Action: Trade Button : Set visible.

And a second group for the other case:

  • Condition of the group: NPC Data: Is "/npcs/npc_elder_rook/states/" + GetString( "Reputation", "/npcs/npc_elder_rook/state" ) + "/can_trade" equal to 0.
  • Action: Trade Button : Set invisible.

The greeting is not written in the event. The event asks the definitions for the line that belongs to the state, and the state comes from the score.

Step 9 — Open an interaction when the score is high enough​

In the event of Step 8, add a group:

  • Condition of the group: GetNumber( "Reputation", "/npcs/npc_elder_rook/reputation" ) >= GetNumber( "NPC Data", "/npcs/npc_elder_rook/interactions/open_crypt/min_reputation" ).
  • Action: Interaction Label : Set alterable string to GetString( "NPC Data", "/npcs/npc_elder_rook/interactions/open_crypt/label" ).
  • Action: Interaction Button : Set visible.

And a second group for the other case:

  • Condition of the group: GetNumber( "Reputation", "/npcs/npc_elder_rook/reputation" ) < GetNumber( "NPC Data", "/npcs/npc_elder_rook/interactions/open_crypt/min_reputation" ).
  • Action: Interaction Button : Set invisible.

The requirement of the interaction is a number, like the thresholds, so the same kind of comparison decides it.

Step 10 — Use the interaction​

Add an event with the condition Interaction Button is clicked.

  • Action: Reputation : Set number 1 at "/npcs/" + Current NPC + "/interactions" with key "open_crypt".
  • Action: Reputation : Save JSON to file at Apppath$ + "reputation.json".
  • Action: Status Label : Set alterable string to "The crypt is open".

The flag is what remembers that the door was opened. A door that opens once should not open again with a different message.

The key of the action is the identifier of the interaction, and this guide shows the one of Elder Rook. Warden Dorn opens the cavern gate instead, so a project with several interactions keeps the identifier of the interaction in a global variable and writes that variable instead of the literal.

Step 11 — Change the dialogue of the NPC​

In the event of Step 8, add these actions and groups:

  • Action: Special : Set Current Dialogue to "dlg_rook_intro".

Under that event, add a group:

  • Condition of the group: Reputation: Is "/npcs/npc_elder_rook/state" equal to "hostile".
  • Action: Special : Set Current Dialogue to "dlg_rook_hostile".

And a second group:

  • Condition of the group: Reputation: Is "/npcs/npc_elder_rook/state" equal to "trusted".
  • Action: Special : Set Current Dialogue to "dlg_rook_trusted".

The dialogue panel of the branching dialogue guide reads the current dialogue from the same kind of global, so the two systems fit together. The actions of the event run first and the groups replace the dialogue afterwards.

Step 12 — Report a failure to the player​

Add one event for each JSON++ Object.

  • Condition: Reputation: On Error.
  • Action: Status Label : Set alterable string to GetError( "Reputation" ).

And a second one:

  • Condition: NPC Data: On Error.
  • Action: Status Label : Set alterable string to "NPC definitions unavailable".

J. Edge Cases & Error Handling​

SituationWhat happensHandling
reputation.json does not existThe load fails and On Error runsShip the file with the game and reset it when a new run starts.
The score is below every thresholdNo threshold is reached and the state keeps its previous valueThe refresh sets the state to the lowest one before the walk, as this guide does.
The score is above every thresholdThe highest threshold is writtenNothing else is needed.
A threshold is missing for a stateThe state is never reachedKeep the keys of thresholds and the keys of states the same set of names.
The thresholds are not in ascending orderThe walk may stop at a lower thresholdSort the thresholds before the walk, as this guide does.
The score of an NPC is missingThe comparison reads a zero and the state becomes the lowest oneKeep the npcs section of the document complete.
The player takes the bribe twiceThe group condition refuses the second timeThe flag of the decision is the latch.
The interaction button is clicked after the door is openThe flag is written again with the same valueCheck the flag before the action when the interaction has a cost.
The score changes while the walk is runningThe walk uses the score it read at the beginningApply one decision at a time and let the walk finish.
The state of the NPC is out of dateThe greeting reads an old stateThe state is written at the end of the walk and saved in the same place.
The definitions file is saved after the sortThe thresholds are stored in a different orderDo not write the definitions document at runtime, or accept the new order.
The game runs on HTML5Apppath$ has no meaningUse a browser reference such as storage://reputation. See the platform-specific file guide.

Two rules deserve emphasis. First, a score of zero is a score, not a missing member: use the exists condition before reading a score that may be absent. Second, the thresholds are walked in the order of their values, and that order comes from the sort. Without the sort, the document order decides the state, and a file that was edited by hand can hold the thresholds in any order.

K. Runtime Compatibility​

The system relies on four groups of features: file operations, reading and writing values, sorting a map by value and iteration over an object.

TargetFile workValue changesSortingNotes
WindowsImplemented and testedImplemented and testedImplemented and testedApppath$ resolves to the folder of the exported application.
AndroidImplemented, not verified by an automated checkImplemented, not verified by an automated checkImplemented, not verified by an automated checkWrites inside the sandbox of the application. Test the export.
HTML5Implemented and testedImplemented and testedImplemented and testedUse a browser reference. storage:// uses the origin storage.
macOSUnknownUnknownUnknownNo separate build was verified.
iOSImplemented, not verified by an automated checkImplemented, not verified by an automated checkImplemented, not verified by an automated checkWrites inside the sandbox of the application. Test the export.

One difference matters for the sort. On the HTML5 runtime the comparison of the values that are not numbers is made with the string form of the value, while the native runtime compares the text of the document. The thresholds of this guide are all numbers, so both targets sort them in the same order. The full matrix is on the runtime compatibility page.

A second difference matters for the walk. The loop prepares its work from a snapshot, so the thresholds are visited as they were when the walk started. The sort happens before the walk, and the score is not changed during it, so the two never collide.

M. Next Steps​

  • Let the reputation move by itself. Add a member that raises the score every time the hero completes a quest of a giver, and read the amount from the definitions of the NPC.
  • Show the score to the player. The panel of this guide shows the number of the NPC the hero is talking to; a full panel would walk the map of NPCs and draw one line each.
  • Decay the score. A timer that lowers the score of the NPCs that were neglected gives the player a reason to come back.
  • Change the price of the shop. The can_trade flag is a number, and the shop of the inventory guide can read it to offer a discount.
  • Give the decisions a follow-up. A decision that changes the score can also change the dialogue, the same way the relationship changes the greeting.
  • Protect the file. The extension can encrypt the file it writes and validate it against a JSON schema. See Enable Encryption and Enable JSON Schema Validation.
