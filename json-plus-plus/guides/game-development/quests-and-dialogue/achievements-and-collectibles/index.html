Achievements and Collectibles

A. Overview​

Emberfall rewards the hero for things that are not part of any quest. A hundred enemies killed, a lotus herb found in the forest, a bone shard nobody else has seen. Those rewards are the achievements, and the rare objects that unlock them are the collectibles.

DifficultyAdvanced
ComplexityMedium — two documents, one search that links a counter to an achievement, two walks over the achievements
Fusion skillsFrame events, Active objects, String objects, Counter and Timer objects, global variables, group conditions
JSON++ skillsAbsolute paths, reading nested members, searching for a key, reading a result, comparing values, iterating an object, saving a file

Gameplay scenario​

The hero of Emberfall kills slimes in the forest of level_forest and gathers lotus herbs on the way. Nothing in the game tells them that a hundred kills are worth something, and nothing tells them that a bone shard is hidden in the hollow below the old bridge. A panel in the corner of the screen lists the achievements anyway: three of them, the first two with their names and their progress, the third one as three question marks. When a condition is met, a notification slides in from the side and the achievement stops being a question mark.

Learning objectives​

By the end of this guide you will be able to:

  • describe an achievement as data: a title, a counter, a requirement and a reward;
  • keep the definitions of the achievements apart from the progress of the player;
  • link a counter to the achievement it drives with a search, so that the events stay generic;
  • track the collectibles that the hero has found;
  • hide a hidden achievement behind a question mark until it is unlocked;
  • show the percentage of the collection that is unlocked;
  • unlock an achievement once and never a second time;
  • save the progress of the achievements.

What you will build​

An achievement panel with three lines and a percentage, a notification that appears when an achievement is unlocked, an achievement definition file (achievements.json), an achievement progress file (achievements_progress.json) and the events that count the defeats, count the herbs, register a collectible, unlock an achievement and refresh the panel.

B. Prerequisites​

Fusion knowledge you need

  • Frame events such as Start of Frame, and events with the condition Always, which are evaluated again in every frame.
  • Group conditions under an event, and the order in which the actions of an event run before its groups are evaluated.
  • Active objects, the is clicked condition and the is overlapping Active condition.
  • The String object and the Set alterable string action.
  • The Counter object and its Set counter and Add to counter actions.
  • The Timer object and the condition that reports its ticks.
  • Global variables on the Special object, written as Special : Set <name> to <value>, and comparisons of two values.

JSON++ concepts you need

  • JSON Paths, because every read of an achievement is addressed by an absolute path.
  • Search Results and Their Lifetime, because the link between a counter and an achievement is found with a search and the result is read afterwards.
  • Understanding JSON Loops and Reading Loop Values, because the panel walks the achievements twice: once to draw the list and once to count the unlocked ones.
  • Missing, Null and Empty, because a counter that reads as zero does not prove that the counter is missing.
  • Conditions and Triggers, in particular the difference between a state condition and a trigger such as On Results Found.

Runtime limitations to keep in mind

  • JSON++ Object stores the achievements and their progress. It never shows a panel, never plays a sound and never counts a kill by itself. The Fusion events of this guide do the counting and the drawing.
  • A search stores its results in the instance that ran it. The result of a search is read by the event that reports On Results Found, and it is overwritten by the next search.
  • File paths follow the host. Apppath$ + "achievements_progress.json" works on Windows. HTML5 needs a browser reference such as storage://achievements. See platform-specific file operations.

Standard objects used here

JSON++ Object, Active, String, Counter, Timer and Special.

C. Gameplay Scenario​

Emberfall counts three kinds of progress. The first is the number of enemies the hero has defeated. The second is the number of lotus herbs gathered in the forest. The third is the number of bone shards found in the hollow below the old bridge.

The achievements of the game are described in a file that never changes while the game runs. The progress of the hero is described in a second file that changes with every kill. The two are linked by a small map: the name of a counter points at the achievement it drives. That map is what lets a single event count a kill and still know which achievement to check.

The panel of the achievements lists three lines. The first two show their title and their progress, such as Slime Hunter: 42 / 100. The third one is hidden, so it shows ??? and no progress at all.

When the hero kills the hundredth slime, the event that counts the kill looks the achievement up, sees that the requirement is reached and that the achievement is still locked, unlocks it, pays the reward and asks for a notification. The notification names the achievement and disappears at the next tick of the timer.

When the hero finds a bone shard in the hollow, the same machinery runs. The counter that counts the bone shards reaches its requirement, and the third line of the panel stops being a question mark.

D. Final Result​

The completed system behaves like this:

  • The panel lists every achievement with its title and its progress.
  • A hidden achievement shows ??? until it is unlocked, and it never shows its progress before that.
  • The percentage under the list shows how much of the collection is unlocked.
  • A defeat increases the counter of the defeats, and a gather increases the counter of the herbs, without any event naming an achievement.
  • Finding a collectible registers it and counts it.
  • An achievement is unlocked once. A later kill that reaches the requirement again does nothing, and the reward is not paid twice.
  • A notification appears when an achievement is unlocked, and the progress is written to the file.

E. JSON Data Structure​

The definitions of the achievements​

{
  "schema_version": 1,
  "achievements": {
    "ach_slime_hunter": {
      "title": "Slime Hunter",
      "description": "Defeat one hundred enemies.",
      "hidden": 0,
      "counter": "kills",
      "required": 100,
      "reward_gold": 50
    },
    "ach_herbalist": {
      "title": "Herbalist",
      "description": "Gather ten lotus herbs.",
      "hidden": 0,
      "counter": "herbs_gathered",
      "required": 10,
      "reward_gold": 20
    },
    "ach_hidden_hollow": {
      "title": "The Hollow",
      "description": "Something is buried in the old hollow.",
      "hidden": 1,
      "counter": "bone_shards_found",
      "required": 1,
      "reward_gold": 0
    }
  },
  "counters_index": {
    "kills": "ach_slime_hunter",
    "herbs_gathered": "ach_herbalist",
    "bone_shards_found": "ach_hidden_hollow"
  }
}

The root holds the version of the document and two members. achievements is an object whose keys are the identifiers of the achievements. counters_index is a map from the name of a counter to the identifier of the achievement that counter drives.

Each achievement holds these members:

MemberTypeMeaning
titlestringThe name shown by the panel.
descriptionstringThe text shown when the achievement is unlocked.
hiddennumber1 when the achievement must stay secret until it is unlocked.
counterstringThe name of the counter that drives the achievement.
requirednumberThe value of the counter that unlocks the achievement.
reward_goldnumberThe gold paid when the achievement is unlocked.

The counters_index is the reason the events of this guide stay short. A kill event raises a counter and never mentions an achievement; the search then finds the achievement that the counter drives, and the events that follow work with the identifier that the search returned. Without that map, every counter would need its own copy of the unlock logic.

The progress of the player​

{
  "schema_version": 1,
  "counters": {
    "kills": 42,
    "herbs_gathered": 6,
    "bone_shards_found": 0
  },
  "collectibles": {
    "bone_shard": 0,
    "ore_iron": 0
  },
  "unlocked": {
    "ach_slime_hunter": 0,
    "ach_herbalist": 0,
    "ach_hidden_hollow": 0
  }
}

This document is written to disk. It holds three sections:

MemberTypeMeaning
countersobjectThe progress of each counter, keyed by the name of the counter.
collectiblesobjectOne flag per collectible. A flag of 1 means the collectible has been found.
unlockedobjectOne flag per achievement. A flag of 1 means the achievement has been unlocked.

The counters hold the numbers that the events raise. The unlocked section holds the flags that prevent a second unlock. The flags are numbers rather than booleans so that the comparison is the same on every target.

The collectibles are tracked apart from the counters. A counter says how many bone shards were found, and the collectible flag says which ones were found. A game that never gives the same collectible twice can use the flag alone.

Two documents, two jobs​

The definitions belong to the game and never change while it runs. The progress belongs to the player and changes with every kill. A new game only has to reset the small document, and a designer can add an achievement without touching a single saved file.

G. Step-by-Step Implementation​

Step 1 — Create the objects and the globals​

  1. Add the objects listed in the previous section to the frame that holds the gameplay.
  2. On the Special object, create the global variables Current Achievement, Current Counter, Refresh Ready and Notification Ready. Leave them empty or at zero.
  3. Set the Notification Panel to invisible, so that no banner is on screen when the frame starts.

Step 2 — Load the two documents​

Add a Start of Frame event with two actions:

  • Action: Achievement Definitions : Load JSON from file at Apppath$ + "achievements.json".
  • Action: Achievement Progress : Load JSON from file at Apppath$ + "achievements_progress.json".

Step 3 — Count a defeated enemy​

Add an event with the condition Attack is overlapping Slime.

  • Action: Slime : Destroy.
  • Action: Achievement Progress : Add number 1 at "/counters" with key "kills".
  • Action: Achievement Definitions : Search for key "kills" at "/counters_index" (Exact: 1).
  • Action: Special : Set Refresh Ready to 1.

The event never names an achievement. It raises a counter and asks the definitions which achievement that counter drives. The search stores its result in the instance that ran it, and the next step reads it.

Step 4 — Look up the achievement of the counter​

Add an event with the condition Achievement Definitions: On Results Found.

  • Action: Special : Set Current Achievement to GetResultString( "Achievement Definitions", 0 ).
  • Action: Special : Set Current Counter to GetString( "Achievement Definitions", "/achievements/" + Current Achievement + "/counter" ).

The first action reads the value of the member that the search found, which is the identifier of the achievement. The second action reads the name of the counter that drives it, so that the progress can be read from the progress document.

Add a second event with the condition Achievement Definitions: On Not Results Found.

  • Action: Status Label : Set alterable string to "No achievement uses this counter".

That event should never run with the documents of this guide. It exists so that a counter without an achievement is reported instead of passing unnoticed.

Step 5 — Unlock the achievement​

In the event of Step 4, add a group:

  • Condition of the group: Achievement Progress: Is "/unlocked/" + Current Achievement + equal to 0.

Under that group, add a second group:

  • Condition of the group: GetNumber( "Achievement Progress", "/counters/" + Current Counter ) >= GetNumber( "Achievement Definitions", "/achievements/" + Current Achievement + "/required" ).
  • Action: Achievement Progress : Set number 1 at "/unlocked" with key Current Achievement.
  • Action: Gold Counter : Add to counter GetNumber( "Achievement Definitions", "/achievements/" + Current Achievement + "/reward_gold" ).
  • Action: Special : Set Notification Ready to 1.
  • Action: Special : Set Refresh Ready to 1.
  • Action: Achievement Progress : Save JSON to file at Apppath$ + "achievements_progress.json".

The first group is the latch. An achievement that is already unlocked is never unlocked a second time, so the reward is never paid twice. The second group is the condition of the unlock: the counter must have reached the requirement.

The comparison uses >= and not =, because a counter can go past its requirement. A hero who kills a hundred and one slimes still unlocks the achievement once.

The flag Refresh Ready is set again here, so that the panel is drawn with the new state of the achievement.

Step 6 — Collect a lotus herb​

Add an event with the condition Herb is clicked.

  • Action: Herb : Destroy.
  • Action: Achievement Progress : Add number 1 at "/counters" with key "herbs_gathered".
  • Action: Achievement Definitions : Search for key "herbs_gathered" at "/counters_index" (Exact: 1).
  • Action: Special : Set Refresh Ready to 1.

The event is the same as the event of Step 3 with another counter. That is the point of the map in the definitions: adding a new achievement is a new counter and a new entry in the map.

Step 7 — Register a hidden collectible​

Add an event with the condition Bone Shard is clicked.

  • Action: Bone Shard : Destroy.
  • Action: Achievement Progress : Set number 1 at "/collectibles" with key "bone_shard".
  • Action: Achievement Progress : Add number 1 at "/counters" with key "bone_shards_found".
  • Action: Achievement Definitions : Search for key "bone_shards_found" at "/counters_index" (Exact: 1).
  • Action: Special : Set Refresh Ready to 1.

The collectible is registered twice on purpose. The flag in /collectibles remembers which collectible was found, and the counter feeds the achievement that the hidden collectible unlocks.

Step 8 — Draw the panel​

Add an event with the condition Always, below the events that raise the flags.

  • Condition of the group: Special : Refresh Ready = 1.
  • Action: Special : Set Refresh Ready to 0.
  • Action: Unlocked Counter : Set counter to 0.
  • Action: Achievement Progress : Start loop "Unlocked" at "/unlocked".
  • Action: Achievement Definitions : Start loop "Achievements" at "/achievements".

Two walks start here. The first one counts the achievements that are unlocked, and the second one draws the three lines of the panel.

Step 9 — Count the unlocked achievements​

Add an event with the condition Achievement Progress: On Loop "Unlocked".

  • Condition of the group: GetLoopValue( "Achievement Progress", "Unlocked" ) = 1.
  • Action: Unlocked Counter : Add to counter 1.

The values of the map are numbers, so the loop value is the flag itself. A flag of one means the achievement is unlocked.

Add an event with the condition Achievement Progress: On End Loop "Unlocked".

  • Action: Completion Label : Set alterable string to Str$(Round(value("Unlocked Counter") / GetNumItems( "Achievement Progress", "/unlocked" ) * 100)) + "%".

The total number of achievements is read with GetNumItems instead of with the loop, because the state of the loop is gone by the time the walk ends.

Step 10 — Draw the list of achievements​

Add an event with the condition Achievement Definitions: On Loop "Achievements".

  • Action: Special : Set Current Achievement to GetLoopKey( "Achievement Definitions", "Achievements" ).

Under that event, add a group for the first line:

  • Condition of the group: GetLoopIndex( "Achievement Definitions", "Achievements" ) = 0.
  • Action: Achievement Label 1 : Set alterable string to GetString( "Achievement Definitions", "/achievements/" + Current Achievement + "/title" ) + ": " + Str$(GetNumber( "Achievement Progress", "/counters/" + GetString( "Achievement Definitions", "/achievements/" + Current Achievement + "/counter" ) )) + " / " + Str$(GetNumber( "Achievement Definitions", "/achievements/" + Current Achievement + "/required" )).

Under that group, add a second group, which holds no action of its own:

  • Condition of the group: Achievement Progress: Is "/unlocked/" + Current Achievement + equal to 0.

Under that group, add a third group:

  • Condition of the group: Achievement Definitions: Is "/achievements/" + Current Achievement + "/hidden" equal to 1.
  • Action: Achievement Label 1 : Set alterable string to "???".

Repeat the three groups for the second line with the condition GetLoopIndex( "Achievement Definitions", "Achievements" ) = 1 and the third line with GetLoopIndex( "Achievement Definitions", "Achievements" ) = 2.

The title is written first and replaced by the question mark afterwards, so a hidden achievement that is still locked shows nothing but the question mark.

Step 11 — Show the notification​

Add a second group to the Always event, above the group of Step 8.

  • Condition of the group: Special : Notification Ready = 1.
  • Action: Special : Set Notification Ready to 0.
  • Action: Notification Panel : Set visible.
  • Action: Notification Label : Set alterable string to GetString( "Achievement Definitions", "/achievements/" + Current Achievement + "/title" ) + " unlocked".

Add an event with the condition Achievement Timer On timer.

  • Action: Notification Panel : Set invisible.

The timer runs on the interval that was set in the Frame Editor, so the banner stays on screen until the next tick.

Step 12 — Report a failure to the player​

Add one event for each JSON++ Object.

  • Condition: Achievement Progress: On Error.
  • Action: Status Label : Set alterable string to GetError( "Achievement Progress" ).

And a second one:

  • Condition: Achievement Definitions: On Error.
  • Action: Status Label : Set alterable string to "Achievements unavailable".

I. Expected Behavior​

Before the hundredth slime falls​

achievements_progress.json shows a run in progress:

{
  "schema_version": 1,
  "counters": {
    "kills": 42,
    "herbs_gathered": 6,
    "bone_shards_found": 0
  },
  "collectibles": {
    "bone_shard": 0,
    "ore_iron": 0
  },
  "unlocked": {
    "ach_slime_hunter": 0,
    "ach_herbalist": 0,
    "ach_hidden_hollow": 0
  }
}

The panel reads Slime Hunter: 42 / 100, Herbalist: 6 / 10 and ???. The percentage reads 0.

After the hundredth slime and the bone shard of the hollow​

{
  "schema_version": 1,
  "counters": {
    "kills": 100,
    "herbs_gathered": 6,
    "bone_shards_found": 1
  },
  "collectibles": {
    "bone_shard": 1,
    "ore_iron": 0
  },
  "unlocked": {
    "ach_slime_hunter": 1,
    "ach_herbalist": 0,
    "ach_hidden_hollow": 1
  }
}

The panel reads Slime Hunter: 100 / 100, Herbalist: 6 / 10 and The Hollow: 1 / 1. The percentage reads 67, because two of the three achievements are unlocked. The gold counter of the hero is fifty gold higher than it was.

J. Edge Cases & Error Handling​

SituationWhat happensHandling
achievements_progress.json does not existThe load fails and On Error runsShip the file with the game and reset it when a new run starts.
A counter is missing from the progress documentThe write creates the member with the value oneKeep the counters section complete, with an entry for every counter of the map.
The search finds no achievement for a counterOn Not Results Found runsReport it. A counter without an achievement is a mistake in the definitions.
The search finds more than one achievementThe first result is usedKeep the keys of counters_index unique, and check the number of results when the definitions grow.
A counter goes past its requirementThe comparison still holds and the achievement is unlockedThe unlock is guarded by the flag, so the reward is paid once.
The hero kills the same enemy again after the unlockThe counter grows and nothing else happensThe latch of Step 5 holds, so no second notification and no second payment.
A hidden achievement is not unlockedThe panel shows ??? and no progressThe question mark is written after the title, so it wins.
The percentage is calculated when there is no achievementThe division has no divisorGuard the label with the number of achievements before the division.
The notification is on screen when the level endsThe banner stays on screen in the next frameHide the Notification Panel in the event that leaves the level.
The progress file cannot be writtenThe save fails and On Error runsKeep the counters in memory for the rest of the run and tell the player that the progress was not remembered.
A path contains a slash in a keyThe path is split at the slashEncode the slash as ~1 and the tilde as ~0 inside a path.
The game runs on HTML5Apppath$ has no meaningUse a browser reference such as storage://achievements. See the platform-specific file guide.

Two rules deserve emphasis. First, a counter that reads as zero does not prove that the counter is absent: use the exists condition before reading a member that may be missing. Second, the search result belongs to the instance that ran it. Read it in the event that reports On Results Found, and do not expect it to survive the next search.

K. Runtime Compatibility​

The system relies on four groups of features: file operations, reading and writing values, searching for a key and iteration over an object.

TargetFile workValue changesSearchNotes
WindowsImplemented and testedImplemented and testedImplemented and testedApppath$ resolves to the folder of the exported application.
AndroidImplemented, not verified by an automated checkImplemented, not verified by an automated checkImplemented, not verified by an automated checkWrites inside the sandbox of the application. Test the export.
HTML5Implemented and testedImplemented and testedImplemented and testedUse a browser reference. storage:// uses the origin storage.
macOSUnknownUnknownUnknownNo separate build was verified.
iOSImplemented, not verified by an automated checkImplemented, not verified by an automated checkImplemented, not verified by an automated checkWrites inside the sandbox of the application. Test the export.

One difference matters for the search. On the HTML5 runtime the result collection keeps both the paths and the values that were collected, while the native runtime resolves the stored path against the current document when a result is read. The definitions of this guide are not modified while the game runs, so both targets return the same identifier. The full matrix is on the runtime compatibility page.

M. Next Steps​

  • Show a description. The description of an achievement is in the definitions; show it under the title when the achievement is unlocked.
  • Play a sound. A Sound object can play a short chime when the notification appears.
  • Give a reward of items. A reward of gold is a number in the definitions; a reward of items needs the identifier and the quantity of the item as well.
  • Show a hint for a hidden achievement. Add a hint member and show it when the hero stands next to the place where the collectible is.
  • Group the achievements. A category member and a second map let the panel draw several groups of achievements.
  • Protect the file. The extension can encrypt the file it writes and validate it against a JSON schema. See Enable Encryption and Enable JSON Schema Validation.
