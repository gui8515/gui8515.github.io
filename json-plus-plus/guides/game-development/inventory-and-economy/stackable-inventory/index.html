Stackable Inventory System

A. Overview​

Emberfall gives the hero a pack with a fixed number of slots. Every slot holds one stack, and a stack holds several units of the same item: five lotus herbs, three health potions, one iron sword. When the hero picks up an item that is already in the pack, the units join the existing stack instead of opening a second one. When the last unit of a stack is used, the stack leaves the pack.

DifficultyIntermediate
ComplexityHigh — one document, an item catalog, an array of stacks, one scan loop and one search
Fusion skillsFrame events, Active objects, Counter and String objects, global variables, comparison expressions
JSON++ skillsAbsolute paths, loops, searches, insertion, arithmetic, file work, error handling

Gameplay scenario​

Ari leaves the village with an empty pack. The first lotus herb she picks up opens a stack; the second one joins it, so the pack still shows a single slot used. When the pack is full, the next herb is refused with a message and nothing is written. The player can drink a potion, split a stack in two to free a slot later, and save the pack before leaving the level.

Learning objectives​

By the end of this guide you will be able to:

  • describe every item by a stable identifier and keep its definition in a catalog;
  • store the contents of the pack as an array of {"id": ..., "quantity": ...} entries;
  • count the stacks and the units of the pack with a loop over that array;
  • find the stack that holds a given identifier, with a search and with a scan;
  • add units to an existing stack, open a new stack, split a stack and remove an empty stack;
  • refuse a pickup when the pack has no room, and save the pack to a file.

What you will build​

A pack of twelve slots, an item catalog with eleven entries, the scan loop that measures the pack, the pickup, use and split actions, and the save file inventory.json.

B. Prerequisites​

Fusion knowledge you need

  • Frame events such as Start of Frame and the difference between a frame condition and a group condition under an event.
  • Active objects and the is clicked condition.
  • The Counter object and its Set counter and Add to counter actions.
  • The String object and the Set alterable string action.
  • Global variables on the Special object, written in this manual as Special : Set <name> to <value>.
  • Comparison conditions, written as value1 < value2 or value1 >= value2, and string comparison written as value1 = value2.

JSON++ concepts you need

  • JSON paths, because every read and every write in this guide uses an absolute path such as /player/inventory/0/quantity.
  • Understanding JSON Loops and loop lifecycle, because the scan of the pack is a named loop that publishes its items over several frames.
  • Reading loop values, because the path of the current entry comes from Get Loop Path.
  • Search results and their lifetime, because a search stores a result list that a later edit can make stale.
  • Missing, null and empty, because an entry that does not exist and an entry with a quantity of zero are different situations.
  • JSON instance state: the pack and the catalog live in one document, but each JSON++ Object keeps its own document, its own navigation position and its own result list.

Runtime limitations to keep in mind

  • A loop works on a snapshot of the array. The events that change the pack run after the loop ends, never inside the item event, so the snapshot and the document never disagree.
  • The result path of a search points at the member that holds the searched value. For an entry of the pack, that is the id member. The stack that owns the entry is one level above, which is why the scan exists.
  • File paths follow the host. Apppath$ + "inventory.json" works on Windows. HTML5 needs a browser reference such as storage://inventory, and the mobile targets write inside the sandbox of the application. See platform-specific file operations.
  • A save emits On JSON Saved to File when the file work completes. On some targets the completion is asynchronous, so the confirmation belongs in that event.

Standard objects used here

JSON++ Object, Counter, String, Special, Active and Timer. Nothing else is required.

C. Gameplay Scenario​

The pack of Ari is drawn by the game itself, not by the extension. The extension holds the data of the pack, and the events of Fusion decide what the pack looks like on screen.

The data of the pack is a single document, inventory.json. It holds the catalog of the items of Emberfall, the number of slots of the pack, and the record of the hero. The contents of the pack are an array. Each entry of the array names an item and counts the units of that item:

{"id": "herb_lotus", "quantity": 4}

The array is the order in which the stacks were opened. It is not the identity of a stack. The identity is the identifier inside the entry, and that identifier is the contract with the catalog and with the rest of the game.

Two mechanisms work together when the pack is measured. A loop walks the array and counts the stacks and the units. A search answers a single question, whether one identifier is present in the pack. The loop gives the numbers, the search gives a yes or a no, and the events of Fusion turn both into the messages and the bars of the interface.

D. Final Result​

The finished system behaves like this:

  • The pack line reads 4 / 12 when four stacks occupy the twelve slots of the pack.
  • Picking up a herb that is already in the pack adds the units to that stack and keeps the number of slots unchanged.
  • Picking up an item that is not in the pack opens a new stack and uses one more slot.
  • Picking up anything when all twelve slots are used is refused, and the document is not changed.
  • Drinking a potion removes one unit; drinking the last potion of a stack removes the whole stack and frees the slot.
  • Splitting a stack moves a chosen number of units into a new stack, which uses one more slot.
  • The search answers whether the hero carries a given item, and the message says so.
  • Saving the pack writes inventory.json; loading it at the start of the next session restores the same stacks.
  • A file that cannot be read or written produces a readable message instead of an empty pack.

E. JSON Data Structure​

The complete document​

{
  "schema_version": 1,
  "capacity": 12,
  "items": {
    "potion_health": {"name": "Health Potion", "type": "potion", "stack": 10, "value": 25},
    "potion_mana": {"name": "Mana Potion", "type": "potion", "stack": 10, "value": 30},
    "bread": {"name": "Bread", "type": "food", "stack": 5, "value": 8},
    "herb_lotus": {"name": "Lotus Herb", "type": "material", "stack": 20, "value": 5},
    "ore_iron": {"name": "Iron Ore", "type": "material", "stack": 20, "value": 7},
    "bone_shard": {"name": "Bone Shard", "type": "material", "stack": 20, "value": 4},
    "sword_iron": {"name": "Iron Sword", "type": "weapon", "stack": 1, "value": 120},
    "axe_ember": {"name": "Ember Axe", "type": "weapon", "stack": 1, "value": 150},
    "armor_leather": {"name": "Leather Armor", "type": "armor", "stack": 1, "value": 90},
    "armor_chain": {"name": "Chain Armor", "type": "armor", "stack": 1, "value": 180},
    "key_cavern": {"name": "Cavern Key", "type": "key", "stack": 1, "value": 0}
  },
  "player": {
    "name": "Ari",
    "level": 3,
    "hp": 80,
    "max_hp": 100,
    "gold": 250,
    "checkpoint": "cp_village_square",
    "position": {"x": 320, "y": 640},
    "inventory": [
      {"id": "potion_health", "quantity": 3},
      {"id": "herb_lotus", "quantity": 4},
      {"id": "ore_iron", "quantity": 5},
      {"id": "sword_iron", "quantity": 1}
    ]
  }
}

The root is an object with four members. schema_version is a number that records the shape of the document. capacity is the number of slots of the pack. items is the catalog. player is the record of the hero.

The catalog​

The catalog is an object whose members are the identifiers of the items. The identifier is the name of the member, so the path of the definition of an item is built from the identifier alone.

MemberTypeMeaning
namestringThe name shown in the interface, such as Health Potion.
typestringThe family of the item: potion, food, material, weapon, armor or key. The interface groups the slots by this value.
stacknumberThe largest number of units a single stack of this item may hold. A weapon has a stack of one, so it always occupies a slot of its own.
valuenumberThe base price of one unit. The shop guide uses it.

Because the catalog is keyed by the identifier, every field of an item is reachable with a direct path:

What is readPathExample
The name of an item/items/<id>/name/items/herb_lotus/name
The maximum size of a stack/items/<id>/stack/items/herb_lotus/stack
The base price of a unit/items/<id>/value/items/herb_lotus/value

The array of the pack​

The contents of the pack live under /player/inventory. The array holds one entry per stack.

MemberTypeMeaning
idstringThe identifier of the item, exactly as it appears in the catalog.
quantitynumberThe number of units of that item in the stack. It is never zero: an empty stack is removed from the array.

Three rules keep the array consistent with the rest of the guides:

  • One entry per item. A second unit of the same item joins the existing entry. Two entries with the same identifier are a bug, and the events of this guide never create one.
  • Identifiers, never positions. The events locate a stack by its identifier. The position of the entry in the array is a detail of the moment, and it changes as soon as a stack is removed.
  • Numbers for counts. Quantities are numbers, so the arithmetic actions of the extension can add and subtract them.

The rules the events enforce​

The document does not enforce anything by itself. The rules below are the contract that the events of this guide keep, and the edge cases section lists what happens when one of them is broken.

RuleEnforced by
A stack never holds more units than the stack value of its itemThe pickup branch compares the quantity of the stack with /items/<id>/stack before it adds units.
The pack never holds more stacks than capacityThe pickup branch compares the number of stacks with /capacity before it opens a stack.
An empty stack is removedThe use branch deletes the entry when the last unit is consumed.
A stack of a weapon holds one unitThe catalog gives every weapon a stack of one.

The state that stays in Fusion​

Three groups of values belong to the running game, not to the document: the identifier the player is dealing with, the amount of that identifier, and the pending flags that tell the events which decision they owe. They live in global variables on the Special object, because they describe the state of the current interaction and not the state of the hero.

The path of the stack that the scan found is also a temporary value. It is valid from the moment the scan finds the stack until the array changes, and the events of this guide never keep it longer than that.

Writing those values into the document would be a mistake of design: the file of the hero would carry the leftovers of the last click of the player.

G. Step-by-Step Implementation​

Step 1 — Create the frame and the objects​

  1. Create a frame named Village.
  2. Add the objects of the previous section. Name the counters and the strings exactly as the table lists them, because the captions of the events refer to them by name.
  3. On the Special object, create the global variables Wanted Id (string), Wanted Amount (number), Found Flag (number), Stack Fits (number), Entry Path (string), Entry Quantity (number), Pickup Pending (number), Use Pending (number) and Split Pending (number). Leave every one of them at 0, except Wanted Id and Entry Path, which start empty.

Step 2 — Load the document at the start of the frame​

Add a Start of Frame event with one action:

  • Action: Inventory Data : Load JSON from file at Apppath$ + "inventory.json".

The path expression Apppath$ + "inventory.json" is the folder of the exported application plus the name of the file. When the file is missing or is not valid JSON, the On Error event of Step 16 runs instead.

Step 3 — Start the scan of the pack​

Add an event with the condition Inventory Data: On JSON Loaded:

  • Action: Inventory Data : Start loop "Inventory" at "/player/inventory".

The loop name is Inventory. The same name appears in every condition and in every expression of this guide that reads the current entry. A different name would be a different loop.

Step 4 — Reset the counters when the scan starts​

Add an event with the condition Inventory Data: On Start Loop "Inventory":

  • Action: Slots Used Counter : Set counter to 0.
  • Action: Units Counter : Set counter to 0.

The counters are reset here rather than in the click events, because the scan runs for several reasons: the load of the file, a pickup, a use and a split. One place resets them for all of them.

Step 5 — Count the stacks and the units​

Add an event with the condition Inventory Data: On Loop "Inventory":

  • Action: Slots Used Counter : Add to counter.
  • Action: Units Counter : Set counter to value("Units Counter") + GetNumber( "Inventory Data", GetLoopPath( "Inventory Data", "Inventory" ) + "/quantity" ).

The first action counts one stack per entry. The second reads the quantity of the current entry. The path of that entry comes from Get Loop Path, which returns /player/inventory/0 for the first entry, /player/inventory/1 for the second one, and so on. The expression appends /quantity to that path, so the number that is read belongs to the entry the loop is visiting.

Reading a member under the path of the loop is safe here because the document is not modified during the scan. The events that change the pack all run after the loop ends.

Step 6 — Show the slot usage when the scan ends​

Add an event with the condition Inventory Data: On End Loop "Inventory":

  • Action: Slots Label : Set alterable string to Str$(value("Slots Used Counter")) + " / " + Str$(GetNumber( "Inventory Data", "/capacity" )).

The label shows the number of slots in use and the capacity of the pack. The capacity is read from the document, so a designer can change the size of the pack in the file without touching an event.

Step 7 — Remember the stack of a wanted identifier​

The same scan also answers a second question: where is the stack of a given identifier? Add a group under the On Loop event of Step 5:

  • Condition of the group: Wanted Id = GetString( "Inventory Data", GetLoopPath( "Inventory Data", "Inventory" ) + "/id" ).
  • Action: Special : Set Entry Path to GetLoopPath( "Inventory Data", "Inventory" ).
  • Action: Special : Set Entry Quantity to GetNumber( "Inventory Data", GetLoopPath( "Inventory Data", "Inventory" ) + "/quantity" ).
  • Action: Special : Set Found Flag to 1.

The condition compares the wanted identifier with the identifier of the current entry. When they match, the path of the stack and its quantity are stored in two global variables, and Found Flag becomes 1. When the wanted identifier is empty, no entry matches and Found Flag stays at the value it had before the scan.

Add a second group under the same event, inside the first one:

  • Condition of the group: Entry Quantity + Wanted Amount <= GetNumber( "Inventory Data", "/items/" + Wanted Id + "/stack" ).
  • Action: Special : Set Stack Fits to 1.

This second group answers whether the units still fit in the existing stack. The maximum size of the stack is read from the catalog with the identifier as the last part of the path.

Step 8 — Answer "does the hero carry this item?" with a search​

The scan is the tool for counting and for locating a stack. A search answers a single yes-or-no question. Add an event with the condition Item Check Button is clicked:

  • Action: Inventory Data : Search for value """potion_health""" at "/player/inventory" (Exact: 1).

And two events that answer the search:

  • Condition: Inventory Data: On Results Found.

  • Action: Status Text : Set alterable string to "The hero carries this item".

  • Condition: Inventory Data: On Not Results Found.

  • Action: Status Text : Set alterable string to "The hero does not carry this item".

The result list of this search holds the member that contains the identifier, for example /player/inventory/0/id. The stack that owns that member is /player/inventory/0. The events that change a quantity need the stack, which is why the scan of Step 7 stores it.

Step 9 — Pick up an item​

Add an event with the condition Pickup Button is clicked:

  • Action: Special : Set Wanted Id to "herb_lotus".
  • Action: Special : Set Wanted Amount to 2.
  • Action: Special : Set Found Flag to 0.
  • Action: Special : Set Stack Fits to 0.
  • Action: Special : Set Pickup Pending to 1.
  • Action: Inventory Data : Start loop "Inventory" at "/player/inventory".

The click does not write anything. It records what the player wants and starts the scan. The scan fills Entry Path, Entry Quantity and Found Flag, and the decision is taken when the loop ends.

Step 10 — Add the units to an existing stack​

Add a group under the On End Loop event of Step 6 with the condition Pickup Pending = 1, and inside it a group with the condition Found Flag = 1, and inside that one a group with the condition Stack Fits = 1:

  • Action: Inventory Data : Add number Wanted Amount at Entry Path with key "quantity".
  • Action: Status Text : Set alterable string to "Units added to the stack".
  • Action: Special : Set Pickup Pending to 0.

The innermost group is the one that writes. The two outer groups only carry the decision: the item was found in the pack, and the units still fit in the stack. The path of the stack comes from the global variable Entry Path, and the action writes the member quantity inside that stack.

Step 11 — Open a new stack​

Inside the group Pickup Pending = 1 of Step 10, add a group with the condition Found Flag = 0, and inside it a group with the condition value("Slots Used Counter") < GetNumber( "Inventory Data", "/capacity" ):

  • Action: Inventory Data : Insert object "{""id"":""herb_lotus"",""quantity"":2}" at "/player/inventory" with key "entry".
  • Action: Status Text : Set alterable string to "New stack created".
  • Action: Special : Set Pickup Pending to 0.

The destination is an array, so the insertion appends one entry and the key parameter is ignored. The literal JSON text of the entry is the example of this guide. A general implementation builds that text from the two global variables, with the Fusion string concatenation:

"{""id"":""" + Wanted Id + """,""quantity"":""" + Str$( Wanted Amount ) + """}"

Inside the same group, add a last group with the condition value("Slots Used Counter") >= GetNumber( "Inventory Data", "/capacity" ):

  • Action: Status Text : Set alterable string to "The inventory is full".
  • Action: Special : Set Pickup Pending to 0.

That branch writes nothing. The pack stays exactly as it was.

Step 12 — Drink a potion and remove the empty stack​

Add an event with the condition Use Button is clicked:

  • Action: Special : Set Wanted Id to "potion_health".
  • Action: Special : Set Wanted Amount to 1.
  • Action: Special : Set Found Flag to 0.
  • Action: Special : Set Use Pending to 1.
  • Action: Inventory Data : Start loop "Inventory" at "/player/inventory".

Under the On End Loop event, add a group with the condition Use Pending = 1, and inside it a group with the condition Found Flag = 1:

  • Condition of the group: Entry Quantity > Wanted Amount.
  • Action: Inventory Data : Subtract number Wanted Amount at Entry Path with key "quantity".
  • Action: Status Text : Set alterable string to "The potion was used".
  • Action: Special : Set Use Pending to 0.

And a second group with the condition Entry Quantity <= Wanted Amount:

  • Action: Inventory Data : Subtract number Wanted Amount at Entry Path with key "quantity".
  • Action: Inventory Data : Delete item at Entry Path.
  • Action: Status Text : Set alterable string to "The last potion was used".
  • Action: Special : Set Use Pending to 0.

The last group consumes the units and removes the stack in the same breath. Deleting an entry of an array moves the entries that come after it one position down, so the paths of the other stacks change. The next scan reads the new paths, and no other event keeps a path of its own.

Under the same On End Loop event, add a group with the condition Found Flag = 0, inside the group Use Pending = 1:

  • Action: Status Text : Set alterable string to "The hero has no potion".
  • Action: Special : Set Use Pending to 0.

Step 13 — Split a stack​

Add an event with the condition Split Button is clicked:

  • Action: Special : Set Wanted Id to "herb_lotus".
  • Action: Special : Set Wanted Amount to 2.
  • Action: Special : Set Found Flag to 0.
  • Action: Special : Set Split Pending to 1.
  • Action: Inventory Data : Start loop "Inventory" at "/player/inventory".

Under the On End Loop event, add a group with the condition Split Pending = 1, and inside it a group with the condition Found Flag = 1:

  • Action: Inventory Data : Subtract number Wanted Amount at Entry Path with key "quantity".
  • Action: Inventory Data : Insert object "{""id"":""herb_lotus"",""quantity"":2}" at "/player/inventory" with key "entry".
  • Action: Status Text : Set alterable string to "The stack was split".
  • Action: Special : Set Split Pending to 0.

A split needs a free slot, because it opens a second stack of the same item. The check of the capacity of Step 11 applies here as well; add the same group with the condition value("Slots Used Counter") >= GetNumber( "Inventory Data", "/capacity" ) and the message The inventory is full to refuse the split before it writes anything.

Step 14 — Draw the pack in the interface​

The numbers of the pack are not enough for the player. The name of every stack is read from the catalog and written to a row of the interface. Add a group under the On Loop event of Step 5:

  • Condition of the group: Row Index < 12.
  • Action: Special : Set Stack Label to GetString( "Inventory Data", "/items/" + GetString( "Inventory Data", GetLoopPath( "Inventory Data", "Inventory" ) + "/id" ) + "/name" ).
  • Action: Special : Set Row Index to Row Index + 1.

The condition uses a global variable Row Index that starts at 0 and grows once per entry, so the rows of the interface are filled in the order of the array. The name of the item is read from the catalog with the identifier of the entry, so the interface never has to know the names of the items.

Add the global variables Row Index (number) and Stack Label (string) on the Special object, and reset Row Index to 0 in the On Start Loop event of Step 4.

Step 15 — Restore the pack after a level change​

The pack belongs to the hero, not to the level. When the hero walks into the forest, the level reads the pack from the file and hands it to the interface. Add an event with the condition Start of Level:

  • Action: Inventory Data : Load JSON from file at Apppath$ + "inventory.json".

The On JSON Loaded event of Step 3 starts the scan again, and the counters and the label are refreshed with the contents of the file. The events of the level that change the pack write to the same document, and the save of Step 16 writes it back.

Step 16 — Save the pack and handle the errors​

Add an event with the condition Save Button is clicked:

  • Action: Inventory Data : Save JSON to file at Apppath$ + "inventory.json".

Add a second event with the condition Inventory Data: On JSON Saved:

  • Action: Status Text : Set alterable string to "The inventory was saved".

And a third one with the condition Inventory Data: On Error:

  • Action: Status Text : Set alterable string to GetError( "Inventory Data" ).

The save writes the whole document, including the catalog. That is deliberate: one file describes the pack and the items of Emberfall, so a file that is copied to another machine keeps its meaning.

J. Edge Cases & Error Handling​

SituationWhat happensHandling
inventory.json does not existThe load fails and On Error runsWrite the file with the game on the first run, and show a message that the pack is unavailable.
inventory.json contains invalid JSONThe document is not replaced and the error text describes the problemKeep the technical text for a log and show a short message to the player.
The file has no player memberThe loop finds nothing and the pack line reads 0 / 0Check /player and /player/inventory with the exists condition before the scan, and write an empty pack when they are missing.
The file has no items memberThe maximum size of a stack cannot be read and the value falls back to zeroKeep the catalog in the same file as the pack, and validate the file against a JSON schema.
The pack already holds twelve stacksThe pickup is refused and nothing is writtenCompare the number of stacks with /capacity before every insertion.
The catalog and the pack are in different filesThe maximum size of a stack cannot be readKeep the catalog and the pack in the same document, as this guide does.
The player picks up a weapon, which never stacksThe stack limit of one forces a new slot for every weaponGive every weapon a stack of one in the catalog, and let the capacity of the pack decide how many weapons the hero may carry.
The stack of the item is fullThe units would exceed the stack valueCompare the quantity of the stack with /items/<id>/stack before adding units.
The wanted identifier is not in the catalogThe maximum size of the stack cannot be readAdd every identifier that the game can pick up to the catalog, and validate the file against a JSON schema.
Two entries hold the same identifierThe scan stores the path of the last one that matchedNever open a second stack of an item that is already in the pack, and clean the file when it happens.
An entry has a quantity of zeroThe entry occupies a slot without holding anythingRemove the entry when the last unit is used, and refuse to add units to an empty stack.
A stack of a material holds twenty units and the player picks up three moreThe stack would exceed the maximum sizeCompare the quantity with /items/<id>/stack before the addition, and open a second stack when the maximum is reached.
A stack is deleted while the paths are storedThe stored path points at another entry after the array shiftsKeep the path only for the duration of one scan and read it again after every change of the array.
The search is run and the pack changes afterwardsThe stored result path can point at a member that no longer holds the searched valueRun the search again after every change that matters, and check the number of results before reading one.
The save file cannot be writtenThe save fails and On Error runsKeep the confirmation in On JSON Saved to File, so the player is never told that a save happened when it did not.
The game runs on HTML5Apppath$ has no meaningUse a browser reference such as storage://inventory and read the platform-specific file guide.
The game runs on Android or iOSThe file lands in the sandbox of the applicationUse the path documented for that target and test the export.

Three rules deserve emphasis. First, never identify a stack by its position in the array; the position changes as soon as a stack is removed. Second, a stack that reaches zero must leave the array, because a zero quantity is not a valid state of this design. Third, the events of Fusion own the rules: the document holds the numbers, and the group conditions of the events decide what may change.

K. Runtime Compatibility​

The system relies on four groups of features: file operations, loops, searches, and insertion and change of values.

TargetFile workLoops and searchesNotes
WindowsImplemented and testedImplemented and testedApppath$ resolves to the folder of the exported application.
AndroidImplemented, not verified by an automated checkImplemented, not verified by an automated checkWrites inside the sandbox of the application. Test the export.
HTML5Implemented and testedImplemented and testedUse a browser reference. storage:// uses the origin storage, download:// dispatches a download, embedded:// is read-only.
macOSUnknownUnknownNo separate build was verified.
iOSImplemented, not verified by an automated checkImplemented, not verified by an automated checkWrites inside the sandbox of the application. Test the export.

A second difference matters for the messages of this guide. On the native runtime the exists condition accepts a member whose value is null, while the HTML5 runtime reports such a member as absent. The document of this guide never stores null, so both targets agree. The full matrix is on the runtime compatibility page.

M. Next Steps​

  • Show the pack as a list. Use Get JSON Text to write the array to a String and let a list object draw one row per stack, or read each entry with a loop and fill the rows of the interface.
  • Let the player sort the pack. The action Sort by key in ascending order at <path> sorts the members of an object; a sorted catalog or a sorted list of identifiers keeps the interface stable.
  • Separate the catalog from the pack. Keep items.json read-only and the pack in the save file of the run. The multiple save slots guide shows the save file.
  • Protect the file. The extension can encrypt the file it writes and validate it against a JSON schema. See Enable Encryption.
  • Move the rules into the data. Give every item a weight member and let the capacity be a weight instead of a number of slots.
