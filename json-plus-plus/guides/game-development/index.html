Game Development Guides

These twenty-four guides build complete gameplay systems with JSON++ Object inside Clickteam Fusion. Each one starts from a scenario a designer would recognize — a save menu, a merchant, a boss arena — and ends with the events, the JSON and the failure handling that make it work.

Every guide follows the same path: the gameplay scenario, the JSON that describes it, the Fusion objects that hold it, the event logic, the JSON++ operations, the result the player sees, the way the system survives bad data, and the improvements worth making afterwards.

The shared example project​

The guides use one fictional action RPG, Emberfall, so that a reader who follows several of them sees a single game grow. You do not need to complete one guide before reading another: every guide states the data it starts from.

Conventions used in every guide​

JSON paths are absolute. Every path begins with /, including the root itself, written as /. A path such as /player/inventory/0/quantity always means the same node regardless of where the navigation position currently sits.

Identifiers are stable strings. Items, enemies, NPCs, quests and levels are named by identifiers such as potion_health, never by the order they appear in an array. Fusion objects that represent a game entity carry the same identifier in an alterable string, so an event can match JSON data to the object on screen.

JSON stores; Fusion acts. JSON++ Object holds and transforms data. It does not move a character, spawn an enemy or draw a HUD. Those remain native Fusion work: Set X Position, Create Object, Set Alterable String, Timer, and so on. Each guide names the event that copies a value out of JSON and into a gameplay object.

Event blocks are live. The event examples in this section open in the Fusion event viewer. Switch between the event editor, the event list and the code view to read the same block in three ways. The object column of each event tells you which objects take part in it.

Failures are part of the design. Loading a missing file, reading an absent member and writing into a path that does not exist all have documented outcomes. Every guide includes an On Error branch and says what the player sees when it runs.

Guide index​

Save & Progress​

  1. Multiple Save Slots — a title screen with three independent runs.
  2. Checkpoints and Autosave — a checkpoint, an automatic save and a way back after a defeat.
  3. Persistent World State — chests, doors, bosses and switches that stay as they were left.
  4. Save Versioning and Recovery — older saves that still open, and the ones that cannot.

Inventory & Economy​

  1. Stackable Inventory System — items, quantities, stacks and capacity.
  2. Equipment and Character Stats — slots, modifiers and derived attributes.
  3. Shop and Currency System — a merchant, a price list and a balance that always adds up.
  4. Crafting and Recipes — ingredients, requirements and what comes out of the bench.

Quests & Dialogue​

  1. Quest and Objective Tracking — objectives that survive a restart and a reward paid only once.
  2. Branching Dialogue System — nodes, answers and the conditions that hide an option.
  3. Achievements and Collectibles — counters, hidden goals and a completion percentage.
  4. NPC Relationships and Reputation — a reputation that changes what an NPC says and sells.

Levels & World Data​

  1. Data-Driven Enemy Database — one place to balance every enemy.
  2. Enemy Waves and Spawning — waves, intervals and the arena that escalates.
  3. Random Loot Tables — weights, rarities and the drop that gives nothing.
  4. Loading Levels from JSON — a level described by data and built at runtime.

Settings & Localization​

  1. Game Localization — English and Portuguese in one dictionary structure.
  2. Difficulty Presets — easy, normal and hard as configuration.
  3. Customizable Controls — bindings the player can change and the game can restore.
  4. Tutorials and Unlockable Features — a first-time event that happens only once.

Advanced & Online​

  1. Remote Game Configuration — a configuration read from a remote resource, with a fallback.
  2. Daily Challenges — a challenge of the day, its progress and its reward.
  3. Leaderboard API Integration — reading the answer of a ranking service.
  4. Custom Content and Modding — items, enemies and levels that a player defines.

Where to start​

Begin with Multiple Save Slots if you want the framework every other guide reuses: a JSON++ Object, a save document, and the events that write it and read it back. Continue with Stackable Inventory System for the data model that the shop, the crafting bench and the quest rewards all share.
