Enemy Waves and Spawning

A. Overview​

The Ashen Arena is the survival room of Emberfall. The hero stands in a clearing of the Whispering Forest and fights until the arena is emptied. The waves are not written in the event editor: a document called waves.json describes how many enemies arrive, which types they are, how long the game waits between two of them and where they appear. The game reads that document and turns it into a fight.

DifficultyAdvanced
ComplexityHigh — one configuration document, one runtime state document and a state machine driven by a timer
Fusion skillsFrame events, Active objects, Counters, Timers, global variables, expressions
JSON++ skillsLoading files, absolute paths, reading nested members, writing numbers and strings at runtime, comparing values

Gameplay scenario​

The arena opens with a message that names the first wave. Three marsh slimes crawl in from the eastern gate, two at a time, and the last one arrives late from the western track. When the last slime of the wave dies, the arena announces the second wave and the wolves start coming from the northern road. The third wave brings bandits, and the health of every enemy grows with the wave. The fourth wave is the cavern warden, and after it falls the arena reports that the clearing is safe.

Learning objectives​

By the end of this guide you will be able to:

  • describe a wave, the enemies of a wave and the interval between two of them entirely in a document;
  • give every wave a spawn point and read the coordinates of that point from the same document;
  • keep the progress of the fight in a small state document that the events read and write;
  • raise the difficulty of later waves with a multiplier applied to the values of the enemy database;
  • recognise the end of a wave, the end of the arena and the failure of the survival limit.

What you will build​

A wave configuration file (waves.json), the enemy database of the first guide (enemies.json), a small state document that the fight writes into, and the events that read a wave, spawn its enemies and decide when the arena is cleared.

B. Prerequisites​

Fusion knowledge you need

  • Frame events and the On timer trigger of a Timer object.
  • Active objects and the alterable string that carries the type of an enemy.
  • The Counter object, the actions Set counter to, Add to counter and Subtract from counter, and the expression value("Object").
  • The Create object of the frame, which places a new instance in the world.
  • Reading the alterable of an Active by name, for example EnemyType("Enemy").

JSON++ concepts you need

  • JSON paths: every read uses an absolute path, including the paths that the game builds at runtime.
  • JSON objects and arrays: a wave is an object of the array waves, and a spawn is an object of the array spawns.
  • Building JSON from expressions: the state document is written by the game while the fight runs.
  • Missing, null and empty: an empty array and a missing member are different states.
  • Runtime compatibility: the runtimes differ on how a missing member is reported.

Runtime limitations to keep in mind

  • The configuration document is read once, at the start of the frame. A change in the file is only visible after the frame restarts.
  • The state document lives in the memory of the game. It is not written to disk, and it is lost when the frame ends.
  • The creation of an enemy is the work of the runtime of Fusion. JSON++ Object reads the numbers and writes the state; it never places an object on the screen.

Standard objects used here

JSON++ Object, Active, Counter, Timer, String, Special and Create.

C. Gameplay Scenario​

The arena frame holds a Wave Manager, a Wave Clock, the Enemy object and two counters named Build X and Build Y. The Enemy object is the template of every enemy of the arena. The manager never moves it directly: it writes the type of the next enemy on the template, reads the coordinates of the spawn point into the two counters and lets the Create object of the frame place the new instance.

Two documents carry the data. waves.json is the configuration: it never changes during the fight. The state document is the opposite: it holds nothing but the progress of the fight, and the events of the arena write it on every tick.

The configuration describes four waves. Each wave has a label, a reward, two multipliers and a list of spawns. A spawn names the type of the enemy, how many of them arrive, the interval between two of them, the delay before the first one and the point they appear at.

The three points of the arena are described in the same document, with a name and a pair of coordinates. A spawn refers to a point by its name, so moving a gate is a change of two numbers in the document and nothing else.

The state document holds the wave being played, the number of waves, the index of the current spawn, the enemies still to come, the number of living enemies, the number of waves already cleared and the two multipliers of the current wave. It also holds two paths that the manager builds for itself: the path of the current spawn and the path of the point it refers to. Holding a path as text keeps the captions of the events short.

D. Final Result​

The finished system behaves like this:

  • The arena reads the four waves of waves.json and the definitions of enemies.json when the frame starts.
  • The first wave sends three slimes from the eastern gate and two from the western track, at the intervals written in the document.
  • The second wave is tougher because its multipliers are higher, and the values of the enemies are multiplied when the instance initialises itself.
  • A wave ends when its spawns are finished and no enemy of it is alive.
  • The arena announces the wave that follows and reports Arena cleared after the last one.
  • A spawn point that does not exist in the document stops the wave instead of placing an enemy outside the arena.
  • The survival limit of the arena ends the fight with a message and no reward.

The arena​

The root of the document holds the version, the description of the arena and the array of the waves.

MemberTypeMeaning
arena.idstringThe level the arena belongs to. It is the identifier level_forest of the level guide.
arena.namestringThe name shown in the interface.
arena.duration_secondsnumberThe survival limit, in seconds.
arena.reward_xpnumberThe experience granted when the arena is cleared.
arena.spawn_pointsobjectThe points of the arena, each one with an x and a y coordinate.

A spawn point is a reusable object. The path /arena/spawn_points/east_gate/x always selects the same pair of numbers, and a wave refers to the point by its name instead of repeating coordinates.

The waves​

waves is an array of four objects. Every wave has the same members:

MemberTypeMeaning
idstringThe identifier of the wave. It is stable and it never changes.
labelstringThe name the arena announces.
hp_scalenumberThe multiplier applied to the health of every enemy of the wave.
damage_scalenumberThe multiplier applied to the damage of every enemy of the wave.
reward_xpnumberThe experience granted when the wave is cleared.
spawnsarrayThe spawns of the wave, in the order they happen.

The multipliers are the difficulty curve. They are plain numbers, so a wave with hp_scale 2 gives every enemy twice the health of its definition. The multiplication belongs to the game, not to the document: the document stores the factors and the base values, and the events of the arena combine them.

The spawns​

Each member of the spawns array describes one group of enemies:

MemberTypeMeaning
enemystringThe identifier of the type of enemy. It refers to a definition of the enemy database.
countnumberThe number of enemies of the group.
intervalnumberThe seconds between two enemies of the group.
delaynumberThe seconds before the first enemy of the group appears.
spawn_pointstringThe name of a point of arena.spawn_points.

The order of the spawns is the order of the fight. The manager reads them one after the other, so a designer reorders two lines and the wave changes behaviour.

The enemy database​

The base values of the enemies live in the file of the Data-Driven Enemy Database:

{
  "schema_version": 1,
  "enemies": {
    "slime": {"id": "slime", "name": "Marsh Slime", "hp": 30, "damage": 6, "speed": 40},
    "wolf": {"id": "wolf", "name": "Grey Wolf", "hp": 45, "damage": 9, "speed": 70},
    "bandit": {"id": "bandit", "name": "Forest Bandit", "hp": 60, "damage": 12, "speed": 55},
    "boss_warden": {"id": "boss_warden", "name": "Cavern Warden", "hp": 320, "damage": 20, "speed": 35}
  }
}

The arena reads four values from this file. It never writes to it: the definitions belong to the game, not to one fight.

The state document​

The state document is written by the game while the fight runs:

{
  "state": {
    "wave": 0,
    "total_waves": 4,
    "spawn_index": 0,
    "spawn_path": "/waves/0/spawns/0",
    "point_path": "/arena/spawn_points/east_gate",
    "remaining": 0,
    "next_in": -1,
    "alive": 0,
    "cleared": 0,
    "complete": 0,
    "failed": 0,
    "hp_scale": 1,
    "damage_scale": 1,
    "xp": 0,
    "exhausted": 0
  }
}
MemberTypeMeaning
wavenumberThe index of the wave being played, starting at zero.
total_wavesnumberThe number of waves of the arena.
spawn_indexnumberThe index of the current spawn inside the wave.
spawn_pathstringThe path of the current spawn, built by the manager.
point_pathstringThe path of the spawn point of the current spawn.
remainingnumberThe enemies of the current spawn that have not appeared yet.
next_innumberThe seconds until the next enemy. -1 means the manager has to load the next spawn, 0 means an enemy appears now.
alivenumberThe enemies of the arena that are still alive.
clearednumberThe waves that were cleared.
completenumber1 when the arena was cleared.
failednumber1 when the survival limit was reached.
hp_scalenumberThe multiplier of health of the current wave.
damage_scalenumberThe multiplier of damage of the current wave.
xpnumberThe experience gathered during the fight.
exhaustednumber1 when the wave has no spawn left to hand over.

The two paths are the reason the captions of the events stay short. The manager writes them once per spawn and reads the members of the spawn through them.

Three JSON++ Object instances are used because they hold three different documents. Each instance keeps its own document, its own navigation position and its own search results.

G. Step-by-Step Implementation​

Step 1 — Create the frame and the objects​

  1. Create a frame named Arena.
  2. Add the objects listed in the previous section.
  3. Give the Enemy object an alterable string named EnemyType.
  4. Make the counters Enemy HP and Enemy Damage children of the Enemy object, and add the Enemy Clock as a child too, set to fire once.
  5. Set the Wave Clock to fire every second.

Step 2 — Load the three documents​

Add a Start of Frame event with three actions:

  • Action: Wave Data : Load JSON from file at Apppath$ + "waves.json".
  • Action: Enemy Database : Load JSON from file at Apppath$ + "enemies.json".
  • Action: Arena State : Load JSON from string "{""state"":{""wave"":0,""total_waves"":0,""spawn_index"":0,""spawn_path"":""/waves/0/spawns/0"",""point_path"":""/arena/spawn_points/east_gate"",""remaining"":0,""next_in"":-1,""alive"":0,""cleared"":0,""complete"":0,""failed"":0,""hp_scale"":1,""damage_scale"":1,""xp"":0,""exhausted"":0}}".

The state document is loaded from a string so that every member the events read already exists. A write that has to create a missing branch is refused by the browser runtime, and a document that starts complete never fails that way.

Step 3 — Initialise the state from the configuration​

Add an event with the condition Wave Data: On JSON Loaded:

  • Action: Arena State : Set number GetNumItems( "Wave Data", "/waves" ) at "/state" with key "total_waves".
  • Action: Arena State : Set number 0 at "/state" with key "wave".
  • Action: Arena State : Set number 0 at "/state" with key "spawn_index".
  • Action: Arena State : Set number -1 at "/state" with key "next_in".
  • Action: Arena State : Set string "/waves/0/spawns/0" at "/state" with key "spawn_path".
  • Action: Arena State : Set string "/arena/spawn_points/east_gate" at "/state" with key "point_path".
  • Action: Arena State : Set number GetNumber( "Wave Data", "/waves/0/hp_scale" ) at "/state" with key "hp_scale".
  • Action: Arena State : Set number GetNumber( "Wave Data", "/waves/0/damage_scale" ) at "/state" with key "damage_scale".
  • Action: Status Text : Set alterable string to GetString( "Wave Data", "/waves/0/label" ).

GetNumItems returns the number of waves of the configuration, so the arena never hard-codes how many waves it plays.

Step 4 — Build the path of the current spawn​

The manager rebuilds two paths whenever it changes the spawn or the wave. Add the actions to the tick event of Step 5, inside the branch that loads a spawn:

  • Action: Arena State : Set string "/waves/" + Str$(GetNumber( "Arena State", "/state/wave" )) + "/spawns/" + Str$(GetNumber( "Arena State", "/state/spawn_index" )) at "/state" with key "spawn_path".
  • Action: Arena State : Set string "/arena/spawn_points/" + GetString( "Wave Data", GetString( "Arena State", "/state/spawn_path" ) + "/spawn_point" ) at "/state" with key "point_path".

The paths are absolute and they always begin with /. The second action reads the name of the point out of the spawn and turns it into the path of that point.

Step 5 — The tick of the arena​

Add an event with the condition Wave Clock: On timer. It has three groups.

The first group loads the spawn that comes next:

  • Condition of the group: Arena State : Is "/state/next_in" equal to -1?.
  • Action: Arena State : Set number GetNumber( "Wave Data", GetString( "Arena State", "/state/spawn_path" ) + "/count" ) at "/state" with key "remaining".
  • Action: Arena State : Set number GetNumber( "Wave Data", GetString( "Arena State", "/state/spawn_path" ) + "/delay" ) at "/state" with key "next_in".

The second group spawns one enemy:

  • Condition of the group: Arena State : Is "/state/next_in" equal to 0?.
  • Action: Enemy : Set alterable string to GetString( "Wave Data", GetString( "Arena State", "/state/spawn_path" ) + "/enemy" ).
  • Action: Build X : Set counter to GetNumber( "Wave Data", GetString( "Arena State", "/state/point_path" ) + "/x" ).
  • Action: Build Y : Set counter to GetNumber( "Wave Data", GetString( "Arena State", "/state/point_path" ) + "/y" ).
  • Action: Arena State : Subtract number 1 at "/state" with key "remaining".
  • Action: Arena State : Add number 1 at "/state" with key "alive".
  • Action: Arena State : Set number GetNumber( "Wave Data", GetString( "Arena State", "/state/spawn_path" ) + "/interval" ) at "/state" with key "next_in".

The Create object of the frame places the new instance at the coordinates of the two counters, and the instance inherits the type written on the template. That creation is the work of the runtime of Fusion.

After the subtraction, the manager compares the remaining count with zero. When the count reaches zero, it writes -1 into /state/next_in with the action Arena State : Set number -1 at "/state" with key "next_in" instead of the interval, and the next tick returns to the first group. That comparison is between two values of the game and belongs to Fusion.

The third group closes a wave that has nothing left to spawn:

  • Condition of the group: Arena State : Is "/state/exhausted" equal to 1?.
  • Condition of the nested group: Arena State : Is "/state/alive" equal to 0?.
  • Action: Arena State : Add number 1 at "/state" with key "cleared".
  • Action: Arena State : Add number 1 at "/state" with key "wave".
  • Action: Arena State : Set number 0 at "/state" with key "spawn_index".
  • Action: Arena State : Set number 0 at "/state" with key "exhausted".
  • Action: Arena State : Set number -1 at "/state" with key "next_in".
  • Action: Arena State : Set number GetNumber( "Wave Data", "/waves/" + Str$(GetNumber( "Arena State", "/state/wave" )) + "/hp_scale" ) at "/state" with key "hp_scale".
  • Action: Arena State : Set number GetNumber( "Wave Data", "/waves/" + Str$(GetNumber( "Arena State", "/state/wave" )) + "/damage_scale" ) at "/state" with key "damage_scale".
  • Action: Status Text : Set alterable string to GetString( "Wave Data", "/waves/" + Str$(GetNumber( "Arena State", "/state/wave" )) + "/label" ).

The group is entered when the spawn index has gone past the last spawn of the wave and no enemy of it is alive. The manager writes the flag exhausted when it advances the spawn index past the end of the list, and it clears the flag when a new wave starts.

Step 6 — Announce the end of the arena​

Add an event with the condition Wave Clock: On timer and one group:

  • Condition of the group: Arena State : Is "/state/complete" equal to 1?.
  • Action: Status Text : Set alterable string to "Arena cleared".
  • Action: Arena State : Add number GetNumber( "Wave Data", "/arena/reward_xp" ) at "/state" with key "xp".

The manager writes 1 into /state/complete when the number of cleared waves reaches the number of waves of the configuration. That comparison is a comparison between two values of the game.

Step 7 — Apply the survival limit​

Add an event with the condition Wave Clock: On timer and one group:

  • Condition of the group: Arena State : Is "/state/failed" equal to 1?.
  • Action: Status Text : Set alterable string to "The clearing was lost".

The arena counts the seconds it has been running and compares them with /arena/duration_seconds. When the limit is reached, the manager writes 1 into /state/failed and the fight ends without the reward.

Step 8 — Initialise a new enemy with the scale of the wave​

Add an event with the condition Enemy Clock: On timer:

  • Action: Enemy HP : Set counter to GetNumber( "Enemy Database", "/enemies/" + EnemyType("Enemy") + "/hp" ) * GetNumber( "Arena State", "/state/hp_scale" ).
  • Action: Enemy Damage : Set counter to GetNumber( "Enemy Database", "/enemies/" + EnemyType("Enemy") + "/damage" ) * GetNumber( "Arena State", "/state/damage_scale" ).

The base values come from the enemy database and the multipliers come from the state of the current wave. The multiplication is the work of the events: the documents only hold the factors.

Step 9 — Count a dead enemy​

Add an event with the condition Enemy Clock: On timer. It runs when the health of the enemy has reached zero, which the game checks with a comparison between the counter of the enemy and zero:

  • Action: Arena State : Subtract number 1 at "/state" with key "alive".
  • Action: Arena State : Add number value("Enemy XP") at "/state" with key "xp".
  • Action: Enemy : Destroy.

Step 10 — Handle a failed load​

Add one event for each JSON++ Object that reads a file:

  • Condition: Wave Data: On Error.
  • Action: Status Text : Set alterable string to GetError( "Wave Data" ).

The same pair of actions belongs to the enemy database. A missing configuration file leaves the arena empty and the status line explains why.

I. Expected Behavior​

Before the first wave​

The state document holds the counters of a fight that has not started:

{
  "state": {
    "wave": 0,
    "total_waves": 4,
    "spawn_index": 0,
    "spawn_path": "/waves/0/spawns/0",
    "point_path": "/arena/spawn_points/east_gate",
    "remaining": 0,
    "next_in": -1,
    "alive": 0,
    "cleared": 0,
    "complete": 0,
    "failed": 0,
    "hp_scale": 1,
    "damage_scale": 1,
    "xp": 0,
    "exhausted": 0
  }
}

The status line reads First contact. Nothing has appeared in the arena yet.

After the first wave is cleared​

The state document records the progress of the fight:

{
  "state": {
    "wave": 1,
    "total_waves": 4,
    "spawn_index": 0,
    "spawn_path": "/waves/1/spawns/0",
    "point_path": "/arena/spawn_points/north_road",
    "remaining": 0,
    "next_in": -1,
    "alive": 0,
    "cleared": 1,
    "complete": 0,
    "failed": 0,
    "hp_scale": 1,
    "damage_scale": 2,
    "xp": 55,
    "exhausted": 0
  }
}

The wave moved from zero to one, the number of cleared waves is one, the damage multiplier of the second wave is in place and the experience of the five dead slimes is stored. The status line reads Pack of wolves.

The configuration document is untouched by the fight. Only the state document changes while the arena runs.

J. Edge Cases & Error Handling​

SituationWhat happensHandling
waves.json does not existThe load fails and On Error runsShow the message and return to the menu. Ship the file with the game.
waves.json contains invalid JSONThe document is not replaced and the error text describes the problemKeep the technical text for a log and show a short message to the player.
The configuration has no waves arrayGetNumItems returns a fallback and no wave is playedCheck /waves with the exists condition before the fight starts.
A spawn names a point that does not existThe path of the point selects nothing and the coordinates read as a fallbackGive every spawn the name of a point of arena.spawn_points, and check the point with the exists condition before the first spawn of the wave.
A spawn names an enemy the database does not knowThe instance initialises with fallback values and dies at onceKeep the two documents in step, and let the enemy check its own definition with the exists condition.
A wave has no spawnsThe manager treats it as finished and moves to the next oneReject an empty wave when the file is written, or give every wave at least one spawn.
The interval of a spawn is zeroTwo enemies appear on the same tickKeep the interval at one second or more, or accept that the wave empties in a single tick.
The tick is late on a slow deviceThe enemies arrive later than the configuration asksThe tick drives the fight, so a late tick delays the wave instead of skipping it.
The player dies during a waveThe fight stops with enemies still aliveDestroy the remaining instances and write 1 into /state/failed.
The survival limit is reachedThe manager writes 1 into /state/failed and the fight endsCompare the elapsed seconds with /arena/duration_seconds before the tick acts.
A wave is cleared twiceThe counter of cleared waves grows twiceThe group that closes a wave requires the flag exhausted, and the flag is cleared as the wave advances.
A path of the state document holds a stale valueA read returns a fallbackRebuild spawn_path and point_path whenever the spawn index or the wave changes.
The game runs on HTML5Apppath$ has no meaningUse a browser reference such as storage://waves and read the platform-specific file guide.

Two rules deserve emphasis. First, the configuration and the state belong to two different documents: a mistake in the state never damages the configuration. Second, the manager must not advance a wave while an enemy of it is still alive, or the wave counter and the number of living enemies stop describing the same fight.

One difference touches the conditions. The native runtime recognizes a member whose value is null when the exists condition asks whether a path is there, while the browser runtime reports such a member as absent. The state document never stores null, so both targets answer the same way. The full matrix is on the runtime compatibility page.

M. Next Steps​

  • Keep the queue in the document. The manager can write the spawns of a wave into the state document as a list and process them one by one, which removes the index arithmetic from the events.
  • Announce the wave with a timer. A Timer that fades the label of the wave in and out gives the arena a voice without touching the configuration.
  • Store the arena best time. The state document already holds the experience of the fight; add the seconds it lasted and write them with the save system of the game.
  • Let the configuration choose the enemies. A spawn can name a category instead of a type, and the manager picks a type of that category with the random expression of Fusion.
  • Protect the configuration. Validate the file against a JSON schema when it is loaded, so a missing hp_scale is reported instead of silently becoming zero. See Enable JSON Schema Validation.
