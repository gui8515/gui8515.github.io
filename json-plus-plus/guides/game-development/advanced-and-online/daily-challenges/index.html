Daily Challenges

A. Overview​

Emberfall offers one challenge a day. The challenge of the day asks the player to defeat five slimes before the day ends, and it pays a reward that is granted once. When the next day arrives, a new challenge appears and the progress of the old one is discarded.

DifficultyAdvanced
ComplexityHigh — two documents, a period check, a counter that follows the objective and a reward that is paid once
Fusion skillsFrame events, Active objects, Counter and String objects, global variables, timers
JSON++ skillsSearching for a value, reading a member with the path of a result, writing counters, comparing numbers

Gameplay scenario​

The player opens the menu of Emberfall and sees Slime cull — defeat 5 slimes — 150 gold. The player has already defeated two slimes today, so the counter reads 2 of 5. When the fifth slime falls, the challenge is complete and the player claims the reward. The button of the challenge then reads Claimed, and it stays that way for the rest of the day.

Learning objectives​

By the end of this guide you will be able to:

  • keep the definition of a challenge apart from the progress of the player;
  • find the challenge that matches an event of the game with a search, and read its identifier from the path of the result;
  • count the progress of an objective in the document;
  • pay a reward only once, with a flag;
  • reset the progress when the period changes, and say plainly what the clock of the game can and cannot prove.

What you will build​

A document with the definition of the challenges of the day, a document with the progress of the player, the event that counts an objective, the event that completes the challenge, the event that pays the reward and the event that starts a new period.

B. Prerequisites​

Fusion knowledge you need

  • Frame events and the condition Start of Frame.
  • The Counter object and the actions Set counter and Add to counter.
  • The Active object and the conditions is clicked and is visible.
  • The String object and the action Set alterable string.
  • Global variables on the Special object.

JSON++ concepts you need

  • Search Results and Their Lifetime: the search finds the challenge, and the path of the result says which one it is.
  • JSON paths, because the path of a result is what turns a match into an address.
  • JSON instance state: the definitions and the progress live in two different objects.
  • Missing, null and empty: a challenge without a recorded progress has no entry yet.

Runtime limitations to keep in mind

  • The extension does not know what time it is and does not decide when a day ends. The date comes from the game, and the game gets it from the system or from a service.
  • A clock inside the device belongs to the player. It can be moved backwards, and it can be set to a date that does not exist. A local challenge is a convenience for the players of a single device, not a protection.
  • A challenge decided by a server is a different system: the server holds the progress, it decides the period and it refuses a score that does not make sense. The extension takes no part in it.

Standard objects used here

String, Counter, Special, Timer, Active, JSON++ Object.

C. Gameplay Scenario​

The challenges of the day come from a definition document. The progress of the player comes from another document, and the second one is the only one that is written to disk.

The separation matters. The definition changes when the studio publishes a new day, and it changes on every device at the same time. The progress belongs to the player, and it belongs to the slot that is being played.

A challenge names an objective, and the objective names a target: five enemies of the type slime. When a slime falls, the game searches the definitions for the challenge whose target is slime, takes the identifier of the challenge from the path of the result and adds one to the progress of that identifier in the progress document.

The reward is paid once. The flag that says the reward was claimed is written in the progress document, and the claim event checks it before it pays.

The period is a date in the format year-month-day. When the period of the definitions differs from the period of the progress, the progress is cleared and the new period is written.

D. Final Result​

The finished system behaves like this:

  • The menu shows the challenge of the day, its objective and the progress of the player.
  • Defeating an enemy of the type the challenge asks for advances the counter.
  • The reward is paid once, and the button reads Claimed afterwards.
  • The challenge of the next day starts with a progress of zero.
  • A device with a wrong clock shows a challenge of the wrong day, and the game says so.

E. JSON Data Structure​

The definitions of the challenges​

{
  "schema_version": 1,
  "period": "2026-02-14",
  "challenges": [
    {
      "id": "challenge_slimes",
      "title": "Slime cull",
      "objective": {"type": "defeat", "target": "slime", "count": 5},
      "reward": {"gold": 150, "xp": 100}
    },
    {
      "id": "challenge_herbs",
      "title": "Gathering",
      "objective": {"type": "collect", "target": "herb_lotus", "count": 3},
      "reward": {"gold": 80, "xp": 60}
    }
  ]
}

The root holds the version, the period and the challenges.

period is a date in the format year-month-day. It is the period of the definitions, not a timestamp: the challenges of a day share it.

challenges is an array of objects, each one with four members:

MemberTypeMeaning
idstringThe identifier of the challenge, such as challenge_slimes.
titlestringThe name shown in the menu. The name of the language belongs to the dictionary of the localization guide.
objectiveobjectThe goal: the type of the goal, the target it applies to and the count it takes.
rewardobjectThe gold and the xp paid when the challenge is completed.

The target of the objective holds the same identifier the game uses for the entity: slime is the type of the enemy, herb_lotus is the item. That is what lets one search find the challenge that an event of the game refers to.

The progress of the player​

{
  "schema_version": 1,
  "period": "2026-02-14",
  "challenges": {
    "challenge_slimes": {"progress": 2, "claimed": 0},
    "challenge_herbs": {"progress": 0, "claimed": 0}
  }
}

The root holds the version, the period that this progress belongs to, and the progress of each challenge.

challenges is an object whose members are the challenges, named by their identifier. Each member holds two numbers: progress, the count of the objective, and claimed, the flag that says the reward was already paid.

The period of the progress is the copy that the game compares with the period of the definitions. A difference means a new day.

G. Step-by-Step Implementation​

Step 1 — Create the objects​

  1. Add the objects listed above to the frame of the menu and to the frame of the game.
  2. Create the global variables Challenge Id, Challenge Target and Daily Date on the Special object.
  3. Place the Claim Button invisible in the frame editor.

Step 2 — Load the two documents​

Add a Start of Frame event:

  • Condition: Start of Frame.
  • Action: Challenge Definitions : Load JSON from file at Apppath$ + "challenges.json".
  • Action: Challenge Progress : Load JSON from file at Apppath$ + "challenge_progress.json".

The definitions may also come from the remote resource, as the remote configuration guide shows.

Step 3 — Compare the periods​

Add an event with the condition Challenge Definitions: On JSON Loaded:

  • Action: Special : Set Daily Date to GetString( "Challenge Definitions", "/period" ).

And an event with the condition Challenge Progress: On JSON Loaded:

  • Action: Special : Set Stored Date to GetString( "Challenge Progress", "/period" ).

Step 4 — Start a new day​

Add an event with the condition Challenge Progress: On JSON Loaded:

  • Condition of the group: Challenge Progress: Is "/period" equal to Daily Date?.
  • Action: Challenge Progress : Set number 0 at "/challenges/challenge_slimes" with key "progress".
  • Action: Challenge Progress : Set number 0 at "/challenges/challenge_slimes" with key "claimed".

When the two dates are the same, the group does nothing and the progress of the player is preserved. When they differ, the game clears the progress of every challenge and writes the new period:

  • Action: Challenge Progress : Set string Daily Date at "/" with key "period".

The group is written per challenge in a game with many challenges. A loop over /challenges clears them all with the same rule.

Step 5 — Count an objective​

Add an event with the condition Slime is destroyed:

  • Action: Special : Set Challenge Target to "slime".
  • Action: Challenge Definitions : Search for value Challenge Target at "/challenges" (Exact: 1).

The search compares the values of the document with the identifier of the enemy that was defeated. The target member of the objective holds that identifier, so a known target produces a match.

Step 6 — Add one to the progress of the matched challenge​

Add an event with the condition Challenge Definitions: On Results Found:

  • Action: Special : Set Challenge Id to GetString( "Challenge Definitions", GetResultPath( "Challenge Definitions", 0 ) + "/id" ).
  • Action: Challenge Progress : Add number 1 at "/challenges/" + Challenge Id with key "progress".

The path of the result says which challenge matched, and the identifier read from that path says where the progress lives. The write adds one to the counter of that challenge and leaves the others alone.

Step 7 — Show the progress​

Add an event with the condition Challenge Progress: On JSON Loaded:

  • Action: Challenge Title Label : Set alterable string to GetString( "Challenge Definitions", "/challenges/0/title" ).
  • Action: Progress Label : Set alterable string to Str$(GetNumber( "Challenge Progress", "/challenges/challenge_slimes/progress" )) + " / " + Str$(GetNumber( "Challenge Definitions", "/challenges/0/objective/count" )).

The label shows the count of the objective and the count it takes, read from the two documents.

Step 8 — Complete the challenge​

Add an event with the condition Challenge Progress: On JSON Loaded:

  • Condition of the group: Challenge Progress: Is "/challenges/challenge_slimes/progress" equal to GetNumber( "Challenge Definitions", "/challenges/0/objective/count" )?.
  • Action: Claim Button : Set visible.

The comparison asks whether the progress reached the count the definition asks for. When it did, the button appears.

Step 9 — Pay the reward once​

Add an event with the condition Claim Button is clicked:

  • Condition of the group: Challenge Progress: Is "/challenges/challenge_slimes/claimed" equal to 0?.
  • Action: Gold Counter : Add to counter GetNumber( "Challenge Definitions", "/challenges/0/reward/gold" ).
  • Action: XP Counter : Add to counter GetNumber( "Challenge Definitions", "/challenges/0/reward/xp" ).
  • Action: Challenge Progress : Set number 1 at "/challenges/challenge_slimes" with key "claimed".
  • Action: Claim Button : Set invisible.

The flag is written in the same group that pays the reward, so a second click finds a flag of 1 and the group does not run.

Step 10 — Store the progress​

Add an event with the condition Save Game is clicked:

  • Action: Challenge Progress : Save JSON to file at Apppath$ + "challenge_progress.json".

I. Expected Behavior​

At the start of the day​

The definitions carry the new day and the progress still carries the old one:

{
  "schema_version": 1,
  "period": "2026-02-15",
  "challenges": [
    {"id": "challenge_slimes", "title": "Slime cull", "objective": {"type": "defeat", "target": "slime", "count": 5}, "reward": {"gold": 150, "xp": 100}}
  ]
}
{
  "schema_version": 1,
  "period": "2026-02-14",
  "challenges": {
    "challenge_slimes": {"progress": 3, "claimed": 0}
  }
}

The dates differ, so the game clears the progress, writes the new period and shows 0 / 5.

During the day​

{
  "schema_version": 1,
  "period": "2026-02-15",
  "challenges": {
    "challenge_slimes": {"progress": 2, "claimed": 0}
  }
}

The label reads 2 / 5. The progress of the previous day is gone.

After the reward was claimed​

{
  "schema_version": 1,
  "period": "2026-02-15",
  "challenges": {
    "challenge_slimes": {"progress": 5, "claimed": 1}
  }
}

The button is invisible, the gold was added once, and a second click on the button does nothing.

J. Edge Cases & Error Handling​

SituationWhat happensHandling
The definitions are missingThe load fails and On Error runsShip the file with the game and keep the local challenge as the fallback.
The progress file is missingThe load fails and the progress starts emptyWrite a progress document with the period of the day when the game starts without one.
The definitions hold a challenge the build does not knowThe document is loaded and the challenge is ignoredThe game reads the members it knows.
A challenge has no entry in the progressThe path selects nothing and the write creates itThe write of Step 6 creates the member, so the first defeat is never lost.
The target of the objective does not exist in the gameThe search finds nothing and nothing is countedGive the targets of the definitions the same identifiers as the entities of the game.
The player defeats the wrong enemyThe search finds no challenge and the progress does not moveThe target of the objective decides what counts.
The reward is claimed twiceThe flag of the claim refuses the second paymentWrite the flag in the same group that pays the reward.
The period of the progress is emptyThe dates differ and the game starts a new dayThe progress of the first run is empty, which is the expected behaviour.
The clock of the device is wrongThe game shows the challenge of the wrong daySay plainly that the challenge follows the clock of the device.
The player moves the clock back to repeat a challengeThe period matches the old progress and the challenge can be repeatedA local challenge does not protect against this. A server that decides the period does.
The player changes the date of the device forwardThe game skips a day and clears the progressThe same limitation applies, and the loss is the progress of the skipped day.
The game runs on HTML5Apppath$ has no meaningUse a browser reference such as storage://challenge_progress and read the platform-specific file guide.

M. Next Steps​

  • Publish the definitions remotely. The definitions of the day change for every player at once, which is what the remote configuration guide does.
  • Show the time that is left. A member with the end of the period lets the menu show how long the challenge lasts.
  • Add a streak. A counter of the days completed in a row is another number in the progress document.
  • Let the player choose between two challenges. The definitions hold an array, and the menu presents the first that the player did not complete.
  • Move the decision to a server. A server that holds the progress and decides the period removes the limitation of the clock of the device. The extension would read the answer of that server, as the leaderboard guide shows.
