Custom Content and Modding

A. Overview​

Emberfall accepts content that the players write themselves. A player puts a JSON file in the folder of the mod, declares an item, an enemy or a level, and the game reads it, checks it and uses the parts it understands.

DifficultyAdvanced
ComplexityHigh — one document of content, a validation pass, a copy into the database of the game and a report
Fusion skillsFrame events, Active objects, String and Counter objects, global variables, loops
JSON++ skillsLoading an external file, looping over an array, reading members with a computed path, writing into another document

Gameplay scenario​

A player writes a file called mods/flame_sword.json with a sword of their own. The game reads it when the mod folder is opened, finds an item with the identifier custom_fire_sword, checks that the damage is a number the game accepts and adds the item to the database of the game. The sword can then be found, bought and equipped like any other. A second file that declares a damage of minus fifty is refused, and the report says why.

Learning objectives​

By the end of this guide you will be able to:

  • read a document that a player wrote and check it before the game trusts it;
  • validate the version of the content and the version of the game it asks for;
  • copy the definitions that the game understands into its own documents;
  • refuse the values the game cannot use and explain the refusal;
  • describe the limits of the platforms honestly, without promising a file system the player does not have.

What you will build​

A content file written by a player, the events that load it, a validation pass over its items and its enemies, the copy of the accepted definitions into the database of the game, a report that lists what was accepted and what was refused, and the event that removes the custom content again.

B. Prerequisites​

Fusion knowledge you need

  • Frame events and the condition Start of Frame.
  • The loop of the game, with the conditions that report the items and the end of the loop.
  • The Active object and the condition is clicked.
  • The String object and the action Set alterable string.
  • Global variables on the Special object.

JSON++ concepts you need

  • Understanding JSON Loops and Reading Loop Values.
  • JSON paths, because the path of the current item is what addresses a definition.
  • Missing, null and Empty: a definition that lost a member is refused.
  • JSON instance state: the content of the player and the database of the game live in two different objects.

Runtime limitations to keep in mind

  • The game reaches the file through a reference that the target supports. On Windows and on the mobile targets it is a path inside the folder of the application or inside the sandbox of the application. On the browser runtime the player chooses the file with a picker, or the file is read from the origin storage. No target gives a game the whole file system of the device.
  • A content file declares numbers and names. It never runs code, and the game never treats a member of the file as an instruction.
  • The browser runtime refuses two file operations at the same time, so a folder of mods is read one file at a time.
  • The extension does not check the content for the player. Every check in this guide is an event of the game.

Standard objects used here

String, Counter, Special, Timer, Active, JSON++ Object.

C. Gameplay Scenario​

A content file has three sections: items, enemies and levels. Every section is an array of objects, and every object names itself with an identifier that the game has never seen.

The game does not trust the file. It reads the version of the structure, compares it with the version the build understands, and compares the version of the game that the content asks for with the version of the build. A file that asks for a newer game is refused before anything is read from it.

Then the game walks the items. For each one it checks that the identifier, the name and the type are present, that the type is one the game knows, and that the numbers are inside the range the game accepts. A definition that passes is copied into the database of the game. A definition that fails is written in the report, with the reason.

The copy is done member by member, because the content lives in another document. The game reads the name of the custom item and writes it in the database, then the damage, then the value. The extension provides the read and the write; the game decides what to copy.

D. Final Result​

The finished system behaves like this:

  • A file that the player wrote is read when the mod folder is opened.
  • The definitions that the game understands are available in the game, next to the ones that ship with it.
  • A definition with a missing member, an unknown type or a value outside the accepted range is refused, and the report says why.
  • A file that asks for a newer version of the game changes nothing.
  • Removing the mods removes the custom content from the game, and the items that ship with it stay.

E. JSON Data Structure​

A content file written by a player​

{
  "schema_version": 1,
  "content_version": "1.0.0",
  "requires_game_version": "1.2.0",
  "author": "player_one",
  "items": [
    {
      "id": "custom_fire_sword",
      "name": "Flame Sword",
      "type": "weapon",
      "stack": 1,
      "damage": 24,
      "value": 120,
      "icon": "custom_fire_sword.png"
    },
    {
      "id": "custom_ember_potion",
      "name": "Ember Potion",
      "type": "potion",
      "stack": 10,
      "heal": 35,
      "value": 60,
      "icon": "custom_ember_potion.png"
    }
  ],
  "enemies": [
    {
      "id": "custom_bone_golem",
      "name": "Bone Golem",
      "category": "undead",
      "hp": 120,
      "damage": 18,
      "speed": 45,
      "xp_reward": 90,
      "attack_range": 30,
      "loot_table": "bandit"
    }
  ],
  "levels": []
}

The root object holds seven members:

MemberTypeMeaning
schema_versionnumberThe version of the structure of the file. The build accepts the versions it was written for.
content_versionstringThe version of the content itself, chosen by the author.
requires_game_versionstringThe oldest version of the game that understands this content.
authorstringThe name of the author, shown in the list of the mods.
itemsarray of objectsThe custom items.
enemiesarray of objectsThe custom enemies.
levelsarray of objectsThe custom levels, in the structure of the level loader guide.

Each custom item holds:

MemberTypeMeaning
idstringThe identifier of the item. The game uses it as the key of the item in the database.
namestringThe name shown in the game.
typestringThe kind of item, with the values the catalog of the game uses: weapon, armor, potion, food, material and key.
stacknumberThe number of units that share one slot. A weapon has a stack of 1.
damagenumberThe damage of a weapon. The game refuses a value below 0 or above 999.
healnumberThe life restored by a potion.
valuenumberThe price of the item in the shop.
iconstringThe name of the image of the item. The game looks for it in the folder of the mod.

The members name, type, stack and value are the members of the catalog of the game, so an item that is copied with those four members is read exactly like a built-in one. The members damage and heal carry the effect of the item, and they travel with the mod file because a mod is a single document.

Each custom enemy holds the id, the name, the category, the hp, the damage, the speed, the xp_reward, the attack_range and the loot_table. The member names are the ones of the enemy database of the game, so a custom enemy is read with the same path as a built-in one, and the ranges are the same. The category names one of the families of /categories, and the loot_table names one of the tables of the loot document.

An empty section is valid. The file of a mod that only adds an item may leave enemies and levels empty.

G. Step-by-Step Implementation​

Step 1 — Create the objects​

  1. Add the objects listed above to the frame of the mods.
  2. Create the global variables Item Id, Item Type and Mod File on the Special object.

Step 2 — Load the content of a mod​

Add an event with the condition Mod List is clicked:

  • Action: Special : Set Mod File to ModFile("Mod List").
  • Action: Custom Content : Load JSON from file at Apppath$ + "mods/" + Mod File.

The name of the file comes from the row that was clicked. The path is built at runtime, so one event reads every file of the folder.

Step 3 — Check the version of the structure​

Add an event with the condition Custom Content: On JSON Loaded:

  • Condition of the group: Custom Content: Is "/schema_version" equal to 1?.
  • Action: Special : Set Content Valid to 1.

A file whose structure the build does not know is not read any further. The rest of the events of this guide run inside a group that checks this flag.

Step 4 — Check the version of the game​

Add a second group under the same event:

  • Condition of the group: Custom Content: Is "/requires_game_version" equal to Game Version?.
  • Action: Special : Set Content Valid to 1.

Both groups write the same flag, and the flag starts at zero. A file that passes one check and fails the other leaves the flag at zero, and the content is refused.

Step 5 — Walk the custom items​

Add an event with the condition Custom Content: On JSON Loaded:

  • Condition of the group: Content Valid = 1.
  • Action: Custom Content : Start loop "Items" at "/items".

And an event with the condition Custom Content: On Loop "Items":

  • Action: Special : Set Item Id to GetString( "Custom Content", GetLoopPath( "Custom Content", "Items" ) + "/id" ).
  • Action: Special : Set Item Type to GetString( "Custom Content", GetLoopPath( "Custom Content", "Items" ) + "/type" ).

The identifier of the item is read from the item itself, because the position of an item in the array is not a name.

Step 6 — Refuse an item the game does not understand​

Add a group under the loop event:

  • Condition of the group: Custom Content: Is GetLoopPath( "Custom Content", "Items" ) + "/type" equal to "weapon"?.
  • Action: Report Text : Set alterable string to "Accepted: " + Item Id.

Add a second group for the other accepted types, and a third one that refuses everything else. The accepted types are the ones of the catalog of the game: weapon, armor, potion, food, material and key:

  • Condition of the group: Custom Content: Is GetLoopPath( "Custom Content", "Items" ) + "/type" equal to "armor"?.
  • Action: Report Text : Set alterable string to "Accepted: " + Item Id.

Step 7 — Check that the member is there, and check the numbers​

Add a group under the loop event:

  • Condition of the group: Custom Content: GetLoopPath( "Custom Content", "Items" ) + "/damage" exists.
  • Action: Report Text : Set alterable string to "Refused: " + Item Id + " has no damage member".

A missing member is not a zero. GetNumber reports the error and returns -1 when the path is absent, so a copy without this check would write a negative value in the catalog. The exists condition asks the question before the value is read.

Then add the check of the value itself:

  • Condition of the group: Custom Content: Is GetLoopPath( "Custom Content", "Items" ) + "/damage" equal to 0?.
  • Action: Report Text : Set alterable string to "Refused: " + Item Id + " has no damage".

A weapon with a damage of zero is refused, and so is a weapon with a damage of minus fifty: the second case needs a comparison of the value with the minimum, which the game performs with the values of the two counters.

Step 8 — Copy the accepted item into the database​

Add a group under the loop event:

  • Condition of the group: Custom Content: Is GetLoopPath( "Custom Content", "Items" ) + "/type" equal to "weapon"?.
  • Action: Item Database : Set string GetString( "Custom Content", GetLoopPath( "Custom Content", "Items" ) + "/name" ) at "/items/" + Item Id with key "name".
  • Action: Item Database : Set string GetString( "Custom Content", GetLoopPath( "Custom Content", "Items" ) + "/type" ) at "/items/" + Item Id with key "type".
  • Action: Item Database : Set number GetNumber( "Custom Content", GetLoopPath( "Custom Content", "Items" ) + "/stack" ) at "/items/" + Item Id with key "stack".
  • Action: Item Database : Set number GetNumber( "Custom Content", GetLoopPath( "Custom Content", "Items" ) + "/value" ) at "/items/" + Item Id with key "value".
  • Action: Item Database : Set number GetNumber( "Custom Content", GetLoopPath( "Custom Content", "Items" ) + "/damage" ) at "/items/" + Item Id with key "damage".

The identifier of the item is the key of the member in the catalog, and the custom item goes into the same member as the built-in ones, so the shop, the inventory and the equipment read a custom item exactly like a built-in one. A potion carries the member heal instead of damage, and it is copied with the same pattern.

Step 9 — Check the asset​

The item names an image. The check of that image belongs to the game: the File object of Fusion reports whether the file exists, and the game writes the answer in the report.

  • Action: Report Text : Set alterable string to "Accepted: " + Item Id + " (image missing)".

The extension does not read images and does not know whether a file exists. It reads and writes the document that names the image.

Step 10 — Apply the custom enemies​

Add a second event with the condition Custom Content: On Loop "Enemies", and read the identifier of the enemy into a global before the copy:

  • Action: Special : Set Enemy Id to GetString( "Custom Content", GetLoopPath( "Custom Content", "Enemies" ) + "/id" ).
  • Action: Enemy Database : Set string GetString( "Custom Content", GetLoopPath( "Custom Content", "Enemies" ) + "/name" ) at "/enemies/" + Enemy Id with key "name".
  • Action: Enemy Database : Set string GetString( "Custom Content", GetLoopPath( "Custom Content", "Enemies" ) + "/category" ) at "/enemies/" + Enemy Id with key "category".
  • Action: Enemy Database : Set number GetNumber( "Custom Content", GetLoopPath( "Custom Content", "Enemies" ) + "/hp" ) at "/enemies/" + Enemy Id with key "hp".
  • Action: Enemy Database : Set number GetNumber( "Custom Content", GetLoopPath( "Custom Content", "Enemies" ) + "/damage" ) at "/enemies/" + Enemy Id with key "damage".
  • Action: Enemy Database : Set string GetString( "Custom Content", GetLoopPath( "Custom Content", "Enemies" ) + "/loot_table" ) at "/enemies/" + Enemy Id with key "loot_table".

The custom enemy goes into the same member as the built-in ones, so the enemy database reads it with the same path. The enemy that the game spawns reads /enemies/ + the identifier of its type, and it does not matter whether that identifier belongs to the game or to a player.

Step 11 — Refuse an enemy without a health​

The enemies need the same existence check as the items:

  • Condition of the group: Custom Content: GetLoopPath( "Custom Content", "Enemies" ) + "/hp" exists.
  • Action: Report Text : Set alterable string to "Refused: " + Enemy Id + " has no hp member".

Without this group, a mod that forgets the health would put -1 in the enemy database, and an enemy with a negative health never dies.

Step 12 — Remove the custom content​

Add an event with the condition Remove Mods is clicked:

  • Action: Item Database : Delete item at "/items/custom_fire_sword".
  • Action: Enemy Database : Delete item at "/enemies/custom_bone_golem".
  • Action: Status Text : Set alterable string to "Custom content removed".

The identifiers are the ones of the mod file, so the game removes exactly the content that the player installed. The items that ship with the game have other identifiers, and they are untouched. A mod with several items needs one action per identifier.

I. Expected Behavior​

The content of the player​

{
  "schema_version": 1,
  "content_version": "1.0.0",
  "requires_game_version": "1.2.0",
  "author": "player_one",
  "items": [
    {"id": "custom_fire_sword", "name": "Flame Sword", "type": "weapon", "stack": 1, "damage": 24, "value": 120, "icon": "custom_fire_sword.png"}
  ],
  "enemies": []
}

The catalog of the game after the copy​

{
  "items": {
    "potion_health": {"name": "Health Potion", "type": "potion", "stack": 10, "value": 25},
    "custom_fire_sword": {"name": "Flame Sword", "type": "weapon", "stack": 1, "damage": 24, "value": 120}
  }
}

The custom item sits next to the built-in ones, in the same member, and the shop and the inventory read both with the same kind of path.

The enemy database after the copy​

{
  "enemies": {
    "slime": {"id": "slime", "name": "Marsh Slime", "category": "beast", "hp": 30, "damage": 6, "speed": 40, "xp_reward": 12, "attack_range": 24, "loot_table": "slime"},
    "custom_bone_golem": {"id": "custom_bone_golem", "name": "Bone Golem", "category": "undead", "hp": 120, "damage": 18, "speed": 45, "xp_reward": 90, "attack_range": 30, "loot_table": "bandit"}
  }
}

The custom enemy is a definition like the others. The enemy that the game spawns reads /enemies/ + the identifier of its type, so a type that a player wrote is read with the same path as a type that ships with the game.

After the player removes the mods​

{
  "items": {
    "potion_health": {"name": "Health Potion", "type": "potion", "stack": 10, "value": 25}
  }
}

The member of the custom content is gone and the built-in items are untouched.

J. Edge Cases & Error Handling​

SituationWhat happensHandling
The file does not existThe load fails and On Error runsReport the missing file and continue with the content that is already loaded.
The file is not JSONThe document is not replacedReport the failure and keep the built-in content.
The file has the wrong schema_versionThe flag of the validity stays at zeroRefuse the content and say which version the build understands.
The file asks for a newer gameThe flag of the validity stays at zeroRefuse the content and say the version of the build.
An item has no identifierThe path selects nothing and the identifier is emptyRefuse the item and report it.
A member of the file is missingThe number reads -1, the fallback of the extension, and the error state of the object is setCheck the member with the exists condition before the copy, as Steps 7 and 11 do.
A member of the file has the wrong typeThe number reads -1 and the text reads emptyCheck the type of the member before the copy, and refuse the content that does not match the schema of the game.
Two items share an identifierThe second one replaces the firstRefuse the duplicate and report both identifiers.
An item has an unknown typeThe type is not one the game acceptsRefuse the item and report the type.
A number is outside the accepted rangeThe value would break the balanceRefuse the item and report the value.
The image of the item is missingThe game finds no picture for the itemThe check belongs to the game, with the File object. Report the item as incomplete.
The file declares a level the game does not understandThe level is ignoredThe level uses the structure of the level loader guide.
The content is loaded twiceThe members are written again with the same valuesThe copy is idempotent, because the key of the member is the identifier.
The file is edited while the game reads itThe document of the runtime is the one that was parsedThe game reads the file again for the next mod.
The game runs on the browser runtimeThe game does not reach the file system of the deviceThe player chooses the file with a picker reference, or the file comes from the origin storage.
The game runs on a mobile targetThe file must be inside the sandbox of the applicationOffer a way to import the file into the sandbox, or read it from the origin storage.

The system reads a file that the player wrote and writes the values into the documents of the game.

TargetFile workValue changesNotes

AndroidImplemented, not verified by an automated checkImplemented, not verified by an automated checkThe file must be inside the sandbox of the application.
HTML5Implemented and testedImplemented and testedThe player chooses the file with a picker, or the file comes from the origin storage. A concurrent file operation is refused.

M. Next Steps​

  • Validate the file against a schema. The extension can validate a document against a JSON schema, which rejects a file with a missing member before the game reads it. See Enable JSON Schema Validation.
  • Copy a whole definition at once. The builders compose a JSON text from the values that were read, and the game inserts that text in the database with a single action.
  • Let the player write the file in the game. A screen with fields for the name, the type and the values writes the content file with the file Actions of the game.
  • Show the mods in a list. The list reads the authors and the versions of the files and shows the report of each of them.
  • Keep the custom content in the save file. The stackable inventory guide stores the items that the player owns, and a custom item is stored exactly like a built-in one.
