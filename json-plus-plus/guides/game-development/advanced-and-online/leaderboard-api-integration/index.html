Leaderboard API Integration

A. Overview​

Emberfall shows a global ranking of the best runs. The game asks a service for the ranking, reads the answer it receives and draws the rows of the table. The service decides which runs count; the game only presents them.

DifficultyAdvanced
ComplexityHigh — one remote answer, a loop over the entries, an empty answer and a failed request
Fusion skillsFrame events, Active objects, Counter and String objects, global variables
JSON++ skillsLoading a file over HTTP, looping over an array, reading members with the path of the loop, handling errors

Gameplay scenario​

The player opens the ranking of Emberfall. The game asks the service for the twenty best runs of the season and draws three rows under the title Best runs of the season. A line at the bottom shows the rank of the player. When the service does not answer, the table is empty and the game says that the ranking is unavailable, without any other change.

Learning objectives​

By the end of this guide you will be able to:

  • load and parse a ranking answer with the file Actions of the extension;
  • walk the entries of the answer with a loop and read a member of the current entry;
  • show the rank of the player separately from the table;
  • handle a failed request, an empty answer and a malformed answer;
  • describe with precision what the extension does and what belongs to the service.

What you will build​

A request that loads the ranking over HTTP, a loop that draws the first rows of the table, a line that shows the rank of the player, a refresh button and the branches that handle a service that does not answer.

B. Prerequisites​

Fusion knowledge you need

  • Frame events and the condition Start of Frame.
  • The loop of the game, with the conditions that report the items and the end of the loop.
  • The Counter object and its conditions and actions.
  • The Active object and the condition is clicked.
  • The String object and the action Set alterable string.
  • Global variables on the Special object.

JSON++ concepts you need

  • Understanding JSON Loops and Reading Loop Values.
  • JSON paths, because the path of the current item turns an entry into an address.
  • Missing, null and Empty, because an answer can be incomplete.
  • Conditions and Triggers: On JSON Loaded and On Error are the two continuations of a load.

Runtime limitations to keep in mind

  • JSON++ Object reads and parses. It does not authenticate, it does not sign a request and it does not decide which score counts. Those belong to the service and to the part of the game that talks to it.
  • The browser runtime reaches an address with a request from the page. The service must allow the origin, and the answer must arrive with status 200.
  • The browser runtime refuses two file operations at the same time, so a refresh that overlaps the first request reports an error.
  • A request that times out leaves the remote state uncertain.
  • The address of this guide is illustrative. No particular service is integrated here.

Standard objects used here

String, Counter, Special, Timer, Active, JSON++ Object.

C. Gameplay Scenario​

A ranking service answers with a document. The document says whether the request succeeded, when the answer was produced, how many players the board holds, the entries of the table and the position of the player who asked.

The game reads the document and nothing else. The entries are an array of objects, and each entry holds the position, the identifier of the player, the name, the score and the level. The order of the array is the order of the table.

The game walks the entries with a loop and draws the first rows. The position of the player is a separate member of the answer, called you, and the game shows it under the table.

The service decides everything that matters for a ranking. It decides which runs count, it refuses a score that does not match a run, it keeps the history and it decides when a season ends. The game only asks, reads and draws.

D. Final Result​

The finished system behaves like this:

  • The table shows the three best runs of the season, with the position, the name and the score.
  • A line under the table shows the position and the score of the player.
  • A refresh button asks the service again and redraws the table.
  • A service that does not answer leaves the table empty and shows a clear message.
  • A board with no entry yet shows a different message, not an empty table.
  • A malformed answer is reported and changes nothing.

E. JSON Data Structure​

The answer of the service​

{
  "status": "ok",
  "board": "emberfall_global",
  "season": "2026_winter",
  "generated_at": "2026-02-14T18:32:00Z",
  "player_count": 1284,
  "entries": [
    {"rank": 1, "player_id": "ari_8841", "name": "Ari", "score": 15400, "level": 27, "country": "BR"},
    {"rank": 2, "player_id": "tenk_0077", "name": "Tenk", "score": 14980, "level": 26, "country": "JP"},
    {"rank": 3, "player_id": "mira_2210", "name": "Mira", "score": 14715, "level": 26, "country": "PT"}
  ],
  "you": {"rank": 84, "player_id": "ari_8841", "score": 9120, "level": 19}
}

The root object holds the status of the request and the contents of the board.

MemberTypeMeaning
statusstringThe result of the request. The value ok means the answer holds a board.
boardstringThe identifier of the board that was asked for.
seasonstringThe period the board covers.
generated_atstringThe moment the answer was produced.
player_countnumberHow many players the board holds.
entriesarray of objectsThe rows of the table, in the order of the ranking.
youobjectThe position of the player who asked.

Each entry of entries holds five members:

MemberTypeMeaning
ranknumberThe position in the table, starting at 1.
player_idstringThe identifier of the player, the one the service knows. It is not a name, and it is the identifier a submission must carry.
namestringThe name shown in the table. It is the name the player chose, and it can be anything.
scorenumberThe score of the run.
levelnumberThe level the player reached in the run.

The you object holds the same members, without the country: the position, the identifier, the score and the level of the player who asked.

An answer that reports a failure has the same shape with an empty list:

{
  "status": "error",
  "board": "emberfall_global",
  "entries": [],
  "you": {"rank": 0, "player_id": "ari_8841", "score": 0, "level": 19}
}

G. Step-by-Step Implementation​

Step 1 — Create the objects​

  1. Add the objects listed above to the frame of the ranking.
  2. Set the Rank Counter to 0 when the frame starts.
  3. Place the three labels invisible in the frame editor, so that a table with fewer than three rows shows nothing in the empty rows.

Step 2 — Ask for the ranking​

Add a Start of Frame event:

  • Condition: Start of Frame.
  • Action: Leaderboard Data : Load JSON from file at "https://api.emberfall.game/v1/leaderboard/global?limit=20".
  • Action: Leaderboard Timer : Start timer 120.

The address is the one of the service of the game. The extension sends the request and parses the answer.

Step 3 — Draw the table​

Add an event with the condition Leaderboard Data: On JSON Loaded:

  • Action: Rank Counter : Set counter to 0.
  • Action: Leaderboard Data : Start loop "Entries" at "/entries".

Then add an event with the condition Leaderboard Data: On Loop "Entries":

  • Action: Rank Counter : Add to counter 1.

And a group for each row of the table:

  • Condition of the group: Rank Counter = 1.
  • Action: Leaderboard Label 1 : Set alterable string to Str$(GetNumber( "Leaderboard Data", GetLoopPath( "Leaderboard Data", "Entries" ) + "/rank" )) + ". " + GetString( "Leaderboard Data", GetLoopPath( "Leaderboard Data", "Entries" ) + "/name" ) + " — " + Str$(GetNumber( "Leaderboard Data", GetLoopPath( "Leaderboard Data", "Entries" ) + "/score" )).

Repeat for the second and the third row, with the counter equal to 2 and to 3. The counter says which row is being drawn, and the path of the loop says which entry is being read.

Step 4 — Show the position of the player​

Add an event with the condition Leaderboard Data: On JSON Loaded:

  • Action: You Label : Set alterable string to "Your rank: " + Str$(GetNumber( "Leaderboard Data", "/you/rank" )) + " — " + Str$(GetNumber( "Leaderboard Data", "/you/score" )).

The member you holds the position of the player who asked. A service that answers without that member leaves the label empty, and the label is hidden in that case.

Step 5 — Handle a board with no entry​

Add an event with the condition Leaderboard Data: On JSON Loaded:

  • Condition of the group: Leaderboard Data: Is "/entries" empty?.
  • Action: Status Text : Set alterable string to "The board has no entry yet".

The empty answer and the failed request are two different situations, and the player deserves to know which one happened.

Step 6 — Handle a failed request​

Add an event with the condition Leaderboard Data: On Error:

  • Action: Status Text : Set alterable string to "The ranking is unavailable".
  • Action: Status Text : Set alterable string to GetError( "Leaderboard Data" ).

The second action overwrites the first with the technical message. Keep the friendly text and send the detail to the log of the game when the message is meant for the player.

Step 7 — Handle a request that never answers​

Add an event with the condition Leaderboard Timer: On timer:

  • Action: Status Text : Set alterable string to "The ranking is unavailable".

Step 8 — Refresh the table​

Add an event with the condition Refresh Button is clicked:

  • Action: Rank Counter : Set counter to 0.
  • Action: Leaderboard Data : Load JSON from file at "https://api.emberfall.game/v1/leaderboard/global?limit=20".
  • Action: Leaderboard Timer : Start timer 120.

The three labels are emptied when the new answer arrives, so that a table with fewer entries does not keep the rows of the previous answer.

I. Expected Behavior​

The answer of the service​

{
  "status": "ok",
  "board": "emberfall_global",
  "season": "2026_winter",
  "player_count": 1284,
  "entries": [
    {"rank": 1, "player_id": "ari_8841", "name": "Ari", "score": 15400, "level": 27, "country": "BR"},
    {"rank": 2, "player_id": "tenk_0077", "name": "Tenk", "score": 14980, "level": 26, "country": "JP"},
    {"rank": 3, "player_id": "mira_2210", "name": "Mira", "score": 14715, "level": 26, "country": "PT"}
  ],
  "you": {"rank": 84, "player_id": "ari_8841", "score": 9120, "level": 19}
}

The table reads:

1. Ari — 15400
2. Tenk — 14980
3. Mira — 14715
Your rank: 84 — 9120

A board with no entry​

{
  "status": "ok",
  "board": "emberfall_global",
  "entries": [],
  "you": {"rank": 0, "player_id": "ari_8841", "score": 0, "level": 19}
}

The three labels stay empty and the status line reads The board has no entry yet.

A service that does not answer​

The document of the runtime is unchanged, the table keeps the rows of the last answer, and the status line reads The ranking is unavailable.

J. Edge Cases & Error Handling​

SituationWhat happensHandling
The service does not answerThe load fails and On Error runsKeep the last table and show the message.
The request times outThe remote state is uncertainThe timer ends the wait and the message is shown.
The answer is not allowed by the browserThe load fails like any other failureThe service must allow the origin of the game.
The answer is not JSONThe document is not replacedReport the failure and keep the previous table.
The answer holds no entriesThe path selects nothingCheck the existence of the member before the loop starts.
The answer holds an empty entriesThe loop runs zero timesThe empty branch of Step 5 shows the message.
An entry has no nameThe expression returns an empty text and the row shows the position and the score onlyShow a placeholder when the name is empty.
The answer holds more entries than the table has rowsThe loop keeps counting and the rows keep the first three entriesStop the loop when the counter reaches the number of rows.
The player asks for a refresh while the first request is runningThe browser runtime refuses the concurrent operationDisable the button until the first answer arrives.
The you member is missingThe label shows a rank of zeroHide the label when the member is absent.
The player changes the name of the playerThe service stores the name and the table shows itThe name is text and the service decides whether it accepts it.
The score of the player is rejected by the serviceThe service answers without the entryThe position of the player comes from the answer, never from the game.

K. Runtime Compatibility​

The system reads one remote resource.

TargetFile workNotes
WindowsImplemented and testedThe build reaches the address with the network stack of the system.
AndroidImplemented, not verified by an automated checkThe application needs the permission of the network. Test the export.
HTML5Implemented and testedThe request comes from the page, so the service must allow the origin. A concurrent file operation is refused.
macOSUnknownNo separate build was verified.
iOSImplemented, not verified by an automated checkThe application needs the permission of the network. Test the export.

The extension reads and parses the answer. The authentication, the transport of a submitted score and the decision of the service belong to the service. The full matrix is on the runtime compatibility page.

M. Next Steps​

  • Show more rows. A list of ten labels and a loop that stops at the tenth entry turns the table into a ranking.
  • Show the position of the player in the table. A search for the identifier of the player inside the entries finds the row and marks it.
  • Refresh on a timer. A timer that asks the service every minute keeps the table current without the player doing anything.
  • Submit a score. The submission needs the transport and the credentials of the player, which belong to another part of the game. The extension reads the answer that comes back.
  • Keep a copy of the last answer. Writing the answer in a file lets the game show the last ranking while the service is unreachable.
