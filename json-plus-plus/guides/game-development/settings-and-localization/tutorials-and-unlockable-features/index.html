Tutorials and Unlockable Features

A. Overview​

Emberfall teaches its systems one after the other. The hero moves first, then fights, then opens a bag that did not exist before, and finally finds a crafting bench. Each lesson appears once, and the features it opens stay open.

DifficultyIntermediate
ComplexityMedium — one progress document, an ordered list of lessons and a set of unlocked features
Fusion skillsFrame events, Active objects, String objects, global variables, loops
JSON++ skillsLoops over an array of objects, reading a member of the current item, searching for a value, writing flags

Gameplay scenario​

A new player starts in the village of Emberfall. The game shows a single line at the bottom of the screen: Use the arrow keys to move. The player moves, the line disappears and the hint about fighting appears. When the player defeats a slime, a bag opens in the inventory button that was grey before, and the game explains how to open it. The hints never come back, and the unlocked features stay unlocked for the rest of the run.

Learning objectives​

By the end of this guide you will be able to:

  • describe the lessons of a game as an ordered list of objects in a document;
  • read a member of the item the loop is currently on, with the path of the loop;
  • open a feature only once, by writing a flag in the document;
  • add a member to a list only when it is not there yet;
  • keep the progress of the lessons in the same file as the game, and reset it when the player asks.

What you will build​

A progress document with the list of the lessons, the list of the unlocked features and the flags of the first-time events, the events that show the next lesson, the events that mark a lesson as completed and open the next feature, and the event that resets the progress.

B. Prerequisites​

Fusion knowledge you need

  • Frame events and the condition Start of Frame.
  • The loop of the game, with the conditions that report the start, the items and the end of a loop.
  • The Active object and the conditions is visible, is invisible and is clicked.
  • The String object and the action Set alterable string.
  • Global variables on the Special object.

JSON++ concepts you need

  • Understanding JSON Loops and Reading Loop Values: a loop over an array of objects exposes one item at a time.
  • JSON paths, because the path of the current item is what turns an item into an address.
  • Search Results and Their Lifetime, used to add a feature only once.
  • Missing, null and empty, because a flag that was never written is not the same as a flag set to zero.

Runtime limitations to keep in mind

  • The loop enumerates the immediate children of an array in order. It does not sort them, which is why the order of the lessons is the order of the array.
  • The path of a loop item reflects the snapshot taken when the loop started. A write that changes the structure of the document while the loop runs needs a fresh loop.
  • A flag that is absent is not the same as a flag set to zero. The guides of this collection always write the flag before reading it.

Standard objects used here

String, Counter, Special, Timer, Active, JSON++ Object.

C. Gameplay Scenario​

The lessons of Emberfall are four: movement, combat, inventory and crafting. The order matters, because each lesson opens the next one. The document keeps that order in an array.

Each lesson holds the flag that says whether it was completed, the feature it opens and the text of the hint. The text of the hint is a key, not a sentence, because the localization guide reads the text of the interface from the dictionary of the language.

The list of the unlocked features is a second array in the same document. A feature is unlocked by adding its identifier to that list, and the button of the feature becomes visible when the search for that identifier finds it.

The first-time events have their own section: a flag per situation, such as the first time the player opens the bag. The flag is written the moment the situation happens, which is what makes the hint appear only once.

D. Final Result​

The finished system behaves like this:

  • The game shows the hint of the first lesson that is not completed, and nothing else.
  • The hint disappears when the lesson is completed, and the next one takes its place.
  • Completing a lesson opens the feature it names, and the feature stays open for the rest of the run.
  • A situation that explains itself never explains itself twice.
  • The progress is stored with the game and restored at the next start.
  • Reset the progress puts the player back at the first lesson and closes the features again.

E. JSON Data Structure​

{
  "schema_version": 1,
  "tutorials": [
    {
      "id": "move",
      "title": "Movement",
      "hint": "hint.move",
      "completed": 0,
      "unlocks": "combat"
    },
    {
      "id": "combat",
      "title": "Combat",
      "hint": "hint.combat",
      "completed": 0,
      "unlocks": "inventory"
    },
    {
      "id": "inventory",
      "title": "Inventory",
      "hint": "hint.inventory",
      "completed": 0,
      "unlocks": "crafting"
    },
    {
      "id": "crafting",
      "title": "Crafting",
      "hint": "hint.crafting",
      "completed": 0,
      "unlocks": ""
    }
  ],
  "unlocked": ["combat"],
  "first_time": {
    "opened_bag": 0,
    "visited_merchant": 0,
    "saw_crafting_bench": 0
  }
}

The root object holds three sections.

tutorials is an array of four objects, and the order of the array is the order of the lessons. An array is used here on purpose: the loop of the game walks it in order, and the game needs the first lesson that is not completed.

Each lesson holds five members:

MemberTypeMeaning
idstringThe identifier of the lesson, such as move.
titlestringThe name of the lesson in the interface.
hintstringThe key of the sentence shown to the player. The sentence itself belongs to the dictionary of the language.
completednumber1 when the lesson was completed, 0 while it is pending.
unlocksstringThe identifier of the feature the lesson opens. Empty for the last lesson.

unlocked is an array of the identifiers of the features that are open. A feature is unlocked when its identifier is in this array.

first_time is an object whose members are the situations that explain themselves once. Each member is a flag with 1 when the situation already happened.

G. Step-by-Step Implementation​

Step 1 — Create the objects​

  1. Add the objects listed above to the frames that use them.
  2. Place the Inventory Button, the Crafting Bench and the Merchant Marker invisible in the frame editor, so that they appear only when the document says they are open.
  3. Create global strings Feature Id and Lesson Id, and a numeric global Lesson Index on the Special object.

Step 2 — Load the progress​

Add a Start of Frame event:

  • Condition: Start of Frame.
  • Action: Progress Data : Load JSON from file at Apppath$ + "progress.json".

Step 3 — Show the hint of the first lesson that is not completed​

In Progress Data: On JSON Loaded, clear Hint Label and start loop Tutorials at /tutorials.

Step 4 — Show the hint only when the lesson is pending​

In On Loop "Tutorials", add Compare To Number for GetLoopPath( "Progress Data", "Tutorials" ) + "/completed", equal to0. Store GetLoopIndex in the numeric global Lesson Index and read the /id member into the global string Lesson Id. Read /hint into Hint Label, then stop Tutorials in that same event. Stopping preserves the first pending lesson.

The label holds the localization key. Resolve it through the localization guide.

Step 5 — Complete a lesson​

When the player performs the movement lesson, require Lesson Id = "move". Set number1 at "/tutorials/" + Str$(Lesson Index) with key "completed". This uses the index stored while the loop was active.

Start Unlocks again to update the unlocked features, clear Hint Label and start Tutorials again to select the next pending lesson. Apply the corresponding gameplay condition for each later lesson.

Step 6 — Open the feature of the completed lesson​

Start a separate loop Unlocks at /tutorials after loading progress and after completing a lesson. In On Loop "Unlocks", require /completed equal to1 and the length of /unlocks greater than0. Read /unlocks into the global string Feature Id, then search at /unlocked with Exact1, passing """" + Feature Id + """". The quotes encode these feature identifiers as JSON strings on both runtimes.

In On Not Results Found, insert Feature Id into /unlocked, then repeat the search. The second search emits On Results Found for the inserted identifier. These search callbacks belong to this unlock flow.

Step 7 — Show the feature when it is open​

In On Results Found, add the global-string condition Feature Id = "inventory" before showing Inventory Button and writing the status message. Use a corresponding identifier condition for crafting or other features. An existing feature is found directly, and a newly inserted feature is found by the repeated search.

Step 8 — Handle a situation that explains itself once​

Add an event with the condition Inventory Button is clicked:

  • Condition of the group: Progress Data: Is "/first_time/opened_bag" equal to 0?.
  • Action: Status Text : Set alterable string to "Press Q to use a potion".
  • Action: Progress Data : Set number 1 at "/first_time" with key "opened_bag".

The flag is written in the same group that shows the message, so the message appears only while the flag is zero.

Step 9 — Store the progress​

Add an event with the condition Save Game is clicked:

  • Action: Progress Data : Save JSON to file at Apppath$ + "progress.json".

The checkpoints and autosave guide shows how this file joins the other files of a run.

Step 10 — Reset the progress​

Add an event with the condition Reset Progress is clicked:

  • Action: Progress Data : Set array "[]" at "/" with key "unlocked" and index -1.
  • Action: Progress Data : Set number 0 at "/tutorials/0" with key "completed".
  • Action: Progress Data : Set number 0 at "/tutorials/1" with key "completed".
  • Action: Progress Data : Set number 0 at "/tutorials/2" with key "completed".
  • Action: Progress Data : Set number 0 at "/tutorials/3" with key "completed".
  • Action: Inventory Button : Set invisible.
  • Action: Crafting Bench : Set invisible.

Deleting the first item of the list of unlocked features leaves the array empty, because it held one item. A list with more items is emptied by deleting them one by one, since the extension has no action that clears an array.

I. Expected Behavior​

Before the first lesson is completed​

{
  "schema_version": 1,
  "tutorials": [
    {"id": "move", "title": "Movement", "hint": "hint.move", "completed": 0, "unlocks": "combat"},
    {"id": "combat", "title": "Combat", "hint": "hint.combat", "completed": 0, "unlocks": "inventory"}
  ],
  "unlocked": [],
  "first_time": {"opened_bag": 0, "visited_merchant": 0}
}

The hint line shows the sentence of hint.move, and the bag button stays invisible.

After the movement lesson and the first slime​

{
  "schema_version": 1,
  "tutorials": [
    {"id": "move", "title": "Movement", "hint": "hint.move", "completed": 1, "unlocks": "combat"},
    {"id": "combat", "title": "Combat", "hint": "hint.combat", "completed": 1, "unlocks": "inventory"},
    {"id": "inventory", "title": "Inventory", "hint": "hint.inventory", "completed": 0, "unlocks": "crafting"}
  ],
  "unlocked": ["combat", "inventory"],
  "first_time": {"opened_bag": 1, "visited_merchant": 0}
}

The hint line shows the sentence of hint.inventory, the bag button is visible, and the lesson about the combat is not shown again.

After the player resets the progress​

{
  "schema_version": 1,
  "tutorials": [
    {"id": "move", "title": "Movement", "hint": "hint.move", "completed": 0, "unlocks": "combat"},
    {"id": "combat", "title": "Combat", "hint": "hint.combat", "completed": 0, "unlocks": "inventory"}
  ],
  "unlocked": [],
  "first_time": {"opened_bag": 0, "visited_merchant": 0}
}

The bag button is invisible again and the first hint is shown again.

J. Edge Cases & Error Handling​

SituationWhat happensHandling
The progress file is missingThe load fails and On Error runsWrite a progress document with the lessons when the game starts without one.
A lesson has no unlocks memberThe getter reports a missing pathGive every lesson the member. The nonempty check skips the empty identifier of the last lesson.
A lesson was completed twiceThe flag is written twice and nothing else changesThe flag is a number, so writing it twice is harmless.
The same feature is unlocked twiceThe search finds the identifier and the feature is not added againThe search of Step 6 is what prevents the duplicate.
The list of unlocked features holds several itemsSet Array with index-1 replaces the complete arraySet /unlocked to [] with index-1.
The document is changed while the loop runsThe snapshot of the loop does not changeStart a new loop after a change of the structure.
The player opens the bag during the same frame in which the lesson was completedThe flag may still be zero and the message appears once moreWrite the flag before the message in the same group.
A hint key does not exist in the dictionaryThe label receives an empty textCheck the key with the exists condition, as the localization guide does.
The player changes the language during the lessonsThe hint keeps the key and the sentence follows the languageRead the hint key into a global and write the sentence again after the language changes.
The game runs on HTML5Apppath$ has no meaningUse a browser reference such as storage://progress and read the platform-specific file guide.

M. Next Steps​

  • Give the lessons a milestone. A member with the number of the milestone lets the game show the progress as a bar of the lessons completed.
  • Let the player skip a lesson. A button that writes the flag of every lesson before the current one is a short event.
  • Show the lessons in the options menu. The same document can list the lessons and their state, so the player sees what is left.
  • Use the first-time flags elsewhere. The merchant marker and the hint of the bench follow the same pattern of a flag per situation.
  • Keep the progress with the run. The multiple save slots guide stores the progress of every slot, and the lessons follow the slot that is loaded.
