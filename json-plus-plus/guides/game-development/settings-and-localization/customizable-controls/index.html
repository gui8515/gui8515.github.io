Customizable Controls

A. Overview​

The options menu of Emberfall lets the player choose the keys of every action of the game. The mapping survives a restart, the defaults can be restored, and a binding that duplicates another one is refused with a message instead of silently breaking the game.

DifficultyIntermediate
ComplexityMedium — one mapping document, one list of actions and a conflict check
Fusion skillsFrame events, Active objects, String objects, global variables, the keyboard object
JSON++ skillsReading members with a computed path, replacing an item of an array, searching values, writing the mapping

Gameplay scenario​

The player opens the options of Emberfall and reaches the controls. Nine actions are listed, from Move left to Pause. The player presses the W key while Move up is selected, and the list shows W. The player tries the same key on Move left, and the game refuses it, because W already moves the hero up and two actions cannot answer to the same key.

Learning objectives​

By the end of this guide you will be able to:

  • describe the controls of a game as a document of identifiers and keys;
  • read the binding of an action with a path built at runtime;
  • replace a key inside an array of keys and keep the array in a known shape;
  • find out whether a key is already used, with a search and with a loop;
  • store the mapping, restore the defaults and load the mapping when the game starts.

What you will build​

A mapping document that lists every action of the game with its default key and its current keys, a controls list in the options menu, a capture event that records the key the player pressed, a conflict check that refuses a duplicate, and the events that save the mapping and restore the defaults.

B. Prerequisites​

Fusion knowledge you need

  • Frame events and the condition Start of Frame.
  • The keyboard object and the condition that reports a key press.
  • The Active object and the condition is clicked.
  • The String object and the action Set alterable string.
  • Global variables on the Special object, including one that holds text.
  • The loop of the game: a Loop event that runs once per item of a list.

JSON++ concepts you need

  • JSON paths, and the reading of an item of an array with a path such as /actions/move_left/keys/0.
  • Understanding JSON Loops, because the conflict check walks the actions.
  • Search Results and Their Lifetime, because the conflict check also uses a search.
  • JSON instance state: the mapping lives in a JSON++ Object of its own.

Runtime limitations to keep in mind

  • JSON++ Object does not read the keyboard. It stores the mapping and gives it back. The detection of a key press and the movement of the hero belong to Fusion, or to the input system the game uses.
  • The name of a key is text. The game and the document must agree on the spelling, because the comparison is a comparison of text.
  • A key that the game cannot read is a dead binding. Test the binding on the target the game ships to.

Standard objects used here

String, Counter, Special, Timer, Active, JSON++ Object.

C. Gameplay Scenario​

Every action of Emberfall has an identifier: move_left, move_right, move_up, move_down, jump, attack, interact, use_potion and pause. The identifier never changes. The key that answers to it is what the player chooses.

The document holds both. For each action it stores the name shown in the menu, the default key and the list of the keys currently bound to it. The list is an array because a single action can answer to more than one key, and because a binding can keep a second key as an alternative.

The options menu reads the document and draws one row per action. When the player selects a row and presses a key, the game writes that key into the document. Before the write, the game checks whether the key is already used by another action, and refuses it with a message when it is.

The gameplay events read the same document. The event that jumps the hero compares the key that was pressed with the key stored in /actions/jump/keys/0. The document is the single place where the binding lives, which is what makes the restore of the defaults a single event.

D. Final Result​

The finished system behaves like this:

  • The controls list shows the current binding of every action.
  • Selecting an action and pressing a key rebinds it immediately, and the list shows the new key.
  • A key that another action already uses is refused, and the list keeps the old binding.
  • Restore defaults returns every action to the key it ships with.
  • The mapping is stored and applied at the next start of the game.
  • The gameplay code does not change when a binding changes.

E. JSON Data Structure​

{
  "schema_version": 1,
  "actions": {
    "move_left": {
      "name": "Move left",
      "default": "left",
      "keys": ["left"]
    },
    "move_right": {
      "name": "Move right",
      "default": "right",
      "keys": ["right"]
    },
    "move_up": {
      "name": "Move up",
      "default": "up",
      "keys": ["up"]
    },
    "move_down": {
      "name": "Move down",
      "default": "down",
      "keys": ["down"]
    },
    "jump": {
      "name": "Jump",
      "default": "space",
      "keys": ["space"]
    },
    "attack": {
      "name": "Attack",
      "default": "z",
      "keys": ["z"]
    },
    "interact": {
      "name": "Interact",
      "default": "e",
      "keys": ["e"]
    },
    "use_potion": {
      "name": "Use potion",
      "default": "q",
      "keys": ["q"]
    },
    "pause": {
      "name": "Pause",
      "default": "escape",
      "keys": ["escape"]
    }
  }
}

The root object holds the version and the actions.

actions is an object whose members are the actions, each one named by its identifier. An object is used instead of an array because the identifier of the action is the key of the lookup, and a path such as /actions/jump/keys/0 reaches the binding of a single action without any index.

Each action holds three members:

MemberTypeMeaning
namestringThe name of the action shown in the options menu.
defaultstringThe key the game ships with. The restore of the defaults copies it back into keys.
keysarray of stringsThe keys currently bound to the action. The first one is the key the game uses, the others are alternatives.

The name of a key is a text chosen by the game: left, right, up, down, space, z, e, q, escape. The document does not define the vocabulary; the game does.

G. Step-by-Step Implementation​

Step 1 — Create the objects​

  1. Add the objects listed above to the frame of the options menu.
  2. Create the global variables Action Id, New Key and Default Key on the Special object.
  3. Give the rows of the Controls Row an alterable string named ActionId with the identifier of their action: move_left, jump, attack and so on.

Step 2 — Load the mapping​

Add a Start of Frame event:

  • Condition: Start of Frame.
  • Action: Controls Data : Load JSON from file at Apppath$ + "controls.json".

Step 3 — Draw the list​

Add an event with the condition Controls Data: On JSON Loaded:

  • Action: Timer : Fire event "ControlsReady" after 00"-01.

Timer schedules ControlsReady with a 10 ms delay. The named event updates the list after loading has completed.

Step 4 — Show the binding of a row​

Add an event with the condition Controls Row is clicked:

  • Action: Special : Set Action Id to ActionId("Controls Row").
  • Action: Special : Set Default Key to GetString( "Controls Data", "/actions/" + Action Id + "/default" ).
  • Action: Key Label : Set alterable string to GetString( "Controls Data", "/actions/" + Action Id + "/keys/0" ).

The first action stores the identifier of the row in a global, so the events that follow work with every row. The last action shows the key that is in use.

Step 5 — Capture the key the player pressed​

Add an event with the condition Keyboard: On key pressed:

  • Action: Special : Set New Key to <the key that was pressed>.
  • Action: Controls Data : Set array New Key at "/actions/" + Action Id + "/keys" with key "unused" and index 0.

The first action records the key in a global. The second replaces the first item of the array of keys of the action being edited. The array keeps its shape: the binding always has a first key, and the restore of the defaults has a value to write back.

Step 6 — Refuse a key that another action already uses​

Add an event with the condition Controls Data: On Loop "Actions" and, inside it, the comparison below. The loop walks the actions of the document, and the comparison reads the first key of each of them:

  • Condition of the group: Controls Data: Is "/actions/" + GetLoopKey( "Controls Data", "Actions" ) + "/keys/0" equal to New Key?.

Inside that group, the event that reports the conflict:

  • Action: Status Text : Set alterable string to "Already used by another action".

The group runs for the action that already owns the key. The event that writes the new binding belongs to the group that finds no conflict, so the write never happens when a conflict exists.

Step 7 — Write the binding when nothing is in conflict​

Add a second group under the same loop:

  • Condition of the group: Controls Data: Is "/actions/" + GetLoopKey( "Controls Data", "Actions" ) + "/keys/0" equal to New Key?.

That is the same condition, which cannot decide both. The check needs the opposite answer, so the game compares the two keys in a different way: the loop stores the key of the current action in a global and compares it with the new key.

  • Action: Special : Set Other Key to GetString( "Controls Data", "/actions/" + GetLoopKey( "Controls Data", "Actions" ) + "/keys/0" ).
  • Condition of the group: Controls Data: Is "/actions/" + Action Id + "/keys/0" equal to New Key? reads the binding of the action being edited, and the group that writes the new key runs when that binding is different from the new key.

The two comparisons together give the rule the guide needs: the game writes the new key only when the action being edited is not the action that already owns it.

Step 8 — Restore the defaults​

Add an event with the condition Restore Defaults is clicked:

  • Action: Controls Data : Set array Default Key at "/actions/" + Action Id + "/keys" with key "unused" and index 0.
  • Action: Status Text : Set alterable string to "Default restored".

The event restores the action that was selected. To restore every action at once, walk the actions with a loop and write the default member of each of them into the first item of its own array of keys.

Step 9 — Store the mapping​

Add an event with the condition Save Controls is clicked:

  • Action: Controls Data : Save JSON to file at Apppath$ + "controls.json".

And an event with the condition Controls Data: On JSON Saved to File:

  • Action: Status Text : Set alterable string to "Controls saved".

Step 10 — Read the binding in the gameplay​

The gameplay events read the mapping. The event that jumps the hero compares the key that was pressed with the key stored in the document:

  • Condition: Keyboard: On key pressed.
  • Condition: Controls Data: Is "/actions/jump/keys/0" equal to <the key that was pressed>?.
  • Action: Player : Set Y Velocity to -300.

The document does not read the keyboard and does not move the hero. It holds the name of the key, and the events of the game decide what that key means.

I. Expected Behavior​

The mapping of a new installation​

{
  "schema_version": 1,
  "actions": {
    "move_left": {"name": "Move left", "default": "left", "keys": ["left"]},
    "move_up": {"name": "Move up", "default": "up", "keys": ["up"]},
    "jump": {"name": "Jump", "default": "space", "keys": ["space"]},
    "attack": {"name": "Attack", "default": "z", "keys": ["z"]}
  }
}

The list shows left, up, space and z.

After the player binds W to Move up​

{
  "schema_version": 1,
  "actions": {
    "move_left": {"name": "Move left", "default": "left", "keys": ["left"]},
    "move_up": {"name": "Move up", "default": "up", "keys": ["w"]},
    "jump": {"name": "Jump", "default": "space", "keys": ["space"]},
    "attack": {"name": "Attack", "default": "z", "keys": ["z"]}
  }
}

The array of move_up still holds one item, and the default is untouched, so the restore of the defaults has a value to work with.

After the player tries to bind W to Move left​

The document does not change:

{
  "schema_version": 1,
  "actions": {
    "move_left": {"name": "Move left", "default": "left", "keys": ["left"]},
    "move_up": {"name": "Move up", "default": "up", "keys": ["w"]}
  }
}

The status line reads Already used by another action, and the binding of Move left is still left.

J. Edge Cases & Error Handling​

SituationWhat happensHandling
The mapping file is missingThe load fails and On Error runsShip the file with the game and write the defaults when it is absent.
An action has no keys memberThe path selects nothing and the expression returns an empty textCheck the existence of /actions/ + Action Id + /keys/0 before reading it.
An action has an empty keys arrayThe path selects nothingWrite the default into the array when the array is empty.
The player binds a key the game cannot readThe binding is stored and the action never happensTest every key the player can choose on the targets the game ships to.
Two actions share a keyBoth answer to the same keyThe conflict check refuses the second binding.
The action being edited is the one that owns the keyThe check would report a conflict with itselfCompare the binding of the action being edited with the new key before the conflict is reported.
The player binds a key to an action that has alternativesThe first key is replaced and the alternatives stayWrite to the index 0 of the array and keep the other items.
The document is edited by hand and holds an unknown actionThe game ignores itWalk the actions with a loop instead of naming them one by one.
The game runs on HTML5Apppath$ has no meaningUse a browser reference such as storage://controls and read the platform-specific file guide.
The mapping is written while the game reads itThe document of the runtime may be replacedWrite the file in a single event and let the game read the document again after it is saved.

The system reads and writes one file and reads values with computed paths.

TargetFile workValue changesNotes

M. Next Steps​

  • Keep the alternatives in use. Write the second key of the array into the second condition of the action, so that the player can bind two keys to the same action.
  • Show the key that conflicts. The search for the value returns the path of the result, and the path names the action that owns the key.
  • Restore every action at once. A loop over the actions writes the default member of each of them into the first item of its own array.
  • Save the mapping with the other preferences. One preferences file with the language, the difficulty and the controls keeps a single save point for the options.
  • Validate the mapping. A JSON schema rejects a mapping that lost an action before the game reads it. See Enable JSON Schema Validation.
