Difficulty Presets

A. Overview​

Emberfall offers three difficulties. On the easy setting the slimes hit for half of their damage and the player carries more potions; on the hard setting they hit for twice as much and the rewards are thinner. The choice is made in the options menu and applies to everything that comes after it.

DifficultyIntermediate
ComplexityMedium — one configuration document, five multipliers and one event per system that reads them
Fusion skillsFrame events, Active objects, Counter objects, global variables, expressions
JSON++ skillsReading members with a computed path, arithmetic through expressions, writing the chosen preset

Gameplay scenario​

The player starts a new run of Emberfall and chooses Normal in the options menu. The forest holds the same slimes as before, but their health and their damage now come from the multipliers of the preset. The player changes the setting to Hard during the run, and the next slime that appears is tougher. The hero picks up a gold pouch after the fight and receives a reward scaled by the same preset.

Learning objectives​

By the end of this guide you will be able to:

  • describe a difficulty as a small set of numbers instead of as a copy of the events;
  • apply a multiplier to a value that comes from another document, such as the health of an enemy;
  • read the selected preset with a path built from an identifier;
  • offer a custom preset without adding a branch to every system of the game;
  • store the choice of the player and apply it again at the next start.

What you will build​

A configuration document with the three presets and one custom slot, an event that applies the preset to the enemies, one that applies it to the damage the hero takes, one that scales the rewards, and the events that read and store the choice.

B. Prerequisites​

Fusion knowledge you need

  • Frame events and the condition Start of Frame.
  • The Counter object and its actions Set counter, Add to counter and Subtract from counter.
  • The Special object and its global variables.
  • The Active object and the condition is clicked.
  • Arithmetic inside an expression, and the Floor expression when a result must be a whole number.

JSON++ concepts you need

  • JSON paths, especially a path built from a global variable.
  • JSON instance state: the preset lives in a JSON++ Object of its own, apart from the database of the enemies.
  • Missing, null and empty, because a preset that is absent must not silently become the neutral value.

Runtime limitations to keep in mind

  • A multiplier is a number in the document; it changes nothing by itself. Each system that reacts to the difficulty needs its own event, and the guide names it.
  • A number read from the document is a floating point value. When the result becomes a counter or an amount of gold, round it with Floor so the player never sees half a coin.
  • The preset is read at the moment an enemy is created or an event happens. Changing the preset in the options menu therefore affects what comes after the change, not the enemies already on the screen.

Standard objects used here

String, Counter, Special, Timer, JSON++ Object.

C. Gameplay Scenario​

The balance of Emberfall lives in two places. The database of the enemies says that a wolf has forty-five health, deals nine damage and grants twenty experience. The preset of the difficulty says how much of that the player has to deal with: the easy preset multiplies the health by 0.75, the normal preset leaves it at 1 and the hard preset multiplies it by 1.5.

The two documents meet in one event, when an enemy is created. The event reads the base health of the type, reads the multiplier of the preset and writes the result in the counter of the new enemy. Nothing else in the game needs to change when a designer decides that the hard preset is too easy.

The same pattern repeats for the damage the hero receives, for the quantity of resources found in the world and for the gold and the experience of a defeated enemy. Each of them is a small event that reads the preset.

D. Final Result​

The finished system behaves like this:

  • The options menu offers Easy, Normal, Hard and a custom slot.
  • The choice is stored and applied the next time the game starts.
  • An enemy created after the choice has the health, the damage and the speed of the preset.
  • The damage the hero takes and the rewards of a defeat follow the same preset.
  • A custom preset lets the player set the multipliers, and the game uses it exactly as it uses a preset that ships with the game.
  • Changing the preset does not rewrite the enemies already on the screen, and the guide says so.

E. JSON Data Structure​

{
  "schema_version": 1,
  "selected": "normal",
  "presets": {
    "easy": {
      "name": "Easy",
      "enemy_health_multiplier": 0.75,
      "damage_taken_multiplier": 0.5,
      "resource_multiplier": 1.5,
      "reward_multiplier": 0.8,
      "starting_gold": 500
    },
    "normal": {
      "name": "Normal",
      "enemy_health_multiplier": 1,
      "damage_taken_multiplier": 1,
      "resource_multiplier": 1,
      "reward_multiplier": 1,
      "starting_gold": 300
    },
    "hard": {
      "name": "Hard",
      "enemy_health_multiplier": 1.5,
      "damage_taken_multiplier": 2,
      "resource_multiplier": 0.5,
      "reward_multiplier": 1.5,
      "starting_gold": 150
    },
    "custom": {
      "name": "Custom",
      "enemy_health_multiplier": 1,
      "damage_taken_multiplier": 1,
      "resource_multiplier": 1,
      "reward_multiplier": 1,
      "starting_gold": 300
    }
  }
}

The root object holds the version, the identifier of the preset in use and the presets themselves.

presets is an object whose members are the presets, each one named by its identifier: easy, normal, hard and custom. An object is used instead of an array because the identifier of the preset is the key of the lookup, and a path such as /presets/hard/damage_taken_multiplier reads the value without any index.

Each preset holds the same six members:

MemberTypeMeaning
namestringThe name shown in the options menu. It is not translated by this document, because the localization guide reads the name from the dictionary of the language.
enemy_health_multipliernumberMultiplies the health of every enemy. A value of 1 leaves the balance untouched.
damage_taken_multipliernumberMultiplies the damage the hero receives.
resource_multipliernumberMultiplies the quantity of the resources found in the world, such as the potions of a chest.
reward_multipliernumberMultiplies the gold and the experience of a defeated enemy.
starting_goldnumberThe gold the hero owns when a new run begins. It is a value and not a multiplier, because there is no base to multiply.

The custom preset always exists, even before the player touches it. It starts with the neutral values, which are the values of the normal preset, so that a game that never opens the options menu still finds a complete preset.

G. Step-by-Step Implementation​

Step 1 — Create the objects​

  1. Add the objects listed above to the frames that use them.
  2. Create the global variables Difficulty Id and Difficulty Name on the Special object. Difficulty Id starts with the text normal.
  3. Give the rows of the Difficulty Selector an alterable string named DifficultyId with the values easy, normal, hard and custom.

Step 2 — Load the configuration​

Add a Start of Frame event:

  • Condition: Start of Frame.
  • Action: Difficulty Data : Load JSON from file at Apppath$ + "difficulty.json".

Step 3 — Read the stored choice​

Add an event with the condition Difficulty Data: On JSON Loaded:

  • Action: Settings Data : Load JSON from file at Apppath$ + "settings.json".

And an event with the condition Settings Data: On JSON Loaded:

  • Action: Special : Set Difficulty Id to GetString( "Settings Data", "/difficulty" ).
  • Action: Difficulty Name Label : Set alterable string to GetString( "Difficulty Data", "/presets/" + Difficulty Id + "/name" ).

When the preferences file does not exist, the error branch runs and the preset of the configuration is used:

  • Condition: Settings Data: On Error.
  • Action: Special : Set Difficulty Id to GetString( "Difficulty Data", "/selected" ).

Step 4 — Apply the preset to an enemy​

The enemy is created by the game, with its counters as children. The event that initializes a new enemy reads the base values of its type and multiplies them by the preset:

  • Condition: Enemy Clock: On timer.
  • Action: Enemy HP : Set counter to Floor(GetNumber( "Enemy Database", "/enemies/" + EnemyType("Enemy") + "/hp" ) * GetNumber( "Difficulty Data", "/presets/" + Difficulty Id + "/enemy_health_multiplier" )).
  • Action: Enemy Damage : Set counter to Floor(GetNumber( "Enemy Database", "/enemies/" + EnemyType("Enemy") + "/damage" ) * GetNumber( "Difficulty Data", "/presets/" + Difficulty Id + "/damage_taken_multiplier" )).

Two documents meet in the same expression: the base value of the type and the multiplier of the preset. The result is written in the counter of the instance, which is the only part the extension does not do.

Step 5 — Apply the preset to the damage the hero receives​

  • Condition: Enemy is overlapping Player.
  • Action: Hero HP : Subtract from counter value("Enemy Damage").

The Enemy Damage counter already includes the multiplier applied in Step 4. Subtract that value directly. On hard, 9 × 2 produces 18 damage and reduces health from 100 to 82.

Step 6 — Apply the preset to the resources​

  • Condition: Chest is clicked.
  • Action: Item Counter : Set counter to Floor(GetNumber( "Difficulty Data", "/presets/" + Difficulty Id + "/resource_multiplier" ) * 2).

The chest gives two potions on the normal preset, three on the easy preset and one on the hard preset.

Step 7 — Apply the preset to the rewards​

  • Condition: Enemy is destroyed.
  • Action: Gold Counter : Add to counter Floor(GetNumber( "Difficulty Data", "/presets/" + Difficulty Id + "/reward_multiplier" ) * 25).
  • Action: XP Counter : Add to counter Floor(GetNumber( "Difficulty Data", "/presets/" + Difficulty Id + "/reward_multiplier" ) * 30).

The base reward of the type is the other half of the multiplication. When the reward depends on the type of the enemy, read it from the database of the enemies as well.

Step 8 — Let the player choose​

Add an event with the condition Difficulty Selector is clicked:

  • Action: Special : Set Difficulty Id to DifficultyId("Difficulty Selector").
  • Action: Difficulty Name Label : Set alterable string to GetString( "Difficulty Data", "/presets/" + Difficulty Id + "/name" ).

The enemies already on the screen keep their values. The new ones use the new preset. Say this in the interface of the game, because a player who expects an instant change will think the game is broken.

Step 9 — Offer a custom difficulty​

Add an event with the condition Custom Slider is released:

  • Action: Difficulty Data : Set number 1.5 at "/presets/custom" with key "enemy_health_multiplier".
  • Action: Difficulty Data : Set number 2 at "/presets/custom" with key "damage_taken_multiplier".

The custom slot is a normal preset. Writing the multipliers into it makes it behave exactly like the others, because every event of the game reads the preset by identifier and never checks which one it is.

Step 10 — Store the choice​

Add an event with the condition Save Settings is clicked:

  • Action: Settings Data : Set string Difficulty Id at "/" with key "difficulty".
  • Action: Settings Data : Save JSON to file at Apppath$ + "settings.json".

And an event with the condition Difficulty Data: On JSON Saved that writes the selection back into the configuration, so that the game opens in the same difficulty even before the preferences are read:

  • Action: Difficulty Data : Set string Difficulty Id at "/" with key "selected".
  • Action: Difficulty Data : Save JSON to file at Apppath$ + "difficulty.json".

On the hard preset​

A wolf of the database has forty-five health and nine damage:

{
  "enemies": {
    "wolf": {
      "id": "wolf",
      "hp": 45,
      "damage": 9,
      "speed": 70,
      "xp_reward": 20
    }
  }
}

The counters of the new wolf hold the multiplied values: the health is Floor(45 * 1.5), which is 67, and the damage is Floor(9 * 2), which is 18. The hero loses 18 points of life per hit and receives Floor(25 * 1.5), which is 37 gold.

On the easy preset​

The same wolf starts with Floor(45 * 0.75), which is 33 health, and hits for Floor(9 * 0.5), which is 4. The chest that gives two potions on the normal preset gives Floor(2 * 1.5), which is 3.

After the player stores the choice​

{
  "locale": "en",
  "difficulty": "hard",
  "music_volume": 80
}

The next start reads hard from the preferences, the label of the options menu reads Hard and the first enemy that appears already uses the multipliers of that preset.

J. Edge Cases & Error Handling​

SituationWhat happensHandling
The configuration file is missingThe load fails and On Error runsShip the file with the game and show a clear message when it is missing.
The chosen preset does not exist in the configurationThe path selects nothing and the expression returns a fallback of 0Check the existence of /presets/ + Difficulty Id before reading the multipliers.
A multiplier is missing in a presetThe expression returns 0 and the enemy has no healthGive every preset the same members and compare the presets in the tests.
The multiplier is 0 because of a missing valueThe enemy has no health and dies at onceTreat a multiplier of 0 as a missing value and fall back to 1.
The player switches the preset while an enemy is on the screenThe enemy keeps its valuesApply the preset when the enemy is created, and say so in the interface.
The result of a multiplication is not a whole numberThe counter receives a fractional valueWrap the expression with Floor, as every example of this guide does.
The custom preset is saved with values the player never choseThe game starts with those valuesReset the custom slot to the neutral values when the options menu opens.
The preferences and the configuration disagreeThe preferences win, because they are read lastWrite the selection to the configuration as well, as Step 10 does.
A designer raises a multiplier to a value that breaks the fightThe fight becomes impossibleTest the extreme values of every preset before a release.
The game runs on HTML5Apppath$ has no meaningUse a browser reference such as storage://difficulty and read the platform-specific file guide.

TargetFile workValue changesNotes

The multipliers are plain numbers, so the behaviour of the game does not depend on the target. What does depend on the target is where the configuration is read from, and the full matrix is on the runtime compatibility page.

M. Next Steps​

  • Move the names to the dictionary. The name member of a preset belongs to the localization dictionary, which already knows how to show a key in the language of the player.
  • Add a mode that scales the world. A multiplier for the quantity of enemies or for the length of the day follows the same pattern.
  • Show the preset in the interface. A label that reads the multipliers of the current preset helps the player understand what the option does.
  • Apply the preset to a whole party. When a group of enemies appears, one event writes the same values in each of them, and the loop of the enemy waves guide does the work.
  • Validate the configuration. A JSON schema rejects a preset that lost a multiplier before the game reads it. See Enable JSON Schema Validation.
