Loop buffers and search results

Loop Expressions read a named callback context, not arbitrary document paths. Search-result Expressions read a stored result list, not a newly executed search. Treat their lifetimes separately from the document itself.

Loop phases and lifetime​

Start Loop registers iteration over an existing object or array. On native targets, iteration is frame-sliced: the scheduler processes items within a time budget. Do not assume all items or completion happen before Start Loop returns.

On Start Loop can run before the first item buffer is populated. On Loop is the appropriate place to read current values. On End Loop runs around completion, after which state is removed. Empty-name trigger parameters do not have the same alias semantics.

The default loop captures iterators into the live JSON container. Structural mutations can invalidate them, so mutating the document during a callback is not safe. On HTML5, the loop also holds a target reference and a key list. Collect changes separately when a workflow needs predictable iteration over stable input.

What the loop getters actually contain​

  • Get Loop String returns raw string contents for a string value and serialized text for other types.
  • Get Loop Number and Boolean use zero when the current item does not have the corresponding type.
  • Get Loop Object/Array test the iterated parent container flag. They do not validate that the current item has the type implied by their names.
  • Get Loop Index is the active loop index. Get Loop Number of Items is the original container total, not the remaining count or child size. On native targets, object-item paths append raw keys; On HTML5, pointer tokens are escaped. Keys containing / or ~ need particular care when reusing a native loop path.

For a stable collection such as {"items":["Potion","Key"]}, start a named Inventory loop at /items and read GetLoopString in On Loop Inventory. The item callbacks yield Potion and Key.

Search result identity and freshness​

Search Actions populate a result-path list. Typed result getters re-read the current document at that path. HTML5 additionally stores collected values/references. Replacing or deleting document members after a search can therefore yield stale paths, new native values, or older HTML5 collected values. A result count does not guarantee that every path still resolves.

Result-list index and array index are distinct. On native targets, Get Result Index tries to parse the last path token and otherwise returns the result slot; On HTML5, it returns the slot. On native targets, Get Result Key decodes the JSON Pointer token; on HTML5 it returns the final stored string token. Numeric getters also use different failure sentinels: zero on native targets versus minus one on HTML5.

Read results immediately after a successful search where possible, and check the relevant type/error conditions. A failed search may leave prior state depending on its failure point.

Trigger metadata and callback behavior​

Some are real event handlers; others are state-reading callbacks that always return the same value. A callback returning true is not a substitute for a call site that emits the event. State flags such as Read Only or Auto Save do not guarantee that the promised operation is enforced or scheduled.
