Search Results and Their Lifetime

Overview​

A search stores a result collection for later result getters. Each result slot is separate from an index in the searched array.

Why it matters​

Changing a document after searching can invalidate a stored path or make its value different from the match you originally found.

How it works​

Use Get number of Results to inspect the collection size. Get Result Path identifies a matched location. Native typed result getters read the document at stored paths, while HTML5 also maintains collected values/references. Get Result Index and Key have their own target-specific contracts.

Example​

Search /players for the key name in {"players":[{"name":"Alex"}]}. There is one result at /players/0/name. Result slot 0 refers to that match. It does not describe every item at array index 0.

Important considerations​

Read results from the outcome of the intended search and repeat it after mutations when freshness matters. A failure can retain prior results depending on its point of failure. A positive result count alone cannot prove that all stored paths still resolve after an edit. Getter failure sentinels vary, including zero versus minus one for numeric result getters.
