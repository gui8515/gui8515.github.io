C17 — Values is Numbers

Description​

Tests whether a JSON array contains only numbers. This is the Values is Numbers menu leaf under Is Array.

When to Use​

Use this as a collection-shape gate before processing items as numbers. Check that the collection is nonempty separately if at least one item is required.

Syntax​

JSON++ Object: Is <path> an array of numbers?

Anatomy​

This is a state evaluation, not a trigger. Each evaluation inspects the selected array; a true result can repeat while its state remains unchanged.

Parameters​

PositionNameDescriptor typeMeaning and constraints
1pathTextArray location as a JSON Pointer; example /items. No default is declared.

Behavior​

Native IsArrayOfNumbers reads without creating a missing node, requires an array, and checks each element for the required JSON type. It returns false on the first incompatible element. Empty native arrays return true because no element fails the test. HTML5 explicitly rejects an empty array before checking elements. The element check does not recursively enforce a schema inside nested containers.

Examples​

Basic inventory shape check. Initial JSON is {"items":[10,20]}.

* Start of Frame
    JSON++ Object : Load JSON from string "{""items"":[10,20]}"

* JSON++ Object: Is "/items" an array of numbers?
    String : Set alterable string to "Inventory values are numbers; processing can continue"

Expected Result​

The nonempty example passes the condition in the inspected implementations, so the inventory status is set. Adding one element of an incompatible JSON type makes the predicate false. The predicate does not change the document.

Errors & Edge Cases​

A missing path or non-array value returns false in the native implementation. An empty array returns true natively and false in HTML5. Valid missing reads do not create nodes; invalid path syntax can take a separate resolver error path.

Limitations​

This predicate is not a nonempty-array check. It does not verify required object keys, nested array dimensions, numeric ranges, or other element content beyond the numbers type. Empty-array behavior is not portable across the inspected runtimes.
