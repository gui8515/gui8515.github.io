Go Forward in History

Description​

Move forward among stored cursors. Official Event Editor caption: Go forward %0 step(s) in history.

When to Use​

Move forward among stored cursors. Check the limitations before using the same workflow across runtimes.

Syntax​

JSON++ Object : Go forward <steps> step(s) in history

Anatomy​

The object label selects the instance. %0, %1 and subsequent caption placeholders are zero-based substitutions, not literal input. Arguments follow the positional table, even when their visual order in the caption differs.

Parameters​

PositionNameTypeMeaning and constraints
1stepsIntegerPositive integer count; no default is declared. No default is declared.

Behavior​

Requires enabled, nonempty history and positive steps. It locates the first occurrence of the current cursor and moves only if all requested steps fit. Movement emits On Next History/On Current Path Set/Has Set Path. On HTML5, it uses the last occurrence and clamps to the boundary; nonpositive values become 1.

Examples​

Basic scenario, initial document:

{"a":{},"b":{},"c":{}}

Load this document with Load JSON from String first.

Expected Result​

Given history [/a,/b,/c] and cursor /b, selects /c. JSON is unchanged. The prerequisites are a stored history sequence, not merely an enabled setting.

Errors & Edge Cases​

Disabled/empty history or nonpositive steps reports an error. Missing current cursor or too many steps is a no-op. HTML5 empty history is a no-op.

Limitations​

This is navigation history, not JSON Undo/Redo. HTML5 forward movement may append the current cursor; backward movement from root can select the final history entry. Stored paths can become invalid after document mutations.
